# 発話の確定表示

録音中の発話は、確定前なら行全体を半透明、確定後なら通常の濃さで表示する。従来の4段階のランプは表示しない。

- 対象: アバター・話者名・時刻・本文をまとめて薄くする。
- 意味: 半透明は、文字や話者が後から変わる可能性を示す。
- 制約: 通常表示は認識が正しいことを保証しない。不明話者のまま固定される場合もある。

## 確定の条件

| 会議の状態 | 通常の濃さになる条件 |
|---|---|
| 話者判別ON | 行全体の文字が高精度側で確定し、話者も固定済み |
| 話者判別OFF | 行全体の文字が高精度側で確定済み |
| 停止処理中 | 録音中と同じ条件 |
| 停止処理完了後 | 最終結果へ切り替わった全ての発話 |

速報の文字に話者が付いていても、固定前なら半透明のままにする。暫定末尾も同じ未確定状態として表示する。

行内に確定済みと未確定が混在すれば、行全体を半透明にする。後続の未確定文字が同じ話者の行へつながると、通常表示から半透明へ戻る場合がある。

- 理由: 固定済みの文字や話者が後退したのではなく、行の範囲が広がったため。

後続の発言を待つ固定条件は変えない。最後の発言は無音で待っても半透明のままになる場合がある。

- 通常表示へ戻る時点: 後続発言で固定条件を満たした時、または停止後の最終結果へ切り替わった時。
- 一時停止: 話者判別ONでは音声入力による表示更新が止まる。OFFでは文字起こしの結果通知が届けば反映する。

## 他の表示・操作との関係

未確定による薄化は見た目だけに使い、コピー・AI送信の除外条件には使わない。コピー範囲と暫定末尾の扱いは従来どおり。保存内容と話者補正にも影響しない。

- 手入力・AIの返答: 発話の未確定による薄化の対象外。
- 小音量の除外: 従来の薄化と「小音量のため除外」の注記を保つ。未確定の薄化と掛け合わせない。
- 選択・操作: 文字選択・コピー・話者名変更・検索の操作を保つ。
- 読み上げ: 確定前後の状態をアクセシビリティの説明でも示す。

## 背景

旧表示は暫定・速報確定・高精度確定・話者固定の4段階だった。文字起こしと話者判別は並行して動くため、2段目でも話者が表示される。利用者が知りたい「まだ変わるか」を直接示すため、表示を2状態に整理した。

認識の流れは[文字起こしの速報表示](fast-transcription.md)、話者固定の条件は[話者の割当と固定](speaker-assignment.md)を参照。

## 実装と検証

`LiveTranscript.unconfirmedRows(accurateFinalCount:)` が、表示行と同じトークン範囲から未確定の行添字を求める。高精度側の確定数には、同じ合成スナップショットの値を必ず渡す。

- 話者判別ON: 高精度確定数と実際の凍結数の小さい方を、行の終端と比較する。
- 話者判別OFF: 高精度確定数だけを行の終端と比較する。
- 手入力との併合: `TranscriptEntries.merge` が未確定行の添字も変換する。
- 最終結果: `MeetingSession` が未確定行の集合を空にする。

表示は不透明度60%を使い、小音量による除外は既存の40%を優先する。文字色による追加の薄化は重ねない。

- 配置: ランプ専用の左余白4ptを除き、発話・手入力・AI行の原点を揃える。
- 読み上げ: 発話本文の `accessibilityHelp` に未確定・確定を示す。
- 診断: `KIKIGAKI_DEBUG_LIVE_TRACE` の表示状態は `utterance-confirmation` として出す。

実寸の撮影にはDEBUGビルドの `--utterance-confirmation <出力先>` を使う。既存のCoreから求めた確定状態を製品ウィンドウへ渡す。同じ内容の未確定・確定、話者判別OFF、手入力と小音量除外の混在を比較できる。

- 等倍画像: `-1x.png` は600×740px。
- 注意: 比較用の一様な確定状態を含む。実音声での認識精度を測るものではない。
