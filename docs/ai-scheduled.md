# AIへの定期自動送信

会議参加モードの既存契約は [ai-participant.md](ai-participant.md) を引き継ぐ。

## 確定した仕様

自動実行シートで宛先を切り替えると、初回はその `[[ai]]` の `autoPrompt` と `autoIntervalMinutes` を表示する。編集した文面・間隔・作業許可・停止時の最終送信は宛先ごとに保持し、切り替えて戻る場合や閉じて開き直す場合も復元する。空欄も下書きとして保持する。候補一覧だけの更新では編集内容を変えず、新しい会議では下書きをリセットする。設定ファイルへは書き戻さない。

手動の「手動実行…」と同じ `AIConversationController`、herdrセッション、世代、`AIStreamHistory` を使う。定期送信の専用streamや接続は作らない。利用者が明示的に開始し、既定間隔は3分、録音停止時の最後の1回は既定ON。自動を含む通常の返答に未読表示は出さず、未回答のneeds_inputだけを赤い要返答バッジで強調する。failedの警告は維持する。

設定・稼働状態は会議単位。新会議では設定の初期値へ戻し、稼働状態をアプリ再起動で復元しない。停止後の返送回収と保存は既存の仕組みで続き、片付いた時点でペインを閉じる。自動送信からウィンドウを前面に出さない。

## 操作と設定

ロボットとフッターの見た目・操作の正本はこの節とする。他の文書は要約と参照にとどめる。

ロボットの配色は自動OFFで既存の薄墨の輪郭、自動ONで朱の輪郭。実行中は手動・自動とも朱の塗りつぶしと白い目に反転する。状態文字は9pt mediumで、数字だけ等幅にする。

フッター左端のロボットへ自動・手動の操作を統合する。CLIへ渡す直前の `beginSending` までは朱の輪郭のまま目を1秒ごとに動かし「準備中」、実送信後の返事待ちは朱の反転と「実行中」。どちらかの枠が実送信済みなら実行中を優先する。手動送信の確定待ち・起動・接続待ちも準備中に含める。失敗・取消・自動停止では準備中を解く。

送信待ちがなく自動送信が稼働中なら、静止した朱の輪郭の下に残り時間を `2:30`・`0:45` の形式で表示する。変更なしなどのスキップ理由があっても次の期限があればカウントダウンし、理由はツールチップに残す。切断・最終回待機中は従来どおり「—」。自動OFFの待機は下ラベルを出さない。

クリックするとボタンの上にメニューを開く。自動送信が非稼働なら「自動実行…」「手動実行…」、稼働中なら「今すぐ送る」「自動実行解除」「手動実行…」。自動実行は自動実行シート、手動実行はAI依頼シートへ入る。「今すぐ送る」も開始操作と同じ本番判定を直後に1回行う。送信可能で差分があれば送信し、次の期限はCLIへ渡す時点から1間隔。変更なしなら送らず操作時点から1間隔待つ。送信不可の場合は既存期限を保つ。準備中・返事待ち・送信不可・最終回待機中は無効にし、変更なしだけなら再判定できる。ダブルクリック送信はない。

- 「AIセッションを作り直す」: このロボットのメニューの区切り線の下に、録音中に接続が切れた時だけ出す
- フッターの「…」: 自動送信の項目を置かない

録音を始める前の指定は[録音開始シート](start-sheet.md)が担う。宛先・間隔・プロンプト・作業許可・最後の1回を決め、開始と同時に `startAutomaticSchedule` へ渡す。**「送らない」を選んだ会議では、設定に `autoStart = true` があっても始めない。** 録音中に条件を変えたくなったら、従来どおりロボットの「自動実行解除」で止めてから「自動実行…」で入れ直す。

`board` を指定したプロファイルは自動送信で内蔵のボードプロンプトを使い、議事録パスか `boardLocation` があれば開始できる。パスが無い送信には書き先の作成・通知指示を付け、AIの `minutes` 通知後は同じファイルへ更新を続ける。`boardPrompt` による全文差し替えと手動の `autoPrompt` の扱いは [議論のボード](board.md) を参照。

ホバーには「次 0:45 · 議事録へ」「AI実行中・返事待ち」「差分なしでスキップ中」など、状態と自動宛先を示す。AI未設定ではロボットと隣の仕切りを隠し、録音停止後はメニュー内の自動開始を無効にする。表示中だけ1秒周期で更新し、非表示・最小化・非稼働ではタイマーを止める。視差効果を減らす設定では目を動かさず「実行中」を残す。カウントダウンは動きを減らす設定でも表示中は更新する。CALayerの連続アニメーションや繰り返しopacityを使わない。表示更新の差分判定は `.running` のときだけ全発話を文字列化し、非稼働時には自動送信用の全行を組まない。

シートは次の項目を持つ。

| 項目 | 契約 |
|---|---|
| プロンプト | 複数行、空白だけは不可。既存の問いと同じUTF-8 32 KiB上限とNUL拒否。毎回 `participant.question` に固定して送る |
| 間隔 | 1・2・3・5・10分のポップアップ、既定3分 |
| 作業を許可する | 既存と同じ意味。初期値は会議の現在の作業許可。開始時の値を自動送信用に固定する |
| 録音停止時に最後の1回を送る | 既定ON |
| 開始・閉じる | ⌘Enterで開始。IME確定中のEnterは開始に使わない。開始の二重操作を防ぐ。「閉じる」は稼働状態を変更しない |

シートの開始操作と `autoStart` の録音開始時は、直後に本番の送信判定を1回行う。変更があれば初回期限を待たず送信し、次の期限はCLIへ渡す時点から1間隔。空会話を含む変更なしなら送らず、開始時点から1間隔のカウントダウンへ進む。実行中に設定を変える場合は解除して開き直す。同じ会議内の再開には直前の入力を残し、手動の下書き・完了表示は上書きしない。

`AIConfig` と `ResolvedAIConfig` に `autoPrompt` と `autoIntervalMinutes` がある。省略時は空文字と3。`AIConfig.validate()` でプロンプトの型・上限・NULと、間隔の整数1〜60を検証する。空の設定値は許し、開始時に必須検証する。旧manifestの復号では欠損キーに同じ既定値を使う。既存の `prompt` は全送信に付く補助指示のままで、`autoPrompt` と混同しない。

設定で7分など標準候補以外を指定した場合は「7分」をポップアップへ追加して初期選択する。黙って3分へ丸めない。シート変更をTOMLへ書き戻さず、接続設定の等価性検証にも稼働中の編集値を混ぜない。

## 状態機械と時計

Coreの値型 `AIScheduleState` に設定、実行ID、次の期限、連続失敗数、判定済みrequest IDを持たせる。時計・ファイル保存・AppKit・herdr呼び出しは置かず、時刻と観測を入力して遷移と効果を返す。アプリ側の `MeetingSession` が会議のMainActor上でその効果を実行する。

| 状態 | 入力 | 次状態・効果 |
|---|---|---|
| 停止中 | 有効な開始 | 新しい実行IDを発行し失敗数0。直後に1回判定。変更なしなら開始+間隔、送信したらCLI入力試行+間隔 |
| 実行中 | 期限前 | 何もしない |
| 実行中 | tick | 下記判定を1回行い、送信またはスキップ。次期限へ進む |
| 実行中 | 自動送信の停止 | 停止中。最終送信は予約しない |
| 実行中 | 録音停止 | 通常の期限を破棄。最後の1回ONなら最終保存待ち、OFFなら停止中 |
| 最終保存待ち | 最終判定・保存成功 | 最終送信待ちへ。送信可能なら権利を消費して1回送る |
| 最終送信待ち | 返事待ち | 期限なしで会議単位に保留。answered・needs_input・failed到着後に再判定 |
| 最終送信待ち | 接続不可・変更なし | 権利を消費して停止中。接続不可なら理由を表示 |
| 最終保存待ち | 最終判定または保存失敗 | 停止中。送らず理由を表示 |
| 任意 | 自動の失敗が3回連続 | 停止中。警告を残す |
| 任意 | 新会議・アプリ終了 | timerと未実行の最終判定を破棄。旧会議の返送回収は独立して継続 |

期限は音声経過秒ではなく時計で進め、一時停止中も動かす。スリープ等で複数期限を過ぎても1回だけ判定し、次期限は元の周期で現在より後の最初の時刻にする。過去の回数分を連続送信しない。実行IDとmeeting IDをawait後に照合し、停止前・再開前・旧会議のcallbackを新しい実行へ適用しない。表示する次時刻は同じ期限から算出する。

## tickの純関数と差分

判定順序は `notDue` → `unavailable` → `noChange` → `send`。送信可否には会議状態、`aiTask` の有無、`controller.canSend`、未解決の確認質問、手動シートの使用中状態を渡す。

- 返事待ち・送信中・確定待ち中・接続不可はスキップする。初回の未接続は、既存の `canSend` が起動可能と認めるため送れる。切断後に自動で世代を作り直さない。
- `needs_input` が未解決なら自動では送らない。既存の `canSend` はこれを必ずしも禁止しないので追加判定する。手動による返答・別質問の既存操作は維持する。
- 差分がなければrequestもsnapshotも作らず、sequenceと受領基準を動かさない。スキップは失敗回数に含めない。

差分の入口は `AIStreamHistory` の受領済み本文と現在の確定本文を比較する副作用のないAPIとする。行は手入力統合後の `TranscriptRenderer.lines` を使い、受領済みなしなら現在の非空本文を変更ありと扱う。

**既存の `preview().readLineCount` を差分件数として流用しない。** `prepare` は同一本文なら受領済みsnapshotをそのまま返すので、変更がなくても過去のreadLineCountが正になる。また末尾の削除だけなら変更があっても読む行数は0になる。`hasChanges(lines:)` は追加・置換・削除のいずれもtrueとし、変更開始位置の算出は送信する場合の既存prepareへ任せる。「差分0」は本文の変更なしと解釈し、削除だけの訂正も送る。

tick時に差分を確認し、既存の3秒確定待ちを終えた `capture.lines` でもprepare前に再確認する。待ち中に差分が解消したらrequestを作らず終える。暫定末尾だけの変化は確定本文の差分に数えず、送れる回の付帯情報としてだけ扱う。

## 送信経路と手動の優先

`submitAI` の共通部分に任意の `trigger` と作業許可の固定値を渡せるようにする。手動の既存呼び出しは既定値で維持する。自動は `question: autoPrompt, full: false, parent: nil, trigger: scheduled`。capture・prepare・connect・send・失敗保存を分岐コピーしない。

`submitAI` は入口で `typedEntries` を固定し、`AICapture(..., typed:)` へ渡す。自動も同じ入口を使い、tick後の手入力をその回へ混ぜない。最終保存では `TranscriptEntries.merge` の音声と手入力を含む会議が正本となる。SessionSnapshotの手入力可否・文脈時刻計算を置き換えず、自動送信の表示用状態だけを追加する。

手動シートを開いている間は、そのシートが持つ宛先と同じ宛先の自動tickをスキップする。別の宛先の自動送信は止めない。手動が押された時点で自動の未送信準備だけが走っていた場合は、既存の取消経路で停止してから手動へ譲る。送信試行済みのrequestは取り消して再送せず、既存の返事待ちに従う。MainActor上で送信の所有者を確保し、非同期の確定待ち・接続待ちから戻ったときに実行IDと所有者を再確認する。

手動送信の後は同じ受領基準から次回の差分を判定する。手動シートの作業許可変更を、開始済みの自動設定へ黙って反映しない。自動の作業許可を変えるには停止して再開する。権限値は開始時に固定する。

## 録音停止時の最後の1回

録音停止を受けた時点で通常周期の判定を止める。最終待機の間は状態の再判定だけを続ける。現在の `stop()` は文字・話者の最終化失敗でも取得済みデータを保存するため、`snapshot.saved` だけを成功判定に使わず、最終判定が完遂したかも明示的に保持する。archive・Markdown・rawの既存保存結果が成功し、最終判定も成功した場合だけ最終送信を判定する。

最終送信も送信可否と差分を確認する。変更なしなら何も送らない。最終回だけは通常tickの例外として、返事待ちならanswered・needs_input・failedの到着後に1回送る。期限は置かず、会議単位に権利を1つだけ保持し、アプリ終了・新会議で破棄する。保留している間もロボットのメニューの「自動実行解除」で権利を破棄でき、最終送信を取りやめられる。返事が届いてもherdrがworkingの間は入力可能になるまで保留し、接続不可ならスキップして理由を表示する。needs_input到着を待っていた最終回はその確認によって締めを再び止めず、親参照を持たない最後のプロンプトを送る。通常tickの未解決確認スキップは維持する。

停止直前の確定待ちは既存どおり取り消す。prepare以降の送信は既存契約どおり続行し、その返事を待つ。最終送信のprepare直前に権利を消費し、再走査や保存再試行から再発火させない。新会議開始・終了から戻る非同期処理も古い会議へ追加送信しない。停止後の手動送信は受け付けないので、締めの差分に人の依頼が割り込むことはない。

最後の1回とその返事が済むと、[録音停止後の後片付け](ai-participant.md#録音停止後の後片付け)がherdrのペインを閉じる。後片付けは最終待機そのものも待つので、最後の1回が送られる前にペインを閉じることはない。

## 失敗を3回で止める

失敗数の対象は現在の自動実行が発行したrequestだけ。手動の成否は増減に使わない。自動answered・needs_inputで0へ戻し、failedまたは送達不明で1増やす。取消・スキップ・acceptだけでは増減しない。

`AIQuestion.beginSending` は送信試行の保存時に一時的にdeliveryUnknownへ入るので、その状態通知だけでは数えない。sendが失敗して送達不明が残ったときに1回数え、後着failedと二重計上しない。再走査でもrequest IDで重複計上を防ぐ。遅れてansweredが届けば当該の結果を成功へ訂正するが、停止済みのスケジュールは自動再開しない。

送達不明は既存の `isAwaitingResult` により次の送信を止める。3回に到達するための自動取消・自動再送・世代再作成はしない。prepare前の保存失敗などrequestがない障害は既存の警告で示し、failedの架空requestを作らない。

## Envelope・未読・保存

`AIParticipantContext` に `Trigger.scheduled` の任意キー `trigger` を追加する。手動はキーを省略、旧データの欠損は手動。値の型違いと未知の値は拒否する。トップレベルとparticipantのschema_versionは1を維持する。自動プロンプトは非空なので `question_source` はtyped。triggerは起動原因、question_sourceは問いの由来として分ける。

`AIRequest.trigger` は保存済みenvelopeから参照し、同じ値を別保存して不整合を作らない。確認への手動返答はtriggerを継承しない。送信印の表題を「#3 迅雷へ · 自動」、会議Markdownの送信時刻行・送信印へ「(自動)」を添える。詳細と原文の保存は維持する。

`AIQuestion` の既読情報は保存形式の互換性のため保持する。画面の表示・集計では参照せず、本文クリックでも書き換えない。needs_inputの要返答バッジは返答まで残す。通知音の対象は従来どおりで、自動answeredは鳴らさない。

## 配布用Skillとreplay

`skills/kikigaki/references/meeting.md` にtriggerの説明がある。scheduledなら指定差分の受領、プロンプトで依頼された作業、短いansweredの順に返す。確認質問は通常どおり可能。作業許可、範囲検証、返送CLI、重複防止の契約は変えない。

`KIKIGAKI_DEBUG_AI_AUTO="<間隔秒>:<プロンプト>"` は最初のコロンだけで分割し、以後のコロン・改行をプロンプトに残す。秒数は有限かつ正、プロンプトは本番の必須検証を使う。replay開始時に同じ自動送信入口へ渡し、直後に1回判定する。開始時に会話が空なら変更なしでスキップし、次の期限までカウントダウンする。間隔だけ秒単位で注入し、通常起動では解釈しない。`--smoke --replay` は形式検証だけで送信しない。

`KIKIGAKI_DEBUG_AI_ASK` との併用で手動優先を検証する。自動側はASKの次問向け自動世代復旧を流用しない。HOLDで停止後の最終返送を回収する。
