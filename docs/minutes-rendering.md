# 議事録の描画と検索

[議論のボード](board.md)を使う会議は「議事録」「ボード」の別タブになる。それぞれの目次・検索・折りたたみ・更新強調は同じ描画器で独立して保持し、変更のないタブは再描画しない。ボードのMermaidにある内部見出しへのclick指定だけをアプリの移動操作へ結び、Mermaidのstrict・CSP・SVGのリンク禁止は維持する。

右ペインの本文は専用のWKWebViewで描画する。幅は左右24ptの余白を除いてペイン全体へ追従し、720ptの上限を設けない。表の列は内容幅を上限とし、短い表は左寄せでペイン幅より狭く置く。合計がペイン幅を超える表だけ、広い列から等しく詰める配分を描画後に置く。狭い列は内容幅のまま残るため、「担当」のような短い日本語の列が1文字ずつ折り返すことはない。表の文字は本文より1段小さい14pxで、列の下限は枡の外形64pt(3文字ぶん)。下限でも収まらない表とコード・図は本文全体を押し広げずに横スクロールする。配分はペイン幅が変わるたびに測り直す。

通常本文は会話と同じ15pt。タスクは18ptの円形チェックで未完了を輪郭、完了を紫の塗りと白いチェックで表す。読み取り専用で、ファイルは書き換えない。

プレビュー下端に最終更新時刻と相対時間を常設する。時刻は本文と同じファイル読み取りで検証したmtimeで、描画成功後に反映する。相対時間は10秒周期で、10秒未満は「たった今」、1分未満は10秒単位、その後は分・時間・日で表示する。日付が異なる場合は年月日も示す。読込失敗・取消・対象解除では「最終更新 —」へ戻す。

更新時は、追加・書き換えされた表示本文を淡い紫で4秒強調する。比較単位は段落・見出し・リスト項目・表のセルなどで、長い段落は段落内の文字全体を強調する。初回表示・同一本文の再読込・並べ替え・削除だけでは光らせない。削除後の行は画面に存在しないため、更新時刻で変更を示す。折りたたみとスクロール位置は維持する。検索の強調を優先し、一度に強調するのは先頭1000箇所まで。

強調した箇所を含む見出しは、目次の項目にも紫の丸を付ける。直接その見出しの中身が変わったものは塗り、配下の見出しだけが変わった上位は輪郭で示す。印の寿命は本文の強調と同じで、4秒または基準を置き直すまで残る。目次に載らない301件目以降の見出しには付かない。

AIへ依頼を送った時点と、その依頼の `progress --editing` を観測した時点で、強調の基準をそのときの表示本文へ置き直し、それまでの強調を消す。以後は直前の描画ではなく基準との差分を強調するため、1つの依頼の中で何度編集しても全箇所が残る。返事が届いても消えず、次の依頼の送信か編集の開始で消える。AIの依頼がない間は基準を持たず、従来どおり直前の描画との差分を4秒で消す。会議の切替と表示対象の切替では基準を捨てる。基準を置いた時点でまだ本文を描いていなければ、最初の描画を基準にして初回表示を光らせない。文字を持たない画像は、累積の間だけ淡い紫の枠で示す。

基準を置き直す入口は `window.minutes.markBaseline()` の1つで、送信と編集の観測がそこへ集まる。編集の観測は自分が送った依頼の1回目だけで、進捗率や編集の成否は表さない。

まだ本文を描いていない間に届いた置き直しは、次に描き終えた本文へ1回だけ置く。AIが依頼の中で議事録を作り、その通知で表示対象が切り替わる場合も、切替後の本文を基準にして以後の編集を累積できる。描画が途中で中断されたら消費せず、次に描き終えた本文で置く。既に置いてある基準を表示対象の切替で捨てる規則は変えない。

右上の「目次」を押すとフローティング一覧を展開する。全階層の見出しを字下げして表示し、現在位置を強調する。開閉は目次ボタンだけで行い、本文クリック・見出し移動・Escapeでは閉じない。幅は最長項目に合わせ、画面幅を上限として開閉で維持する。見出しがない文書では表示しない。目次自体は本文検索の対象に含めない。本文の操作を重くしないよう目次は先頭300見出しまでとし、超えた場合は一覧内に案内する。

目次のクリックは約0.25秒のease-outでスクロールし、着地した見出しを淡い紫で約1秒強調する。連打では直前の移動を打ち切り、OSの視差効果を減らす設定ではスクロールだけを即時移動にする。

ホイール・キー・タッチ操作や検索、文書更新が入ると移動を打ち切り、中断した見出しの着地強調は出さない。

見出し左の三角ボタンで配下を折りたたむ。初期状態は展開し、同じファイルの更新では状態を維持する。検索・目次・脚注の移動先が隠れていれば、必要な親を展開する。脚注への移動と本文への復帰は、着地点を淡い紫で強調し約2秒で薄くする。視差効果を減らす設定でも、移動先が分かるよう目次・脚注の着地強調は残す。

画像はクリックで拡大モーダルを開く。閉じるボタン・背景クリック・Escapeで閉じる。OSの視差効果を減らす設定では開くアニメーションを省く。

⌘Fは焦点のあるペインを検索する。右ペインでは検索欄、一致の強調、現在位置と件数を表示する。⌘G・⌘⇧G、Enter・Shift+Enter、矢印ボタンで次・前へ移動し、Escapeで閉じる。大文字小文字を区別せず、太字などの装飾をまたぐ語も検索できる。強調する一致は先頭10,000件まで。

ボードタブの検索はキャンバスのノード文字を対象とする。

- 対象: T番号付きノードのラベル。改行や装飾をまたぐ語も含む。
    - 対象外: 辺のラベル、図のタイトル、ミニマップ、操作列、「以前の本文」。図のない旧ボードは従来の本文検索。
- 件数: ノード数ではなく文字列の一致数。「現在番号 / 件数」は議事録と同じ。
- 移動: 入力時の最初の一致と、次・前の一致を中央へ寄せ、クリックと同じフォーカスを付ける。
    - 倍率: 図100%以上は保つ。100%未満は100%へ上げる。文字の倍率は変えない。
    - 同じノードの次の一致: 再度フォーカスする。2回目のクリックによる見出し移動は起こさない。
- 強調: SVGの文字の背景に依存せず、一致したノードに橙の内枠を付け、現在の一致は濃くする。フォーカスは墨の四隅ブラケット。
- タブ切替: 検索語を引き継いで対象・件数を切り替える。現在番号は各タブで保持する。
    - 位置: タブ切替と文書更新による検索の再計算では、中央寄せを繰り返さない。
- 閉じる: 両タブの一致強調と検索語を消す。ノードのフォーカスと位置・倍率は残す。

パス欄の右のアイコンボタンで対象ファイルをNeovim・Obsidianに開ける。ペインの構成は [議事録ペイン](minutes-pane.md) を参照する。未作成ファイルは案内を表示する。

- Neovimは操作時に選択中のherdrワークスペースへ新しいタブを作る。作業ディレクトリは議事録の親。設定の `herdrCommand` があれば利用する。引数のパスはシェル引用し、既存ペインへコマンドを送らない。Ghosttyが起動中なら前面化する。
- Obsidianには絶対パスを `obsidian://open?path=...` で渡す。対象ファイルがObsidianのVault内にあることが必要。

## 対応記法

| 記法 | 表示 |
| --- | --- |
| 見出し・段落・引用・入れ子リスト・表・通常リンク・強調・打消し | Markdownとして描画する。 |
| タスク `[x]` と `[ ]` | 読み取り専用のチェックボックス。 |
| 脚注 `[^id]` | 本文から文末の脚注へ移動でき、戻るリンクも表示する。 |
| `> [!NOTE] 題` などのcallout | 題と本文の枠。折り畳み指定でも内容を展開して表示する。 |
| `:::{note}`、`:::note`、コードフェンスの `{warning}` など | MyST callout。種別アイコンとタイトル帯で表示。`admonition` の題、先頭の `:class:` と `:name:` に対応する。 |
| `!!! info "題"` と続く4空白字下げの本文 | Python-Markdown・MkDocsのadmonition。calloutと同じ枠で描く。題を省くと種別名、`""` は題の帯を出さない。本文は字下げを外してMarkdownとして描き、間の空行を許して字下げの無い非空行で終わる。`!!!` の直後でない字下げは従来どおりコード。種別語は制限せず、`kinds` 外(abstract・question・exampleなど)はnoteの顔へ寄せる。 |
| 見出し `{#id}` と `(#id)` | 本文内の見出しへ移動する。通常の見出し名でも移動できる。 |
| `[[ノート\|別名]]` | 議事録がVault内にあるときはリンクにし、クリックでObsidianの同名ノートを開く。`[[ノート#見出し]]` と `[[ノート#^ブロック]]` は宛先をそのままObsidianへ渡す。Vault外では文字として表示し、別名も再解釈しない。 |
| `[[#見出し]]` | Vault内外とも本文内の見出しへ移動する。旧ボード内の見出しは「以前の本文」を開いて移動する。`[[#見出し\|別名]]` にも対応する。 |
| `![説明](画像)`、`![[画像.png\|幅]]` | ローカル画像とHTTP・HTTPS画像。ローカル相対パスは議事録の親を基準とする。 |
| Mermaidコードブロック | 図として描画する。失敗時は記法を残す。timelineの期間と出来事は、描画前に実フォントで幅を測り150pxの枠に収まる位置へ `<br>` を差し込む。書かれた `<br>` は残し、`<br/>` も改行として扱う。title・section・コメント行は変えない。Mermaidは期間に `:` を含む `21:39 : 出来事` を受け付けないため、期間の `:` だけMermaid共通のエンティティ記法 `#colon;` へ置き換えて本物のコロンで描く。手書きの `#colon;` や `#58;` もそのまま通る。mindmapのノード幅上限は320px。 |
| `$...$`、`$$...$$`、`\(...\)`、`\[...\]` | KaTeXで数式を描画する。math・latexコードブロックにも対応する。 |
| SVGコードブロック、閉じたSVGブロック | sanitize後、画像として描画する。 |
| 先頭の閉じたfrontmatter | 非表示。BOM・CRLFを扱い、閉じない場合は本文を残す。 |
| 本文のHTML | 文書要素と許可したインライン装飾を安全処理して描画する。 |
| ノートの埋め込み、未対応構文 | 文字として残す。 |

コードブロックと行内コードの記法は変換しない。表のwikilinkのパイプはObsidianと同じくエスケープする。表示例は [minutes-preview-example.md](minutes-preview-example.md)。

## コードブロックのコピー

- 議事録・ボードの普通のコードブロックは、右上にコピーアイコンを重ねる
    - 対象: 言語名付き・言語名なしのコードフェンスと字下げのコードブロック
    - 対象外: Mermaid・SVG・math・latexとして描くブロックと行内コード
- アイコンは普段は薄く、コードブロックへのマウスの重なりやキーボードの焦点で濃くなる
    - 表示: 本文の倍率に従い、操作後は1.5秒だけチェックへ変わる
    - 余白: 右端に専用の領域を取り、横スクロールでも本文がアイコンの下へ潜らない
    - ツールチップ・読み上げ: 「コピー」
- コピーする文字列は、Markdown描画器が保持した元のコード本文
    - 処理: 末尾の改行1つだけを落とす。空白・空行・記号を保持する
    - 書き込み: 世代番号付きの `copyCode` メッセージをSwiftへ渡し、`NSPasteboard` へ文字列だけを書く
- アイコンは文字を持たないSVGで描く
    - 目的: `root.innerText` の本文・検索・更新強調・選択位置へ混ざらないようにする

## 実装と配布

`MinutesFileMonitor`が検証したUTF-8本文を、`MinutesWebView`から引数付きJavaScript呼び出しで渡す。本文をスクリプトへ文字列連結しない。旧TextKit用のブロック解析はプレビューの読込経路では行わない。

拡大中のMermaidは不可視の計測領域で`pageZoom`を打ち消して描く。SVG文字の`em`・`ex`による位置指定は、等倍の計測領域で数値へ変換する。

- 目的: WebKitの拡大で行間や基準位置が縮むのを防ぎ、描画後の倍率変更でも位置を保つ。

議事録のMermaid図はペイン幅や要素数によらず、自然寸法で表示する。

- 幅: 等倍で計測したSVGの自然幅へ固定し、ペインへ収めるために縮めない。小さい図も引き伸ばさない。
- 倍率変更: `pageZoom`で自然寸法へそのまま倍率を掛ける。図は描き直さない。
- 配置: 収まる図は中央寄せ。はみ出す図は左端から表示し、その図の枠で横スクロールする。
- 余白: SVGの描画範囲を上下左右へ8pxずつ広げる。
    - 目的: 等倍でも端のノードの太い枠線を欠けさせない。文字倍率はこの余白にも掛かる。
- SVGブロックから画像化した図と通常の画像は、従来の幅制約を使う。
- 続きの表示: 枠の外へ続く辺だけ、内側を背景色へ薄くぼかし、辺の中央に小さな矢印を出す。
    - 時点: 選択前から表示し、横スクロール・ズーム・ドラッグ・枠の寸法変更・再描画で更新する。
    - 操作: 装飾はクリック・ドラッグ・スクロールを透過する。図を自動で縮めない。

### Mermaid図の選択と拡大縮小

議事録タブと旧ボードの「以前の本文」では、図をクリックすると選択する。

- 表示: 紫の枠と手のひらカーソル。ドラッグ中は握った手。
- ピンチ: カーソル位置を中心に25%〜400%で拡大縮小する。
- ドラッグ・2本指スクロール: 選んだ図の窓の中を移動する。
- 右上の「− 倍率 + 全体 戻す」: 「−」「+」は窓の中央を中心に拡大縮小する。
    - 配置: 通常は図の右上。目次と重なる間は、その左へ寄せる。
    - 幅不足: 左へ収まらない場合は目次の下へ置く。目次と操作列の間は6px空ける。
    - 短い図: 操作列が枠外へ出ても切らずに浮かせて表示する。図と枠の寸法は変えない。
    - 追従: スクロール、ペイン幅、文字倍率、再描画、目次の開閉で配置を測り直す。
- 「全体」: SVGの外接矩形が窓に収まる倍率へ変え、中央に置く。
    - 下限: 25%でも収まらない場合は、25%で中央に置く。
- 「戻す」: 図を100%・初期位置へ戻す。
- Esc・図の外のクリック: 選択を解除する。
    - 動き: 以後のスクロールはペインへ渡す。図の倍率と位置は保つ。
    - 表示: 選択枠と図内のフォーカス表示を消す。Tabで図へ入り直したときのフォーカス表示は残す。
- 選択前の図: 従来の自然寸法・横スクロールで表示する。
    - 操作: 図のズームと移動は行わない。
- 窓: 描画した図の自然寸法へ高さを合わせる。
    - 寸法: スクロールバーを含む既存領域の高さをCSS pxで保つ。枠はoutlineで描き、配置を変えない。
    - 選択: 選んだ瞬間の高さと図の表示位置を保つ。
    - 更新: 選択の有無によらず、新しい図の自然寸法から高さを測り直す。
    - ズーム・ドラッグ: 窓内の見え方だけを変える。窓の高さは変えない。
    - 文字倍率: 窓にも同じ倍率を掛ける。
- AIの再描画: 選択、倍率、移動量を保つ。
    - 対応付け: 見出しIDと、その節内の図の順番を使う。同じ位置の図へ状態を引き継ぐ。
    - 制約: 同じ節で図を挿入・並べ替えた場合、表示状態は図の内容ではなく順番に追従する。見出しIDが変わった図は初期に戻る。
- 別の議事録への切替: 選択、倍率、位置を初期に戻す。
- 文字の倍率: ⌘+・⌘-・⌘0は従来の`pageZoom`を変える。
    - 関係: 図の倍率と掛け合わせる。文字200%・図50%なら図の見かけは等倍になる。
- ボードのカード: 最初のクリックで図を選択する。選択後のクリック・Enter・Spaceで見出しへ移動する。
- SVGブロックから作った画像: 対象外。

### ボードのキャンバス

ボードの節の最初のMermaid図を、タブの下に残るペイン全体へ表示する。

- 操作: 選択なしでピンチ・ドラッグ・2本指スクロールを受ける。「− 倍率 + 全体 戻す」は常時表示する。
    - 配置: 目次との重なりを避ける規則は議事録の操作列と同じ。
- 初期表示・「全体」: SVGの外接矩形を中央へ収める。
    - 倍率: 最小25%・最大200%。25%で収まらない図も中央へ置く。
- 「戻す」: 100%・左上の初期位置へ戻す。
- ノード: 1回クリックでフォーカスの枠だけを付ける。位置・倍率は動かさない。フォーカス中のノードの再クリックで見出しへ移動する。
    - フォーカスの形: 外接矩形から外へ6図単位の位置に、四隅のL字を1本のpathで描く。
    - 腕: `max(14, 10 / 図の倍率)` 図単位。ズームの描画時に更新する。
    - 線: 墨 `#2b2420`、3px、`stroke-linecap:square`、`vector-effect:non-scaling-stroke`。塗りと操作は持たず、ノードの状態色とnow・hotの枠を変えない。
    - 解除: Escまたは余白のクリック。図の操作はその後も有効。
    - キーボード: Enter・Spaceもクリックと同じ2段階。
- 更新: 最初の表示または「全体」のままなら、新しい図全体へ収め直す。
    - フォーカス中: MermaidのT番号を突き合わせ、倍率とノードの画面内位置を保つ。
    - 手動操作後: フォーカスがなければ、キャンバス中央に最も近いノードを同じ位置へ置き直す。
    - 対応するノードがない場合: 倍率と移動量の数値を保つ。
- ミニマップ: 図が枠に収まらない間だけ右下へ出す。端のぼかしは出さない。
    - 寸法: 図の縦横比を保ち、最大180×120 CSS px。キャンバスの幅と高さの各25%も上限にする。外側に3pxの余白と1pxの枠を付ける。
    - 中身: ノードの外接矩形の箱と辺の線だけの粗い絵。図の更新時に1回作り、文字・マーク・状態色は複製しない。現在の表示範囲の枠を重ねる。
    - 操作中の更新: 表示範囲の枠と表示・非表示を100ms間隔に間引く。最後の操作後も100ms以内に追いつく。表示倍率と図全体のボタンは即時に反映する。
    - 操作: クリック・ドラッグした場所をキャンバス中央へ寄せる。倍率は保つ。
- 旧ボード: 最初の図以外は左下の「以前の本文」を開いて読む。
    - 表示: ペイン高さの45%を上限にしたスクロール領域。複数図・立場・直近の動きを保存したまま読む。
    - 図がない場合: 従来の文書表示。

キャンバスのスクロール・ドラッグ・ピンチは、状態への入力を全て受け、transformの反映をrequestAnimationFrameごとに1回へまとめる。

- 座標: 枠とSVGの自然寸法は初回・リサイズ時に測り、操作中は移動量と倍率から求める。
- 操作列: 倍率表示が変わるときだけ内容と位置を更新する。
- 更新直前: まだフレーム待ちの移動も反映してから、フォーカス中のノードの画面位置を記憶する。

WKWebViewは`allowsMagnification = false`を維持する[^diagram-gesture]。

- 経路: `gesturestart`・`gesturechange`・`gestureend`と、`ctrlKey`付き`wheel`を受ける。
- 抑止: 選択中だけ既定動作を止める。gesture中のctrl-wheelは二重適用しない。
- 倍率: ピンチのscaleは開始時からの累積倍率として扱う。
- 配送: WebKitの`magnifyWithEvent`は、ページ拡大を無効にしていてもDOMへgestureを送る。

[^diagram-gesture]: [Apple: allowsMagnification](https://developer.apple.com/documentation/webkit/wkwebview/allowsmagnification)、[WebKit: WebViewImpl::magnifyWithEvent](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/mac/WebViewImpl.mm)。実際のトラックパッド操作は実機確認が必要。

ファイル切替・取消の世代をSwiftとJavaScriptの両側で確認する。同じファイルの更新は先頭可視ブロックとその位置、選択の文字位置を保存して復元する。短縮時は有効範囲へ収める。別ファイルは先頭へ戻す。

Vaultの判定はSwift側で行い、議事録の切替ごとにやり直す。議事録の親から上へ `.obsidian` ディレクトリを探し、最も近いものがあるディレクトリをVaultルート、そのbasenameをVault名とする。探索はファイルシステムのルートまでで、シンボリックリンクは追わず、`.obsidian` 自身がリンクやファイルのものは採らない。Vault名は本文とは別の引数でJavaScriptへ渡し、Vault外ではnullにして他ノートへのwikilinkを描かない[^vault]。クリックしたwikilinkは宛先だけをSwiftへ返し、`obsidian://open?vault=…&file=…` を組んで開く。末尾の `.md` は落とし、`/` や空白や `#` を含む予約文字はすべてパーセント符号化する。

[^vault]: Obsidianが実際に開いているVaultの一覧はアプリ外から確実には読めない。開き先を決められない場所でリンクの顔をさせないため、誤検出より取りこぼしを選んでいる。

描画ライブラリは `Sources/Kikigaki/MinutesAssets` に同梱する。SwiftPMの資産bundleを.appにもコピーするため、実行時のCDN接続やNodeは不要。外部画像だけはURLへ通信する。

更新時は `web/minutes` で以下を順に実行する。

```sh
npm ci --ignore-scripts
npm test
npm run build
```

生成済み資産とlockfileもコミットする。同梱ライセンスは `THIRD-PARTY-NOTICES.txt` と `preview.js.LEGAL.txt`。

## 実行境界

非永続のWebKitデータストアを使う。本文由来のHTMLに専用DOMPurifyを適用し、描画全体のDOMPurifyとCSPも重ねる。段落・見出し・表・リンク・画像・details/summaryなどの文書要素を許可する。文字色・背景色・文字サイズ・余白・枠線などのインラインCSSは許可リストで選別する。

script・イベント属性・iframe・form・外部CSS・固定配置・CSSのURLや変数を除去する。生HTMLのclassは除去し、idと同じHTML内のアンカーには `html-` を付け、アプリの目次や操作要素と衝突させない。HTML画像もMarkdownと同じ専用画像ローダーへ渡す。本文のSVGは画像化し、Mermaidはstrict、KaTeXはtrust無効。図の原文はコマンド実行の口へ渡さない。

`minutes-app` schemeは同梱資産、`minutes-image` schemeは現在の議事録から参照する画像だけに使う。ローカル画像は通常ファイル・1枚24MiB以下を確認し、FIFOを待たない。読込は直列化し、1回の描画で合計96MiBまでに制限する。描画ごとに画像のhostを変え、取消時には待っている要求も終了する。本文に任意のファイル読取APIを公開しない。WebKitの生成は最初の本文描画まで遅延する。

### AppKitの入力配送を通したキャンバス計測

`swift build` 後、`KIKIGAKI_BOARD_APPKIT_PERF=/tmp/kikigaki-board-appkit .build/debug/Kikigaki` でDEBUG専用の比較計測を実行する。

- 構成: 本物の `TranscriptWindowController` と議事録ペインのボードタブ。1500×900pt、文字100%、図100%、非永続WKWebView。画面のRetina倍率と最大更新頻度も結果へ保存する。
- 入力: 独立タイマーから120HzでAppKitへ配送する。ページ内の合成イベントやOSへの `CGEventPost` は使わない。
    - スクロール: ピクセル単位のCGEventを `NSEvent(cgEvent:)` に変換し、窓内座標で `NSWindow.sendEvent` へ渡す。
    - ドラッグ: CGEventをNSEventへ変換した後、公開のマウスイベントfactoryで窓番号を付け直し、`NSApp.sendEvent` へ渡す。
    - 検証: ページ側の `isTrusted`、入力の時刻との対応、transform更新、現在のキャンバス、キーウィンドウを確認する。成立しない場合は途中結果を保存して失敗する。
- 比較: 30・60ノード、会話の静止・更新、粗いミニマップ・詳細なミニマップ・非表示、`will-change: transform` の有無、スクロール・ドラッグの48条件を3回ずつ。
    - 会話: 初期300行。更新条件は8回/秒の速報文字更新と2行/秒の追加を本番の `apply` へ渡す。音声認識・話者判別・AIは動かさない。
    - ミニマップ: 詳細条件だけを元のSVGへの `use` に差し替える。非表示条件はCSSで隠す。100msの枠更新と本体の入力処理は全条件で同じ。
    - 合成レイヤー: 計測するstageだけに `will-change` を設定する。描画資産や利用者の設定は変更しない。
- 記録: 実rAFの間隔、25ms超のフレーム数、入力配送時間、入力からtransform更新までの時間、5ms周期のメインキュー配送の遅れ、`sendEvent` と会話更新の処理時間。平均・p50・p95・最大をJSONへ残す。
    - 入力配送時間: DOMイベントの時刻をネイティブ入力と対応付け、`sendEvent` 直前からページのlistenerまでを測る。WebKitが統合した入力は残ったイベントの時刻へ対応付ける。
    - 精度: ページの時刻は1ms単位。切捨てで負になる端数だけ0へ丸める。生の時刻も保存する。1ms未満の差を性能差として扱わない。
    - メインキューの遅れ: バックグラウンドからmainへ渡した処理が開始するまでの時間。メインスレッド停止の代理指標で、CPUのスタック計測ではない。
    - 限界: WindowServerからAppKitへの実トラックパッド入力、慣性・gestureのphase、音声処理の負荷、GPUの描画・合成・実画素の提示時刻は測らない。rAFとtransformの時刻だけでGPUの遅れを否定しない。
- 保存: 指定した `/tmp` 配下の `results.json` と使い捨てMarkdownだけ。専用UserDefaultsは終了時に削除する。通常の起動・テストでは実行しない。`.build/KIKIGAKI.app` は更新しない。
- 調整:
    - `KIKIGAKI_BOARD_PERF_SECONDS`: 各条件の入力秒数。既定3、1〜30。
    - `KIKIGAKI_BOARD_PERF_REPEATS`: 反復数。既定3、1〜10。
    - `KIKIGAKI_BOARD_PERF_QUICK=1`: 30ノード・粗いミニマップだけの配送確認。
    - `KIKIGAKI_BOARD_PERF_MAP`: `coarse`・`detailed`・`none` の1条件だけを選ぶ。未指定なら3条件すべて。
- 60Hz制限の診断: `KIKIGAKI_BOARD_PERF_HIGH_FPS=1` を添えると、DEBUG計測器だけがWebKitのprivate feature `PreferPageRenderingUpdatesNear60FPSEnabled` を無効にして比較する[^board-perf-feature]。
    - 用途: 画面の最大更新頻度とrAFの差が、WebKitの設定によるものかを切り分ける。
    - 境界: private APIは製品の手当てには使わない。値は計測プロセス内だけに適用し、通常のWebViewやSafariの設定へ保存しない。

[^board-perf-feature]: WebKit公式ヘッダーの [WKPreferencesPrivate.h](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKPreferencesPrivate.h) と [_WKFeature.h](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/_WKFeature.h)。
