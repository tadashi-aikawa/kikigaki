# 議事録の描画と検索

右ペインの本文は専用のWKWebViewで描画する。幅は左右24ptの余白を除いてペイン全体へ追従し、720ptの上限を設けない。表はセル内で折り返し、狭すぎる表とコード・図は本文全体を押し広げずに横スクロールする。

通常本文は会話と同じ15pt。タスクは18ptの円形チェックで未完了を輪郭、完了を紫の塗りと白いチェックで表す。読み取り専用で、ファイルは書き換えない。

プレビュー下端に最終更新時刻と相対時間を常設する。時刻は本文と同じファイル読み取りで検証したmtimeで、描画成功後に反映する。相対時間は10秒周期で、10秒未満は「たった今」、1分未満は10秒単位、その後は分・時間・日で表示する。日付が異なる場合は年月日も示す。読込失敗・取消・対象解除では「最終更新 —」へ戻す。

更新時は、追加・書き換えされた表示本文を淡い紫で4秒強調する。比較単位は段落・見出し・リスト項目・表のセルなどで、長い段落は段落内の文字全体を強調する。初回表示・同一本文の再読込・並べ替え・削除だけでは光らせない。削除後の行は画面に存在しないため、更新時刻で変更を示す。折りたたみとスクロール位置は維持する。検索の強調を優先し、一度に強調するのは先頭1000箇所まで。

強調した箇所を含む見出しは、目次の項目にも紫の丸を付ける。直接その見出しの中身が変わったものは塗り、配下の見出しだけが変わった上位は輪郭で示す。印の寿命は本文の強調と同じで、4秒または基準を置き直すまで残る。目次に載らない301件目以降の見出しには付かない。

AIへ依頼を送った時点と、その依頼の `progress --editing` を観測した時点で、強調の基準をそのときの表示本文へ置き直し、それまでの強調を消す。以後は直前の描画ではなく基準との差分を強調するため、1つの依頼の中で何度編集しても全箇所が残る。返事が届いても消えず、次の依頼の送信か編集の開始で消える。AIの依頼がない間は基準を持たず、従来どおり直前の描画との差分を4秒で消す。会議の切替と表示対象の切替では基準を捨てる。基準を置いた時点でまだ本文を描いていなければ、最初の描画を基準にして初回表示を光らせない。文字を持たない画像は、累積の間だけ淡い紫の枠で示す。

基準を置き直す入口は `window.minutes.markBaseline()` の1つで、送信と編集の観測がそこへ集まる。編集の観測は自分が送った依頼の1回目だけで、進捗率や編集の成否は表さない。

まだ本文を描いていない間に届いた置き直しは、次に描き終えた本文へ1回だけ置く。AIが依頼の中で議事録を作り、その通知で表示対象が切り替わる場合も、切替後の本文を基準にして以後の編集を累積できる。描画が途中で中断されたら消費せず、次に描き終えた本文で置く。既に置いてある基準を表示対象の切替で捨てる規則は変えない。

右上の「目次」を押すとフローティング一覧を展開する。全階層の見出しを字下げして表示し、現在位置を強調する。開閉は目次ボタンだけで行い、本文クリック・見出し移動・Escapeでは閉じない。幅は最長項目に合わせ、画面幅を上限として開閉で維持する。見出しがない文書では表示しない。目次自体は本文検索の対象に含めない。本文の操作を重くしないよう目次は先頭300見出しまでとし、超えた場合は一覧内に案内する。

目次のクリックは約0.25秒のease-outでスクロールし、着地した見出しを淡い紫で約1秒強調する。連打では直前の移動を打ち切り、OSの視差効果を減らす設定ではスクロールだけを即時移動にする。

ホイール・キー・タッチ操作や検索、文書更新が入ると移動を打ち切り、中断した見出しの着地強調は出さない。

見出し左の三角ボタンで配下を折りたたむ。初期状態は展開し、同じファイルの更新では状態を維持する。検索・目次・脚注の移動先が隠れていれば、必要な親を展開する。脚注への移動と本文への復帰は、着地点を淡い紫で強調し約2秒で薄くする。視差効果を減らす設定でも、移動先が分かるよう目次・脚注の着地強調は残す。

画像はクリックで拡大モーダルを開く。閉じるボタン・背景クリック・Escapeで閉じる。OSの視差効果を減らす設定では開くアニメーションを省く。

⌘Fは焦点のあるペインを検索する。右ペインでは検索欄、一致の強調、現在位置と件数を表示する。⌘G・⌘⇧G、Enter・Shift+Enter、矢印ボタンで次・前へ移動し、Escapeで閉じる。大文字小文字を区別せず、太字などの装飾をまたぐ語も検索できる。強調する一致は先頭10,000件まで。

パス欄の右のアイコンボタンで対象ファイルをNeovim・Obsidianに開ける。未作成ファイルは案内を表示する。

- Neovimは操作時に選択中のherdrワークスペースへ新しいタブを作る。作業ディレクトリは議事録の親。設定の `herdrCommand` があれば利用する。引数のパスはシェル引用し、既存ペインへコマンドを送らない。Ghosttyが起動中なら前面化する。
- Obsidianには絶対パスを `obsidian://open?path=...` で渡す。対象ファイルがObsidianのVault内にあることが必要。

## 対応記法

| 記法 | 表示 |
| --- | --- |
| 見出し・段落・引用・入れ子リスト・表・通常リンク・強調・打消し | Markdownとして描画する。 |
| タスク `[x]` と `[ ]` | 読み取り専用のチェックボックス。 |
| 脚注 `[^id]` | 本文から文末の脚注へ移動でき、戻るリンクも表示する。 |
| `> [!NOTE] 題` などのcallout | 題と本文の枠。折り畳み指定でも内容を展開して表示する。 |
| `:::{note}`、`:::note`、コードフェンスの `{warning}` など | MyST callout。種別アイコンとタイトル帯で表示。`admonition` の題、先頭の `:class:` と `:name:` に対応する。 |
| 見出し `{#id}` と `(#id)` | 本文内の見出しへ移動する。通常の見出し名でも移動できる。 |
| `[[ノート\|別名]]` | 議事録がVault内にあるときはリンクにし、クリックでObsidianの同名ノートを開く。`[[ノート#見出し]]` と `[[ノート#^ブロック]]` は宛先をそのままObsidianへ渡す。`[[#見出し]]` は本文内を移動する。Vault外では従来どおり文字として表示し、別名も再解釈しない。 |
| `![説明](画像)`、`![[画像.png\|幅]]` | ローカル画像とHTTP・HTTPS画像。ローカル相対パスは議事録の親を基準とする。 |
| Mermaidコードブロック | 図として描画する。失敗時は記法を残す。timelineの期間と出来事は、描画前に実フォントで幅を測り150pxの枠に収まる位置へ `<br>` を差し込む。書かれた `<br>` は残し、`<br/>` も改行として扱う。title・section・コメント行は変えない。Mermaidは期間に `:` を含む `21:39 : 出来事` を受け付けないため、期間の `:` だけMermaid共通のエンティティ記法 `#colon;` へ置き換えて本物のコロンで描く。手書きの `#colon;` や `#58;` もそのまま通る。mindmapのノード幅上限は320px。 |
| `$...$`、`$$...$$`、`\(...\)`、`\[...\]` | KaTeXで数式を描画する。math・latexコードブロックにも対応する。 |
| SVGコードブロック、閉じたSVGブロック | sanitize後、画像として描画する。 |
| 先頭の閉じたfrontmatter | 非表示。BOM・CRLFを扱い、閉じない場合は本文を残す。 |
| 本文のHTML | 文書要素と許可したインライン装飾を安全処理して描画する。 |
| ノートの埋め込み、未対応構文 | 文字として残す。 |

コードブロックと行内コードの記法は変換しない。表のwikilinkのパイプはObsidianと同じくエスケープする。表示例は [minutes-preview-example.md](minutes-preview-example.md)。

## 実装と配布

`MinutesFileMonitor`が検証したUTF-8本文を、`MinutesWebView`から引数付きJavaScript呼び出しで渡す。本文をスクリプトへ文字列連結しない。旧TextKit用のブロック解析はプレビューの読込経路では行わない。

ファイル切替・取消の世代をSwiftとJavaScriptの両側で確認する。同じファイルの更新は先頭可視ブロックとその位置、選択の文字位置を保存して復元する。短縮時は有効範囲へ収める。別ファイルは先頭へ戻す。

Vaultの判定はSwift側で行い、議事録の切替ごとにやり直す。議事録の親から上へ `.obsidian` ディレクトリを探し、最も近いものがあるディレクトリをVaultルート、そのbasenameをVault名とする。探索はファイルシステムのルートまでで、シンボリックリンクは追わず、`.obsidian` 自身がリンクやファイルのものは採らない。Vault名は本文とは別の引数でJavaScriptへ渡し、Vault外ではnullにしてwikilinkを描かない[^vault]。クリックしたwikilinkは宛先だけをSwiftへ返し、`obsidian://open?vault=…&file=…` を組んで開く。末尾の `.md` は落とし、`/` や空白や `#` を含む予約文字はすべてパーセント符号化する。

[^vault]: Obsidianが実際に開いているVaultの一覧はアプリ外から確実には読めない。開き先を決められない場所でリンクの顔をさせないため、誤検出より取りこぼしを選んでいる。

描画ライブラリは `Sources/Kikigaki/MinutesAssets` に同梱する。SwiftPMの資産bundleを.appにもコピーするため、実行時のCDN接続やNodeは不要。外部画像だけはURLへ通信する。

更新時は `web/minutes` で以下を順に実行する。

```sh
npm ci --ignore-scripts
npm test
npm run build
```

生成済み資産とlockfileもコミットする。同梱ライセンスは `THIRD-PARTY-NOTICES.txt` と `preview.js.LEGAL.txt`。

## 実行境界

非永続のWebKitデータストアを使う。本文由来のHTMLに専用DOMPurifyを適用し、描画全体のDOMPurifyとCSPも重ねる。段落・見出し・表・リンク・画像・details/summaryなどの文書要素を許可する。文字色・背景色・文字サイズ・余白・枠線などのインラインCSSは許可リストで選別する。

script・イベント属性・iframe・form・外部CSS・固定配置・CSSのURLや変数を除去する。生HTMLのclassは除去し、idと同じHTML内のアンカーには `html-` を付け、アプリの目次や操作要素と衝突させない。HTML画像もMarkdownと同じ専用画像ローダーへ渡す。本文のSVGは画像化し、Mermaidはstrict、KaTeXはtrust無効。図の原文はコマンド実行の口へ渡さない。

`minutes-app` schemeは同梱資産、`minutes-image` schemeは現在の議事録から参照する画像だけに使う。ローカル画像は通常ファイル・1枚24MiB以下を確認し、FIFOを待たない。読込は直列化し、1回の描画で合計96MiBまでに制限する。描画ごとに画像のhostを変え、取消時には待っている要求も終了する。本文に任意のファイル読取APIを公開しない。WebKitの生成は最初の本文描画まで遅延する。

## 開発用の実画面確認

debug版.appは `--preview-minutes <絶対パス>` で議事録の検証画面だけを起動できる。マイク・モデル・AI・グローバルホットキーを起動しない。会議状態と幅設定は一時領域へ分け、終了時に片づける。
