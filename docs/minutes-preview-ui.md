# 議事録プレビューの段3検証

## 実装した操作

ヘッダーと「表示」メニューから右ペインを切り替える。パス欄はReturnで確定し、Escapeで編集中の文字を取り消す。空欄の確定は対象解除。既存ファイルは「ファイルを選ぶ…」から選べる。

右ペインは会議のMinutesStoreへ接続し、人の指定を次の送信へ渡す。非表示中のAI通知は本文を読まず、フッターの「議事録」から開ける。本文の更新では選択とスクロール位置を保ち、別ファイルや別会議では先頭へ戻る。

右上部バーは1行にし、左ヘッダーの高さと連動させた。パス欄は和紙地と細い罫線で、フォーカス中だけ墨へ変わる。本文と表は最大720ptで左寄せする。コードも折り返しを維持する。空状態の案内は上から約1/3に置き、直下からファイルを選べる。仕切りは `Washi.rule`、ヘッダーの切替は薄墨でON/OFFをアクセシビリティ値へ反映し、過大ファイルはMiB表示にした。

幅と表示状態は `KikigakiMinutesLayout` の1キーへ保存する。標準の要求は600→1800pt。画面端では追加する右側を縮め、OFFはその時点の左幅へ戻す。フルスクリーンはstyleMask、タイル相当の配置は画面全高と左右端への接触から判定して外枠を維持する。後者はAppKitに専用の公開状態がないための配置判定である。

## 段3cの交差レビュー反映

高1件・中7件・低8件とテストの穴を反映した。FIFO監視はopen前の種別確認とO_NONBLOCKで待たず、無変更の読取失敗を繰り返さない。実イベントと短い補完タイマーを使い、同サイズ保存、親とsymlinkの交換、実読込中の停止、非表示から再表示をテストした。手動のscan呼出しは使っていない。

StatusItemに表示切替を追加し、ウィンドウが閉じていても開いて切り替える。表題・チェック・ヘッダーのAX値を検証した。幅は保存済みの要求を再ONで使い、制約中は保存しない。タイル推定は全高かつ半幅／全幅に限定したが、同じ配置を手で作った場合とは区別できない。

待機中の指定は適用後に消し、準備中の新指定も開始会議へ引き継ぐ。開始取消の本番abandon経路では引き継いだ指定を保留へ戻す。適用失敗の自動再試行はせず、再確定に任せる。パス欄はフォーカスしただけでも内容を保持し、確定エラーは画面更新で消さない。

ファイル無しの文言は、クロディーヌの必須4を本人が採用した裁定変更として、一文で主語と次の動作を示す形へ統合した。人の指定は「指定したファイルはまだありません。作成されると自動で表示します」、AI由来は「AIが通知したファイルはまだありません。作成されると自動で表示します」と区別する。

### 4MiBの実測

Apple M4 Pro、macOS 26.5.2、debug buildで4,194,304 bytesの日本語段落fixtureを更新した。修正前のMainActor同期更新は841.51ms。属性付き文字列の生成を背景へ移し、非連続レイアウトと可視範囲のアンカー計算へ変更した後は178.82msだった。後者は文字列のインストールから表示位置の復元までのMainActor連続占有時間で、背景生成の待ち時間を含まない。単発測定であり分位値ではない。100msは依然超えるため、大きな文書の更新時に短い停止が残る。

```sh
KIKIGAKI_MINUTES_PERF=1 swift test --filter MinutesPerformanceTests
```

ログは `/private/tmp/preview-perf-before.log` と `/private/tmp/preview-perf-after.log`。表示中のTextKitオブジェクトは背景へ渡さず、構築完了後の属性付き文字列だけを渡す。可視範囲を指定してもAppKitがより広くレイアウトする場合はある。[AppleのensureLayout仕様](https://developer.apple.com/documentation/appkit/nslayoutmanager/ensurelayout%28forboundingrect%3Ain%3A%29)

最終buildと全570テスト成功。自動送信・確認返答・再送はシートとスケジューラの本番入口で人の指定だけを採ることを追加検証した。5場面を `/private/tmp/kikigaki-preview-ui-stage3c/` へ再撮影し全て目視した。1800ptで新録音操作の並び、720ptの本文と表、先頭表示、更新時のスクロールと選択保持を再確認した。
