# 手入力の端から端の検証

2026-09-08に、過去の実録 `2026-09-05_1412.wav` を155秒分replayした。音声認識はApple Speech、話者判別は既定のSortformer High Contextを使用。相槌省略を有効にした。録音を継続する検証に加え、一時停止中に投稿して再開する検証も行った。

## 実行条件

- 投稿指定: 処理済み音声20秒と60秒
- 本文: `https://example.com:8080/meeting;a?x=1:2` と `確認用資料 https://example.com/notes`
- `KIKIGAKI_DEBUG_TYPED_VERIFY=1` で本番の投稿・コピー・改名・統合・統合解除を実行
- AI送信指定: 音声155秒、停止後のHOLDは15秒
- AIの接続先は専用のherdrテスト応答。実際のAICaptureと会話ファイル生成を通し、同梱CLIのacceptとreplyを返した。外部AIモデルの判断やURLの取得は検証対象に含めない
- AI登録簿は検証用保存先へ隔離し、通常の登録簿とクリップボードは変更しない

実行設定・テスト応答スクリプト・ログ・全保存物は `/private/tmp/kikigaki-typed-replay/` にある。入力形式は [開発フラグ](../CLAUDE.md) を参照。

アプリは終了コード0で完走した。最終差分の全266テストとswift buildも成功した。以下は停止を挟まない初回の結果。

## 一時停止と再開を含む最終replay

`config-paused.toml` と `replay-paused-final.log`、保存物 `run-paused-final/` に記録した。音声62.5秒で一時停止し、実時間2秒を待って2件目を投稿した。一時停止中の音声を通常録音と同様に取り込まないため、最終的な収録長は135.5秒になった。検証モードではAI送信を停止後のHOLDへ回した。停止直前の確定待ちは既存仕様で取り消されるため、最終会話の送信と返送を独立に確認するためである。

| 検証 | 実測 |

| 一時停止中の投稿 | 音声62.5秒、投稿02:40:52.794 |

一時停止中・再開直後・停止後の実ウィンドウは `run-paused-final/typed-verification/` の各段階の `window.png`。行JSONとtimelineも同じ場所に置いた。この回の通常Markdownとrawは同一で、相槌省略による差の確認は初回の実録結果で補っている。

## 表示と操作

`/private/tmp/kikigaki-typed-ui/` の `posted.png`、`between-voices.png`、`paused-post.png`、`saved.png` をレビュー修正後に撮り直して目視した。声の時計は03:00・03:01と進み、一時停止中の投稿03:04を再開後の声と並べた。手入力だけをNSTextViewへ載せ、分身BのMarkdown本文と同じ朱と下線を指定している。

入力欄は常に紙地とし、無効・通常・フォーカスの枠を描き分ける。NSScrollViewのシステム枠を外し、最前面の描画ビューで1pt・角丸5の枠と横スクロールしても動かない左右2ptの紙の余白を描く。layerの枠だけではcacheDisplayに写らないため、実画面と画像取得で同じ描画を通す形にした。停止後の下書きには「未投稿」を表示して編集と選択を無効にし、空欄なら「録音中に書き込めます」を出す。

IME確定Enter、次のEnterでの投稿、Shift+Enter、複数行貼り付け、Escによる下書き保持、録音外の受付拒否、名前と本文の検索、検索後のリンク属性維持はAppKitテストで確認した。OSの日本語候補ウィンドウを人が操作する検分は別途行える。

過去の40行を検索して上へスクロールした状態から、一時停止中に投稿して末尾が見えることを回帰テストで確認した。一時停止中も録音中と同じ出現効果を使う。時刻tooltipに音声位置と投稿時計の意味を添え、本文が同じ場合の再構築を省き、表示側のpostedAt強制アンラップを除去した。

AIシートのplaceholderは最後のvoiceまたは聞き取り中の声だけを使う。typedしかない場合にURLを声の末尾として出さない回帰テストを追加した。
