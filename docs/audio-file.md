# 音声ファイルの書き起こし

保存済みの音声ファイルを会議の音源にして、録音と同じ書き起こし・話者判別・保存を行う。録音をやり直すのではなく、録った後の後処理を1回で済ませるための機能。

決めた経緯と試作の数字は [音声ファイルの書き起こしの試作記録](records/audio-file-spike.md) にある。

## 入口

待機中にだけ受け付ける。録音中・準備中・保存中・書き起こし中は受け付けない。

- メニューバーの「音声ファイルから書き起こす…」。「録音を開始」の直下に置き、ファイル選択の窓を開く
- 書き起こし窓へのファイルのドロップ
    - 音声として読めないファイルは受け付けない
    - 手入力欄への画像のドロップとは別。手入力欄は録音中だけ受け付けるので重ならない

Finderの「このアプリケーションで開く」とDockのアイコンへのドロップは持たない。扱えるファイルの種類をInfo.plistへ登録する必要があり、入口を増やす理由がまだない。

## 対象のファイル

- macOSが音声として扱う種類(`UTType.audio` に適合するもの)のうち、`AVAudioFile` が読めるもの。m4a・mp3・wav・aiff・cafなど
    - 入口の判定: ドロップとファイル選択は種類で絞る。読めるかは開始シートを出す前に確かめる
- 読めないファイルは開始シートを出さず、ヘッダーに理由を1行出す
- 動画ファイルは対象外
- 1本を1会議にする。マイクとシステム音声のような2本の同時ファイルは扱わない

## 開始シート

録音と同じ開始シートを、音源がファイルの形で開く。決めた値がその会議だけに効き、設定ファイルへ書き戻さないのも録音と同じ。

| 行 | 録音 | 音声ファイル |
|---|---|---|
| 題 | 録音を開始 | 音声ファイルを書き起こす |
| 次の会議 | 予約があれば出す | 出さない。予約も消費しない |
| 音声ファイル | なし | ファイル名・長さ・録音日時。「選び直す…」でファイルを替えられる |
| システム音声・マイク | 出す | 出さない |
| 話者判別・小音量除外・議事録 | 出す | 録音と同じ |
| 自動送信 | 宛先・プロンプト・間隔・作業許可・最後の1回 | 見出しを「完了時に送信」にし、宛先・プロンプト・作業許可だけを出す |
| 手動送信 | 出す | 出さない |

- 使わない行は無効で見せずに出さない。押せない部品を並べても決めるものは増えないため
- 「完了時に送信」は、書き起こしを終えて保存した時点で1回だけ送る。録音の「最後の1回」と同じ送信で、宛先を「送らない」にすれば送らない
- 音声ファイルの行の書式は「32:15 · 10/20 10:00 録音」
- 選び直したファイルを確かめる間は開始できない。続けて選び直したら、最後に選んだものを使う

## 会議の日時

会議の開始時刻は、音声を録った日時にする。会議Markdownのファイル名・見出し・行の時刻・保存先での並びが実際の会議と揃う。

1. 音声のメタデータの作成日時
2. 無ければファイルの作成日時

どちらも録音の開始ではなく書き出しの時刻のことがある。その場合も推測で補正しない。

## 流し方

- 速報の並走を止め、高精度だけで書き起こす
    - 理由: 品質を変えていたのは流す速さではなく速報の並走だった。速報なしなら最速でも等倍と本文・話者が一致した
- 間を置かずに流す。消費側が追いつくまで供給を止め、先行は音声で30秒までにする
    - 理由: 間を置かないと、ファイル全体が待ち行列にも載ってメモリ上で二重になる。消費位置が画面の進み具合として意味を持つ
    - 限界: 抑えるのは消費ループ(話者判別と文字起こしへの入力)まで。Apple Speechが入力を読む速さは抑えない。Speechが遅れても、余分に持つのはファイル1本分まで
- 開始シートを閉じてから変換が終わるまでは、会議は待機中のまま。この間はほかの開始操作を受け付けない
- 消費側が終端まで処理したら、録音の停止と同じ保存へ進む
- WAVは保存しない。元のファイルが残っているため。`saveRecording` はこの会議に効かない

## 書き起こし中

録音の操作のうち、時間の流れに依存するものは持ち込まない。

| 機能 | 書き起こし中 |
|---|---|
| 一時停止 | なし。ボタンを出さない |
| 手入力 | 受け付けない |
| 手動送信・声の合図・グローバルキー | 送らない。グローバルキーは理由を通知する |
| 定期の自動送信 | なし。「完了時に送信」の1回だけ。フッターの「自動実行…」からも始められない |
| 録音中の途中保存 | しない。中止で保存しない約束と、数十秒で終わる処理時間のため |
| マイクの切替 | 起きない |

- ヘッダーの状態は「書き起こし中 12:30 / 32:15」。処理した音声の位置と全体の長さを出す
    - 色: 朱の面にしない。朱の面は録音中の印に限るため
- 時刻帯は、書き起こし中は録音と同じ「10:00〜」。保存後は日付を添えて「10/20 10:00〜10:32」
    - 理由: 書き起こし中は状態の札が位置と長さで伸びる。日付も添えると、600ptの幅でも札が押し縮められた
- 停止の位置に「中止」を置く。中止すると保存せず、予約した会議Markdownも消す
- メニューバーの状態は「書き起こし中」、開始・停止の項目は「書き起こしを中止」
- アプリの終了も中止として扱い、保存しない
    - 例外: 流し終えて保存が始まっていたら、保存を終えてから終了する
- 流し終えた通知は、今の会議の音源から届いたものだけを受ける。中止の後に届いた古い通知で次の会議を止めない

## 書き起こしの後

録音を停止した後と同じ。改名・話者の統合・小音量除外の調整・会話のコピー・議事録ペインが使える。「完了時に送信」の返事待ちと、AIのペインの後片付けも録音と同じ流れ。

会議Markdownの「長さ」の下に、元のファイル名を1行出す。

```markdown
- 開始: 2026-10-20 10:00
- 長さ: 32:15
- 音声: 定例.m4a
```

## 開発用のreplayとの関係

`--replay` は既定で録音の模擬のまま。音声の合図・手入力・AIの送信を音声の秒で試すのに使うため。`KIKIGAKI_DEBUG_REPLAY_FILE=1` を付けると、この文書の書き起こしの経路を通す。詳細は [開発用のフラグと環境変数](dev-flags.md)。
