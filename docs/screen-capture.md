# 画面の記録

会議中に利用者のMacが映している画面を画像で残し、書き起こしの時間軸とAIへ渡す会話に結びつける。この文書が画面の記録の単一情報源。

- 入口: 録音開始シートの「画面」で選んだディスプレイを撮る。シートの値の扱いは [録音開始シート](start-sheet.md)
  - 録音中と一時停止中は、フッターで対象を確かめて替え、記録を切り、入れ直せる。下の「録音中の切り替え」
    - 切る・入れ直すは、設定したグローバルキーでもできる。下の「グローバルキー」
  - 撮っているディスプレイには、右下のバッジと切り替えた瞬間の知らせを出す。下の「撮っている画面の印」
- 流れ: 撮る契機の判定 → 撮影と保存 → 無音の間の保留 → 画面の行として公開 → 画像レーンに表示・会議Markdownに埋め込み・AIへ渡す会話に参照
- 設計の経緯: owlery Vaultの「KIKIGAKI 会議中の画面の記録の設計方針案 2026-11-09」
- 撮る契機の初期値の根拠: [画面の記録の試作の検証記録](records/screen-capture-spike.md)
- 動き続ける画面と直近の画面の規則の根拠: [動き続ける画面と交互に変わる画面の規則の試作の検証記録](records/screen-motion-alternation.md)
- 無音の間の保留の見積もり: [無音の間の画面の保留の見積もり](records/screen-silence-estimate.md)
- 持たないもの
  - 撮る契機のしきい値と、無音とみなす秒数の設定キー
  - 監視フォルダからの取り込み
  - 録音中に替えた対象を次の録音へ引き継ぐこと
  - 公開した画面の行を後から消す操作。無音の間の画面は公開しないことで減らす
  - 話している間に撮る間隔の調整。話している間の画面は変化ごとに全部残す

## 行の形

画面の記録は `Utterance.Kind.screen` の行として、声・手入力と同じ列に並ぶ。

- 画像の行: 画像1枚と、空でない1行の見出し。見出しはディスプレイ名と、取れれば最前面のウィンドウのアプリ名と題
  - 例: `EV3895 · Keynote「提案資料」`
  - 見出しの改行と制御文字は空白へ寄せる。ウィンドウの題は利用者のアプリが決めるため
- イベントの行: 画像なしで、本文は次の決まった文言のどれか。保存物の契約なので文言を変えない
  - `記録を停止` / `記録を再開` / `記録できません: <理由>`
  - 出す条件: 下の「録音中の切り替え」の「イベントの行」と「撮れなくなったとき」
- 共通: 話者は持たない。`start` と `end` は画像を観測した時点の音声位置で、同じ値。`postedAt` は観測した実時刻
  - 時計の表示は `postedAt` を使う。手入力の投稿日時と同じ扱い
- 互換: `screen` を知らない古いバージョンのアプリは、画面の行を含む会議をデコードエラーにする。`typed` を足したときと同じ前方互換の割り切り

## 保存とAIへの行

- 会議Markdown: `- [14:05:40] 画面: EV3895 · Keynote「提案資料」 ![画面1](<file://…>)`
  - イベントの行: `- [14:20:05] 画面: 記録できません: <理由>`
- 会話ファイル・「会話をコピー」・AI送信: `[14:05:40] 画面: EV3895 · Keynote「提案資料」 画像1: `/abs/path.webp``
  - 手入力の画像と同じ `TranscriptRenderer.line` を通る
  - AIが画像を読める条件と置き場 `image_dirs`: [AIへの受け渡し](ai-handoff.md) の「画像の参照」
  - 送信済みの範囲より前の位置に遅れて届く行の差分: [AI参加者の設計](ai-participant.md) の「Envelopeと差分の基準」

## 経路ごとの扱い

声以外の行(手入力と画面)を、経路ごとに3つに分けて扱う。一律に「声でない行」へ広げない。

- 共通にする(`Utterance.isEntry`): 手入力と画面を同じに扱う
  - 併合の順序と同点処理: `TranscriptEntries.merge`。声と同じ位置なら実時刻で並べ、声以外の行どうしは届いた順を保つ
  - archiveの退避と再併合: `MeetingArchive.replaceResult`。改名・統合・再判定で声を作り直しても残す
  - AI送信の値コピー: `AICapture` の `typed` に、送信操作の時点で公開済みの行を渡す。無音の間に保留していた画面は、値を取る前に公開する。下の「無音の間の保留」
  - 時計の日時: `TranscriptRenderer.date(for:)`
  - 会話範囲の終点: `SessionSnapshot.contextEnd`
  - 音量の計測から外す: `MeetingSession` の評価。声以外の行に「音量 未計測」を付けない
  - 半透明の対象から外す: 行ビューの `updateConfirmation`。画面の行は行ビューを持たず、画像レーンも半透明にしない
- 画面だけの枝を足す
  - 表示名: 「画面」。`SpeakerNames.displayName(for:)`
  - 絞り込みの相手: `TranscriptFilter.Subject.screen`。選ぶ一覧には出さない。書き起こしウィンドウでは行を持たず、画像は割り当て先の発言と一緒に出し隠す。下の「表示」
  - 書き起こしウィンドウ: 発言の列に行を出さず、右の画像レーンに出す。検索の一致にも数えない。下の「表示」
  - Markdownの行: 見出しの後ろに画像を1行で埋め込む
  - 保存の検証: 画像の行とイベントの行のどちらかに当たらなければ不正
  - 受領の境界線: `AIRangeBoundaries` の候補から外す。画面の行は保存の遅れで送信済みの範囲より前に届くことがあり、線は声と手入力の位置で引く
    - 受け入れた限界: 画面の行が境界線より上に置かれても、その画面がAIに渡ったとは限らない。線の意味は「声と手入力の受領範囲」に限る
- 声に限る(触らない)
  - 送信の印の `voiceAnchorIndex`、問いの末尾の `voiceQuestionPlaceholder`
  - 小音量の除外、発言ごとの音声再生、声の合図
  - 話者の補正と固定、話者数と話者一覧

## 表示

書き起こしウィンドウでは、画面の行を発言の列から外し、右の画像レーンに出す。発言の列は途切れない。表示専用で、行の持ち方・会議Markdown・会話ファイル・AIへの渡し方は変えない。

- 設計の経緯: 設計方針案の「表示」の決め直し。試用で画面の行が発言の間に2〜4秒ごとに挟まり、本筋を追いにくかった
- 無音の間の画面は遅れて出る: 公開するまで画像レーンにも出ない。話し始めや送信の操作で、観測した位置の発言の横に1枚だけ出る。仕組みは「無音の間の保留」
  - 例: 黙ってスライドを2枚送っている間は新しい画面が出ず、話し始めた瞬間に最後のスライドが1枚出る
  - 消える動きは無い。開いた「+N枚」、Quick Lookの一覧と見ている画像は、保留の公開で変わらない
- 実装: 割り当てと畳み方は `ScreenLane`(`KikigakiCore/ScreenLane.swift`)、描画は `ScreenLaneView`、組み立てとQuick Lookは `TranscriptWindowScreenLane.swift`
- 並び: 画面の行を飛ばしても、その位置までのマイク切替は先に置く。画面の行の後ろに付くAIの行より前に出す

### 置き場

画像の行もイベントの行も、同じ規則で発言の横に置く。割り当ては行の並びから毎回導き、状態として持たない。録音中に行が増えても、話者の付け替え・併合で行が変わっても、次の更新で置き直す。

- 観測した時点に話していた声の行の横。区間は開始〜終了の両端を含む
  - 区間が重なる声の行では、後から話し始めた行。話者の交代の直後に映った画面を、話し始めた次の話者に結びつける
- 誰も話していない間なら、次の声の行の横。会議の頭の画面は最初の発言の横に入る
- 後ろに声の行がまだ無い画面: 会議の末尾と、録音中の最新が当たる
  - 聞き取り中の行があれば、その横。確定すればその行へ移る
  - 無ければ、末尾にレーンだけの行を出す。発言の列は空ける。次の発言が届けばそちらへ移る
- 手入力の行は割り当て先にしない
  - 理由: 手入力は投稿した時点の点で、話していた区間を持たない。自分の添付画像も持ち、横にサムネイルを並べると、どちらが貼った画像か取り違えやすい

### 1つの発言に何枚もあるとき

- 2枚までは全部出す。3枚以上は最初と最後を出し、間をトレイに畳む。押すとその場で開く
  - トレイ: 畳んだ画像の連なりを載せる、角の丸い淡い背景の受け皿。畳んでいる間は頭の1行だけで、開くと下端が伸びて中の画像を載せる
  - 開いた状態は画像のパスで覚える。割り当て先が変わっても開いたまま保つ。会議が変わると閉じる
- 開いている間は、トレイの頭の行に「畳む」を出し、末尾にも同じ「畳む」の行を置く。押すと開いた覚えを消し、頭の1行に戻る
  - 理由: 開いた場所と閉じる場所を同じにする。開いたままだとレーンが縦に伸び続ける。長い連なりを下まで読んだ所からも、上へ戻らずに閉じられるようにする
  - 見た目:
    - 畳んでいるとき: 畳んだ画像の小さな見本、「+N枚」、右端に下向きの山形。トレイの全体が押せる
    - 開いているとき: 頭に「N枚」を薄墨で、右端に「畳む」と上向きの山形。末尾の行は右端の「畳む」と山形だけで、頭と同じ位置・同じ見た目。トレイの縁が開いた分の範囲を示す
    - 理由: 前の形は、押した瞬間にボタンのすぐ下の最後の画像が大きく下へ飛び、目で追えなかった。畳まれた画像そのものも見えず、開いた分の終わりに境目も無かった。動く端を押した部品の一部にし、伸びる端を目で追えるようにする
    - 寸法: 行の高さは28pt。トレイはサムネイルの幅から左右へ6ptはみ出す。左は8ptの余白、右はスクローラー用の20ptの中に収まる。サムネイルの幅は変えない
    - 間隔: 頭の行と最初の画像の間、最後の画像と末尾の行の間は2pt。中の画像どうしと、トレイの前後は12pt
    - 色: 背景は罫色 `rule` の45%。ポインタを乗せると、その行に薄墨 `muted` の12%、押している間は22%を重ねる。開いたトレイでは、頭の行は上の角だけ、末尾の行は下の角だけを丸める。影とグラデーションは付けない
    - 文字: 11pt。「+N枚」と「畳む」は墨、開いた頭の「N枚」は薄墨。山形は8ptの薄墨。文字の倍率を掛けない。操作部なので固定の大きさ
    - 小さな見本: 幅28pt、高さは画像の縦横比のまま。4pt間隔で3枚まで。それより多い分は見本を出さず、「+N枚」の数で伝える。狭いレーンや桁の多い枚数で、枚数の文言が右端の山形と重なるなら、重ならない枚数まで減らす。開く途中は右端に「畳む」もあるので、その幅と4ptの間隔も空ける
    - 押せる所: 畳んでいるときはトレイの全体、開いているときは頭の行と末尾の行だけ。中の画像は今までどおりQuick Lookで開く。はみ出した6ptは押せない(受け入れた限界)
    - 実装: 行は `ScreenLaneFoldButton`、背景は `ScreenLaneTrayBackground`。トレイの範囲と間隔は `ScreenLaneTransition.Part` と `gap`
  - 読み上げ: ラベルは「間のN枚を開く」「間のN枚を畳む」。値と展開の状態で、畳んでいるか開いているかを伝える。ツールチップはラベルと同じ
  - 伸び縮み: 開くときはトレイの下端が下へ伸び、その中で画像が0から伸びて出る。畳むときはトレイが縮んで頭の1行に戻る。行の高さも一緒に変わる。約0.2秒で、終わりへ向けて緩める
    - 文言と山形は押した時点で替える。頭の行は作り直さない。小さな見本は、開くときは前半で薄くして消し、畳むときは後半で濃くして出す
      - 見本は薄くなるのと一緒に左端へ縮み、枚数の文言もその右に付いて動く。薄くなる途中の見本と文言を重ねない
      - 濃さはその時点の値から動かす。通常の閉じ始めは0から。途中で反対の操作をしたら、いまの濃さから続ける
    - 「視差効果を減らす」が有効なら、伸び縮みせずにその場で切り替える
    - 作り: 枠ごとに見えている割合を持ち、高さと前の枠との間隔に掛ける。1コマごとに行の高さを決め直し、スクロールの位置を保ったまま文書を並べ直す。増減する枠は押したボタンより下にあるので、ボタンと上の内容は動かない
      - 行の高さはもともと毎回の並べ直しで足し上げる作りで、載っているのは表示域の近くの行だけなので、1コマの費用は小さい
    - 枠は鍵で突き合わせる。画像はパス、イベントは時刻と文言、「+N枚」と「畳む」は最初の画像のパス。「+N枚」と「畳む」は同じ鍵で、押した位置でその場で入れ替わる
    - 途中で反対の操作をしたら、その時点の割合から動かし直す。連打しても、最後の操作の状態で終わる
    - 途中で録音中の行の追加・絞り込み・レーンの幅のドラッグが重なっても、そのレーンの並びが変わらなければ伸び縮みは続く。並びが変わったときはその場で次の並びへ切り替える
    - 別の行を開閉しても、動いている途中の行は時刻を置き直さずにそのまま進む。開始の時刻を置くのは、その操作で組み直したレーンだけ
      - 理由: 置き直すと、動いている行の割合が始めの値へ戻り、その行より下が跳ねる
    - 途中で終わらせるときは、どの経路も `finishScreenLaneTransitions` で最後の状態に確定する
      - 「最新の発言へ」: 確定してから末尾へ動かす。伸び縮みの間はスクロールの位置を保つので、確定しないと伸びた分だけ末尾から離れ、次の発言で追従しない
      - 「視差効果を減らす」が途中で有効になったとき
      - 会議の切替
      - ウィンドウの解放: 並べ直す相手が無いので、タイマーだけを止める。繰り返しのタイマーはRunLoopが持ち続けるため
    - 計算は `ScreenLaneTransition`(`KikigakiCore/ScreenLaneTransition.swift`)
  - スクロール: 押したボタンの画面上の位置に、入れ替わった相手(「畳む」なら「+N枚」、「+N枚」なら「畳む」)を置く。開く向きも同じ。末尾を読んでいても末尾へは飛ばさない。検索中・絞り込み中も同じ
    - 相手は並べ直した後に対象の画像のパスで探す。割り当て先の併合などで手前に別の「+N枚」があると、畳んだ分がそれと1つにまとまり、行の上端を保つだけでは相手が押した位置より上に来るため
    - 例外: 押したボタンが表示域の上へ出ていた場合(キーボードや読み上げで押した場合)は、相手を表示域の上端へ寄せる。縮んだ分だけ下の内容が上がり、どこを開閉したか見失うため
    - 末尾の「畳む」: 畳んだ後のトレイの下端を、押した行の下端の位置に置く。伸び縮みの間も毎コマ合わせるので、上の内容がトレイと一緒に下りてきて、畳んだトレイが押した所に収まる
      - 理由: 頭の位置を保つと、末尾から読み返していた目の前からトレイが消え、上へ探しに行くことになる
      - 伸び縮みの間は、押した末尾の行のいま見えている下端を合わせる。消え終えたら、畳んだ頭の行のトレイの下端へ引き継ぐ
        - 理由: 手前の「+N枚」と合流すると、合流先の頭と消えていく旧いトレイは、縮み終えるまで別のトレイに見える。合流先の行だけを見ると、縮み始める前に旧いトレイの高さの分だけスクロールが跳ねる
      - 頭の「畳む」が画面の外に出ているほど長いトレイでも同じ。畳んだトレイが押した所に収まる
      - 受け入れた限界: この0.2秒の間は、利用者のスクロールよりこの位置合わせを優先する
    - 受け入れた限界: 文書の末尾が表示域に入っていると、縮んだ分はスクロールの上限で詰まり、相手はその分だけ下へずれる
  - フォーカス: 押したボタンにキーボードのフォーカスがあったときだけ、入れ替わった相手へ移す。並べ直しで押したボタンは消えるので、移さないと同じ場所でスペースキーを続けて押せない
  - 開いた後に間へ届いた画像は、開いた連なりとは別の「+N枚」に畳む
  - Quick Lookの一覧と見ている画像は変えない
- イベントの行は畳まない。撮れなかった期間を見落とさないため。間の画像はイベントの行の前後で別のトレイに分ける

### 見た目

- レーンの幅は既定で180pt。境目のドラッグで180〜480ptに変えられる。下の「レーンの幅」
- サムネイルの幅はレーンの幅から28ptを引いた幅。左に8pt、右にスクローラーの分の20ptを空ける。上端は発言の名前の行に揃える
  - 枠の高さは画像の縦横比に合わせる。画像の輪郭に罫色の細い線を引く
    - 理由: 画面の縦横比はディスプレイごとに違う。16:9の固定の枠に収めていた頃は、横長の画面(3840×1600など)で画像の下に20pt余りの空きが出て、題が下の次の画像のものに見えた
    - 縦長の画面は枠の高さを幅までに抑え、枠の中へ縦横比を保って収める。広げたレーンで1枚が画面を埋めないため
    - 縦横比はファイルの頭だけをメインスレッドで読み、パスごとに覚える。読み込みの前に枠の高さを決め、読み終えた後に行の高さを変えないため。デコードはしない。実測で1枚0.2ms(初回)、0.06ms(2回目以降)
    - 寸法が読めない画像は16:9の枠にする
  - 縮小画像は描くときに裏のキューで読み、会議をまたいでキャッシュする。同じパスの読み込みは1回にまとめる。読み終えるまでは罫の枠だけを描き、行の高さは変えない
    - 理由: 展開や速いスクロールで何枚も初めて出したときに、UIを待たせないため
    - 読む大きさ: サムネイルの幅を152pt刻みで切り上げ、その2倍の画素で長辺を読む。304・608・912pxの3段で、広げたレーンでもぼやけない
    - 大きさを替えて読み直す間は、読めている別の大きさの画像で描く
  - 実装: 寸法は `ScreenLaneLayout`(`KikigakiCore/ScreenLaneLayout.swift`)
- サムネイルのすぐ下に、観測の時刻と題を1行で添える。収まらなければ末尾を省き、全文はツールチップで出す
  - 間隔: 画像と題の間は3pt、題と次の枠の間は12pt。どの画像の題かを、間隔だけで読み分けられるようにする
  - 題: 見出しからディスプレイ名を省く。ウィンドウが無い見出しは時刻だけになる
    - ディスプレイが1つの会議: 全画像から省く。毎枚同じ名前を重ねて言わない
    - 録音中に対象を替えた会議: 直前の画像と同じディスプレイなら省き、違えば残す。最初の1枚も残す。替えた直後の1枚で、どのディスプレイに替わったかが分かる
    - 実装: `ScreenLane.captions`
  - 「画面」のようなラベルは足さない。サムネイルを見れば分かるため
- イベントの行: 時刻と決まった文言を薄墨で出す。3行まで折り返す
- 発言の行が画像の分より低ければ、行を画像の高さまで伸ばす。本文と音量の注記は上から詰めたまま
- 発言の行の半透明(未確定・小音量の除外)はレーンに掛けない。画像は声の確定や除外と関係なく保存される
- 更新の点灯は発言の文字の部分だけ
- 文字の倍率: 時刻・題・イベントの文言に掛ける。レーンの幅、サムネイルの枠、トレイの行には掛けない
- AIの行・マイクの切替・絞り込みの線・範囲の印は、発言の列の幅に収める
- 画面の行が1つも無い会議では、レーンを出さず、幅も今のまま

### 操作

- サムネイルを押すと、Quick Lookで原寸を開く。会議の全画像をパネルに渡し、押したものから開く。←→で前後の画像へ送る
  - 録音中に画像が増えたら、開いているパネルの一覧も揃える。見ている画像は動かさない
    - 見ている画像はパネルがいま出している番号から取る。パネル側の操作で移った画像を、最後に押したサムネイルへ戻さないため
  - パネルのデータ源とデリゲートは `ScreenPreviewSource` に渡し、書き起こしウィンドウのコントローラーは渡さない
    - 理由: `QLPreviewPanelDelegate` は `NSWindowDelegate` を継承する。コントローラーを渡すと、パネルを閉じた通知で議事録の監視を止め、パネルの画面変更でウィンドウの幅を直してしまう
  - 手入力の添付画像は既定のアプリで開くまま
- 話者での絞り込み: 画像は割り当て先の発言と一緒に出し、畳む。選ぶ一覧に「画面」は足さない
  - 末尾のレーンだけの行は、割り当て先の発言が無いので絞り込み中も出す
- 検索: 画面の見出しは一致に数えない。移れる行が無いため

### レーンの幅

発言の列と画像レーンの境目を左右にドラッグすると、レーンの幅が変わり、幅に合わせてサムネイルが大きくなる。

- 範囲: 180〜480pt。発言の列には420ptを残す。会話側が狭ければ、広げられる上限はそこまで
  - 420ptはウィンドウの最小幅と同じ。これより狭いと本文の折り返しが増えて読めない
- ウィンドウの幅は変えない。会話側の中で、発言の列とレーンが分け合う
  - 議事録を開いている間も同じ。議事録ペインの幅は変えない
  - 理由: ドラッグした境目がポインタに付いて動く。ウィンドウを広げると、画面の右端で伸ばせず、ポインタと境目がずれる
- つかめる範囲: 発言の列の右端の4ptから、サムネイルの左端の手前まで。乗せると左右に動かせるカーソルになる
  - 線や取っ手は描かない。見た目は今までのまま
  - サムネイルには掛けない。押すとQuick Lookで開くため
  - 画像が無い会議(イベントの行だけの会議を含む)と、レーンを出さない会議ではつかめない
- 覚え方: 離したときに、幅を `KikigakiMinutesLayout` の `screenLaneWidth` へ保存する。次の会議と次の起動でも使う。設定ファイルへは書かない
  - 同時に、そのときの発言の列の幅を希望幅 `leftWidth` として保存する。次の会議や次の起動で、広げたレーンの分だけウィンドウが広がらないようにするため
  - 例外: タイル・フルスクリーンでは発言の列の幅を取らない。制約された幅は希望幅ではない。議事録の開閉と同じ扱い
  - キーの無い保存値は既定の180ptとして読む
- 会話側が狭まったとき(ウィンドウの伸縮、議事録の区切り線のドラッグ): 発言の列が420ptになるまでは列が縮み、その後はレーンが180ptまで譲る。広げ直すと保存した幅まで戻る
  - 譲った幅は希望の幅 `screenLaneWidth` に入れない。希望の幅は境目のドラッグでだけ変わる
- ウィンドウの合わせ直しに使う幅は、希望の幅と分けて `screenLaneShownWidth` に保存する。`leftWidth` を取るたびに、そのとき出していたレーンの幅を一緒に取る
  - 合わせ直し(ライブリサイズの終わり・画面の変更・議事録の開閉)では、`leftWidth` にこの幅を足す。いまのウィンドウの幅を保ち、その内側でレーンを抑える
  - 理由: 希望の幅を足すと、ウィンドウを狭めてレーンが譲った分だけ、リサイズの終わりにウィンドウが広がる。例: レーン480ptで700ptへ狭めると、発言の列420ptとレーン280ptになり、希望の幅を足すと900ptへ戻ってしまう
  - 例外: レーンを出すときは希望の幅の分だけ広げる。下の「ウィンドウの幅」
  - キーの無い保存値は希望の幅として読む
- ドラッグの間は縮小画像を新しく読まない。読めている画像を引き伸ばして描き、離してから今の幅に合う大きさで読む
- 境目は `TranscriptDocument` が受け、幅の範囲は `ScreenLaneLayout.dragged` が決める。行は作り直さず、幅を渡して高さを測り直す

### ウィンドウの幅

レーンが出るとき、発言の列が狭くならないよう、ウィンドウをレーンの分だけ右へ広げる。レーンの無い会議へ移ると、同じ分だけ縮める。広げる量はレーンの希望の幅 `screenLaneWidth`。前に狭めたウィンドウで譲った幅は引き継がない。

- 希望幅: 議事録ペインの幅と同じ1キー `KikigakiMinutesLayout` の `leftWidth` に、レーンを含まない発言の列の幅で保存する。開閉・ライブリサイズ・レーンの出入り・境目のドラッグのどれでもレーンの分を引いて保存する
  - 理由: 含めて保存すると、レーンの無い会議や次の起動で、前の会議のレーンの分だけ広いまま残る
  - レーンを足す直前に、ライブリサイズ以外で変わった幅も希望幅として取る。議事録の開閉と同じ扱い
  - レーンを外すときは取らない。理由: 画面の右端や狭い画面で伸ばせなかった幅からレーンの分を引くと、足す前の希望幅より狭い値を保存してしまう。レーンの出ている間の手動の変更はライブリサイズで取る
- 最小幅: 会話側の最小幅に、レーンの最小幅180ptを足す。議事録の区切り線のドラッグの下限も同じ。広げたレーンは、会話側が狭まると180ptまで譲るため
  - ドラッグの下限: レーンを除いた幅で発言の列の下限を比率から決め、その後でレーンの分を足す。全体に比率を掛けると、レーンの分まで削られて発言の列が最小幅を割るため
- 議事録を開いている間: 右ペインの幅は変えず、ウィンドウを広げて会話側だけを伸ばす
- タイル・フルスクリーンなど幅を変えられないとき: ウィンドウは広げない。議事録を開いていれば右ペインから、閉じていれば発言の列から譲る
- 伸縮は一瞬で切り替える。レーンは会議を開いた時点か最初の1枚で出るので、録音中に何度も伸縮しない
- 最前面への固定には関わらない
- 議事録ペインの幅と復元の全体は [議事録ペイン](minutes-pane.md) の「幅と復元」

## 撮影と保存

`ScreenRecorder`(`Kikigaki/ScreenRecorder.swift`)が会議ごとに1つ、選んだディスプレイを撮る。

- 有効化: 開始シートの「画面」でディスプレイを選んだ録音と、録音中にフッターで選んだ録音。既定は撮らない。音声ファイルの書き起こしとreplayでは撮らない。シートの値の保存は [録音開始シート](start-sheet.md)
  - マイクの録音では、「撮らない」で始めても `ScreenRecorder` を作り、対象をnilにしておく。途中から選べるようにするため。下の「録音中の切り替え」
- ストリーム: SCStreamを1x寸法・`minimumFrameInterval` 1秒・カーソル無しで開く。Retinaは半分に縮めて受け取る
  - KIKIGAKI自身のウィンドウは、撮影と変化の検知から外す。書き起こしの更新を「変化」にしないため。議事録ペインを参加者に映していても、その画面は残らない
- 時刻: 画像の行の音声位置と実時刻は、そのフレームの `displayTime` から求める。受け付けた音声の位置から観測からの経過を引き、受け付けた位置より後ろにはしない
- 題: フレームを受け取った時点で `CGWindowListCopyWindowInfo(.optionOnScreenOnly)` の前から順に、対象ディスプレイに重なる通常レイヤーのウィンドウを採る。KIKIGAKI自身は除く。無ければディスプレイ名だけ
  - 全画面のChromeなど題が空のウィンドウは、アプリ名だけになる
- 保存: `<会議名>.captures/HHmmss.webp`。同じ秒の2枚目以降は `_2` を足す。1x寸法の非可逆WebP、品質80。フォルダは0700、画像は0600で排他的に公開する
  - 置き場を手入力の添付 `<会議名>.attachments/` と分ける理由: 添付は利用者が貼ったもの、記録は自動で溜まるもの。あとで記録だけを消せるようにする
  - 符号化: libwebpを静的に同梱する。macOSのImageIOはWebPを書けない
- 一時停止: 撮らず、ストリームも止める。再開の直後は、一時停止の前の画面と違えば落ち着きを待たずに1枚撮る
  - 比較の基準は一時停止をまたいで引き継ぐ。一時停止の直前に保留を公開するので、基準はその画面と一致する。同じ画面を2枚続けて残さない
  - 撮るかどうかは操作の時点で切り替える。ストリームの開始・片付けは待たず、操作した順に1本で後から流す。開始を待つ間に一時停止・停止したら、開いたストリームをすぐ閉じる
- いま撮る: フッターの画面の記録の操作のメニューの項目。選んだ対象の、いまの世代の開始を終え、その撮影に要るものが揃って撮っている録音中だけ出す。一時停止中・停止後・対象を替える途中・再開でストリームを準備し直す間と、撮れなくなった後は出さない。押した時点で1枚取り、しきい値によらず保存する
  - 替える途中: 替えた後に元の対象へ戻した場合も、戻した開始を終えるまでは出さない。表示と選んだ対象が一致していても、まだ撮っていない
  - 時刻の例外: 音声位置と実時刻は押した時点に置く。`SCScreenshotManager.captureImage` は観測した時刻を返さないため
  - 無音の間でも保留を通さず、すぐ公開する。受付の番号がそれより小さい自動の保留は、それより古いので画像ごと捨てる。後に受け付けた保留は、手動の完了が遅れても残す
  - 公開した1枚を判定器の比較の基準にする。捨てた保留を基準に残すと、画面がそれへ戻っても変化なしとなり記録できない。手動で撮った画面のまま自動でもう1枚撮ることも無い
  - 公開した1枚は、判定器の直近に公開した画面にも入れる。基準の新旧とは別に、最後に見た時刻で比べる
  - 基準の新旧は受付の番号で比べる。完了した順では決めない。続けて押した複数の「いま撮る」は、完了が逆順でも後に押した方が基準になる

### 保存と公開の順序

判定・符号化・書き込みは音声スレッドともMainActorとも別のキューで行い、次の順を守る。

1. 保存を決めた時点で、そのフレームの音声位置・実時刻・見出しを固定する
2. 画像を原子的に書く
3. MainActorで、公開する前に一体で確かめる。同じ会議の記録か、無効にされていないか、受け付ける状態か。外れたら書いた画像を消す
   - 消し方は保留の破棄と同じ。消せなければ消し直す。下の「無音の間の保留」の「画像を消せなかったとき」
   - 受け付ける状態: 録音中・一時停止中と、停止処理中の受付済みの処理
4. 画面の行を公開する。自動の1枚は、無音の間なら公開せずに保留する。判定器へは、保留も含めて保存の成功を返し、その場の行き先を添える。公開した・保留へ入れた・届いた時点で捨てた、のどれか
   - 保留の行き先と公開の契機: 下の「無音の間の保留」
   - 保留した1枚を後で公開したか捨てたかは、受付の番号で判定器へ知らせる。下の「撮る契機の判定」の「直近に公開した画面」

- 停止: 停止の操作の時点で新しい保存を受け付けなくする。ストリームの片付けは待たず、音源の停止を遅らせない。受付済みの処理の公開を最大3秒待ってから最終保存へ進み、超えた分は無効にする。無効にした処理は3.で弾かれる
  - 3秒は単調時計で測る。「いま撮る」は押した時点で受付済みになる
  - 待ちを終えたら、保留していた画面を全部公開してから最終保存へ進む。保留は書き込みを終えているので、3秒の待ちを使わない
- 結果の返し方: 保存の成功・失敗・公開の拒否は、保存した順に1本でMainActorへ返し、判定器へも返す。公開できなかった1枚は失敗として返し、比較の基準に残さない
- 保存の失敗: 行を作らず、判定器へ失敗を返す。3回続いたらヘッダーに `画面を記録できません: <理由>` を出し、次に1枚保存できたら消す。停止処理中の失敗はヘッダーへ出さない
- 撮れなくなったとき: 許可が無い・ディスプレイが見つからない・取得が止まった。ヘッダーに `画面を記録できません: <理由>` を出し、取得不能のイベントの行を残し、以後は撮らない。再接続しても自動では追わない
  - 選び直し: フッターで同じか別のディスプレイを選び直すと撮り直す。ヘッダーの1行は、次に撮影を始められた時点で消す。下の「録音中の切り替え」
  - 停止後: ヘッダーの1行は消す。撮れなかった期間はイベントの行として本文に残る
- 許可: TCCの「画面収録とシステムオーディオ録音」。許可の有無は `SCShareableContent` を取れるかで決める。取れなければ `CGRequestScreenCaptureAccess` で一度だけ確認を求め、一覧に出す
  - `CGPreflightScreenCaptureAccess` で決めない理由: 許可した直後の同じプロセスでは古い値を返す。試作で実測した
  - 許可の後に再起動は要らなかった。説明文 `NSScreenCaptureUsageDescription` は無くても撮れたが、Appleの案内に従い書く

## 録音中の切り替え

録音中と一時停止中は、フッターのピンの左で、どのディスプレイを記録しているかを確かめ、替え、記録を切り、入れ直せる。

- 実装: 判定と状態の遷移は `ScreenTarget`(`KikigakiCore/ScreenTarget.swift`)、入口は `MeetingSession.selectScreen`、撮影の差し替えは `ScreenRecorder.retarget`、表示は `ScreenTargetButton`
- 出す場面: 録音中と一時停止中で、画面を撮れる会議だけ。停止後・音声ファイルの書き起こし・replayでは出さない
- 引き継がない: 録音中に替えた対象はその会議にだけ効く。次の開始シートの初期値と設定ファイルは書き換えない。[録音開始シート](start-sheet.md)

### 表示

| 状態 | アイコンと名前 | 色 |
| --- | --- | --- |
| 記録中 | 画面のアイコンとディスプレイ名 | 墨 |
| 撮らない | 斜線の入った画面のアイコンと「撮らない」 | 薄墨 |
| 一時停止中 | 一時停止の前の対象 | 薄墨 |
| 撮れなくなった | 撮れなくなった対象 | 朱 |

- 名前の後ろに▼を置く。メニューを開いている間は押した背景を残す
- ツールチップと読み上げ: `画面の記録: EV3895`。一時停止中は `、一時停止中`、撮れなくなったら `、記録できません` を足す
- 切り替わる時点: 撮影を始められた時点。選んだ時点では替えない
  - 撮影を始められた時点: 画面収録の許可と、ディスプレイがつながっていることを確かめ、ストリームと「いま撮る」のフィルタを準備し終え、ストリームを動かす直前
  - 一時停止からの再開も、ストリームを準備し直して同じ時点で知らせる。それまでは開始待ちで、「いま撮る」を出さない。対象の世代は増やさず、一時停止の前の判定器の比較の基準を保つ
  - 例外: 「撮らない」は撮影をその場で止めるので、その場で替える
- 寸法と置き場: [書き起こしウィンドウ](transcript-window.md) の「画面の記録の操作」

### メニュー

- 「撮らない」、区切り、メニューを開いた時点でつながっているディスプレイ、区切り、「いま撮る」
  - 印: 最後に選んだ対象に1つだけ付ける。替える途中は、フッターの表示より先に印が移る
  - 「いま撮る」を出す条件は上の「撮影と保存」の「いま撮る」
- 画面収録の許可は、メニューを開いた時点では確かめない。ディスプレイを選んで撮り始める時点で確かめる
  - 許可が無いときは、開始シートで選んだときと同じ。一度だけ確認を求め、取得不能のイベントの行とヘッダーの1行を出す

### 切り替えの入口

選び直しは、開始シートの選択も含めて `selectScreen` の1本の入口を通る。どれも「いまの撮影を止めて、新しい対象で始め直す」。

- 録音中: その場で撮影を止め、新しい対象ですぐ始め直す
- 一時停止中: 選んだ対象を覚えるだけ。撮り始めるのは再開から。「撮らない」はその場で効く
- 撮っている対象と、開始を待っている対象を選び直したら何もしない
- 撮れなくなった対象を選び直したら撮り直す。別のディスプレイを選んでも撮り直す
- 続けて選んだら、最後に選んだものだけが効く。前の開始は世代が変わって開かずに戻る
  - 例: EV3895を撮っている間に内蔵を選び、始まる前にEV3895へ戻した。内蔵の開始は開かずに戻り、EV3895で始め直す。行は出さない。戻した開始を終えるまで「いま撮る」は出さない

### イベントの行

| 操作 | 行 |
| --- | --- |
| 撮っている対象を「撮らない」で切った | `記録を停止` |
| 切った後(「撮らない」・撮れなくなった)に撮影を始められた | `記録を再開` |
| 対象を替えただけ | 出さない |
| 撮らずに始めた会議で初めて撮り始めた | 出さない |
| 撮り始める途中で「撮らない」にした | 出さない。何も撮っていない |
| 撮れなくなった後に「撮らない」にした | 出さない。`記録できません` の行が切れ目を示している |

- `記録を停止` は、撮影を止めて保留を公開した後に足す。止める手前の最後の画面がその前に並ぶ
- `記録を再開` は、撮影を始められた時点で、ストリームを動かす前に足す。替えた先の最初の1枚より前に並ぶ
- 一時停止中に「撮らない」を選んでも `記録を停止` を残す。位置は一時停止の位置
- 受け入れた限界: 撮影を始められたと知らせた後にストリームの開始が失敗すると、`記録を再開` の直後に `記録できません` が並ぶ。許可とディスプレイは確かめ終えているので、まれ

### グローバルキー

どのアプリが前面でも、設定 `screenCaptureHotkey` のキー1つで記録を止め、入れ直す。資料を出す間だけ撮る、見せたくない画面を開く間だけ止める、をKIKIGAKIを前に出さずに行うため。設定の書式は [設定リファレンス](config.md) の共通のキー。

- 実装: 行き先は `ScreenHotkeyChoice`(`KikigakiCore/ScreenHotkey.swift`)、入口は `MeetingSession.toggleScreenCapture`。中身はフッターのメニューと同じ `selectScreen` を通す
- 止める: 撮っている間と、撮り始めるのを待つ間。一時停止中に選んである対象も含む。フッターで「撮らない」を選んだのと同じ
  - 撮れなくなった後に撮り直しを頼み、始められるのを待つ間も止める。フッターの表示は始められるまで撮れないままだが、続けて2回押せば撮らないに戻る
- 入れ直す: 「撮らない」の間と、撮れなくなった後。次の順で、最初につながっているディスプレイを選ぶ
  1. この会議で最後に撮影を始められたディスプレイ。番号と名前が同じもの、無ければ名前が同じもの
     - 番号だけ同じで名前が違うものは使わない。つなぎ直しで番号が別のディスプレイへ振られていることがある
  2. 開始シートで最後にディスプレイを選んで始めたときの名前。UserDefaultsキー `KikigakiScreenCaptureLastDisplay`。[録音開始シート](start-sheet.md)
     - `KikigakiScreenCaptureDisplay` は使わない。撮らずに始めた会議では、その開始で空文字に書き換わっている
  3. メインのディスプレイ
  4. つながっている最初のディスプレイ
- 一時停止中: フッターと同じく、入れ直しは再開から効き、止めるのはその場で効く
- イベントの行: フッターで選んだのと同じ。上の「イベントの行」
- 知らせ
  - 録音中: 音も通知も出さない。結果は撮っている画面の印の知らせで見える。下の「撮っている画面の印」
  - 一時停止中: 印を出さないので、通知で知らせる。表題は「KIKIGAKI · グローバルキー」
    - 入れ直す: 「再開するとEV3895の記録を始めます（⌃⌥⌘S）」
    - 止める: 「画面の記録を停止しました（⌃⌥⌘S）」
  - 切り替えられない: `Basso` と通知で断る。押して何も起きない、を作らない
    - 録音外: 「画面の記録を切り替えられませんでした。録音中・一時停止中だけ切り替えられます（⌃⌥⌘S）」。停止後と停止処理中も含む
    - 画面を撮らない会議: 「…この会議では画面を記録しません（⌃⌥⌘S）」。音声ファイルの書き起こしとreplay
    - つながっているディスプレイが無い: 「…つながっているディスプレイがありません（⌃⌥⌘S）」
- 登録・再読込・replayでの扱い・登録の失敗は、手動宛先へ送るキーと同じ。[AIへの定期自動送信](ai-scheduled.md) の「グローバルキー」
  - 再読込で2つのキーを入れ替えても登録できるよう、替わるキーを全部外してから登録し直す
  - 手動宛先へ送るキーと同じキーは設定エラー。2つ目の登録が必ず失敗するため

### 撮れなかった理由のヘッダー

- 次に撮影を始められた時点で消す。選び直しも、一時停止からの再開も当たる
- 「撮らない」を選んだら消す。自分で切った後に、撮れなかった理由を出し続けない。撮れなかった期間は行として本文に残る

### 世代と受付の番号

`ScreenRecorder` は録音できる会議ごとに1つで、対象だけを替える。受付の番号・受け付けた数・まだ届いていない数は会議の中で1本の列のまま。

- 替える前に受け付けた保存: 無効にせず、公開まで続ける。利用者が映していた画面なので捨てない。受付の番号の順に並び、替えた後に届いても替える前の位置に置く
  - 会議の切替では古い保存を拒む。会議の切替は記録ごと替えるので、番号の列が別になるため。切り替えは同じ列の中で境界を引くだけで、拒む理由が無い
- 対象の世代: `ScreenTarget` が振り、選び直して止めるか始め直すたびに増える。撮影の世代と別に持つ
  - いまの世代かの判定は `ScreenTarget.isCurrent` の1か所に置く。`ScreenRecorder` は世代を受け取って運び、知らせに添えて返すだけで、自分で新旧を決めない
  - 撮影の世代は一時停止・再開・停止・取得不能・切り替えで増え、古いストリームの通知と古い開始を捨てる。いまの形のまま
- 世代を効かせる時点: 世代は、予約した時点ではなく、効かせる時点で確かめる。届くまでの間に選び直しが挟まるため

| 効かせるもの | 確かめる時点 | 古い世代なら |
| --- | --- | --- |
| 撮影を始められた知らせ | MainActorで受け取った時点 | 表示も行も替えない |
| 撮れなくなった知らせ | MainActorで受け取った時点 | 取得不能にせず、行もヘッダーも出さない |
| 撮れなくなったストリームの片付け | 片付けを流す時点 | その世代で開いたストリームだけを閉じる。替えた先のストリームは閉じない |
| 「いま撮る」の撮影 | 撮影を始める時点。確かめてから撮影APIを呼ぶまでを中断の無い1区間で行う | 撮らずに失敗として終える。撮影APIを呼んだ後の画像は、いまの契約どおり公開する |
| 「いま撮る」を出す | メニューを組む時点 | いまの世代の開始を終え、その撮影に要るものが揃うまで出さない。一時停止からの再開も同じ |

- 例: EV3895の取得不能を判定した直後、MainActorへ届く前に内蔵を選んだ。届いた知らせはEV3895の世代なので取り合わない。内蔵は撮影中のまま、ストリームも閉じない
- 例: EV3895で「いま撮る」を受け付け、撮影が動く前に内蔵か「撮らない」を選んだ。撮影を始める時点で世代が違うので、EV3895を撮らない
- 判定器: 対象を替えたら作り直し、比較の基準を引き継がない。替えた先の最初の1枚は、録音の開始と同じく落ち着きを待たずに撮る
  - 理由: 替える前の画面と比べると、替えた先がたまたま似ていたときに撮らない。メニューバーの高さもディスプレイごとに違う
  - 替える前に決めた保存の結果は、新しい判定器では見つからず無視する
- 「いま撮る」の画像は、押した時点の対象の世代を持つ。替える前に押して替えた後に届いた1枚は、行としては公開し、替えた先の判定器の基準にはしない
- 「いま撮る」の撮影に要るもの: 受け付けた時点で、押した対象の世代とフィルタを要求に写す。以後は共有の状態を読まない
  - 撮影を始める時点: MainActorの中断の無い1区間で、対象の世代を確かめてから撮影APIを呼ぶ。切り替えもMainActorで行うので、確かめた後・呼ぶ前に切り替えが挟まらない
  - 一時停止だけなら対象の世代は変わらないので、ストリームを閉じた後でも要求が持つフィルタで撮って公開する。「押した時点で受付済み」「一時停止の前に受け付けた保存は後から届いても公開する」の契約のまま
  - 対象の変更と「撮らない」の後は撮らない。撮影APIを呼んだ後に替えた1枚は公開する
  - 記録を無効にした後も撮らない。停止の待ちの期限を超えたときと、会議の切替が当たる。期限内は撮れるまま保つ
    - 無効を世代より先に確かめる。対象の世代は会議ごとに振り直すので、古い記録の要求が次の会議で同じ番号になりうる
    - 無効の確定もMainActorで行い、確かめてから撮影APIを呼ぶまでの区間へ割り込ませない
- ストリームを閉じたら、共有の撮影に要るものも一緒に消す。受付済みの要求は自分の分を持っているので影響しない

### 切り替えをまたぐ保留

切り替えと「撮らない」は、一時停止と同じ境界で保留を公開する。撮影を止めた後に境界を引くので、境界より前に受け付けた保存は後から届いてもその場で公開する。

- 替える手前の最後の画面を残す。替えた先の無音の画面に置き換えられない
- 公開する契機の表は下の「保留と公開」

### 撮らずに始めた会議

- `.captures/` は最初の画像を保存するときに作る。撮らずに始めても途中から入れれば同じ置き場へ書く
- AIへ渡す `image_dirs` は会議Markdownの保存先から導くので、撮るかどうかで変わらない。[AIへの受け渡し](ai-handoff.md) の「画像の参照」
- 会議Markdown・途中保存・archiveは、画面の行をほかの会議と同じに扱う

## 撮っている画面の印

撮っているディスプレイの上に、撮っている間ずっと出すバッジと、切り替えた瞬間に出す知らせを置く。どのディスプレイを撮っているかを、そのディスプレイを見れば分かるようにする。

- 実装: いつ何を出すかは `ScreenIndicator`(`KikigakiCore/ScreenIndicator.swift`)、描画は `ScreenIndicatorOverlay`
- 理由: メニューバーにmacOSが出す画面の取得中の印は、どのディスプレイのメニューバーにも同じに出る。どのディスプレイを撮っているかは分からない
- 出す場面: 録音中と一時停止中で、画面を撮れる会議だけ。フッターの画面の操作と同じ。停止後・音声ファイルの書き起こし・replayでは出さない

### バッジ

- 置き場: 撮っているディスプレイの右下の隅から10pt。ディスプレイの枠の隅で、Dockや見える範囲で動かさない
- 形: 高さ20ptの朱の背景に、生成りの点と「記録中」。11ptの太字。背景は72%の濃さで少し透かす
- 出す間: 撮影を始められた時点から、撮るのをやめるか撮り直しを待ち始めるまで
  - 出さない: 「撮らない」・一時停止中・撮れなくなった後
  - 撮り直しを待つ間も出さない。対象を替えてから替えた先で撮り始めるまでと、一時停止から再開してストリームを準備し直している間。何も撮っていないため
    - フッターの表示は、この間も替える前の対象のまま。バッジだけ先に消す
- ディスプレイの配置や解像度が変わったら置き直す

### 知らせ

撮っているディスプレイの中央に、高さ64ptで出す。22ptの太字。

| 契機 | 形 | 出し方 |
| --- | --- | --- |
| 撮り始めた | 朱の背景に生成りの点と「画面を記録中」 | 1.2秒留めてから、0.35秒で右下のバッジの位置へ縮みながら移り、薄れてバッジに替わる |
| 撮るのをやめた | 墨の背景に、斜線の入った画面の絵と「画面の記録を停止」 | 1.2秒留めてから、0.3秒で消える |
| 撮れなくなった | 生成りの背景に朱の輪郭、朱の文字で画面の絵と「画面を記録できません」 | 2秒留めてから、0.3秒で消える |

- 撮り始めた: 会議の開始・「撮らない」からの入れ直し・一時停止からの再開・対象の替え・撮れなくなった後の選び直しのどれも、撮影を始められた時点で出す
  - 対象を替えたときは、替えた先に撮り始めた知らせだけを出す。替える前のバッジは替え始めた時点で黙って消す
  - 替える途中で元の対象へ戻したときも、撮り直した時点で撮り始めた知らせを出す
- 撮るのをやめた: 「撮らない」・一時停止・会議の停止で、バッジを出していたときだけ出す。バッジはその場で消す
  - 撮り直しを待つ間に「撮らない」・一時停止にしたときは出さない。再開の手前の一時停止で、止めた知らせが2度並ぶため
- 撮れなくなった: 撮っていたとき・撮り始める途中のどちらでも出す。撮れなくなった後に「撮らない」にしても何も出さない
  - 出す画面: 撮れなくなったディスプレイ。外れていて無ければ、書き起こしウィンドウのある画面。それも無ければメインの画面
  - 撮れなくなった対象をもう一度選び、また撮れなかったときは出し直さない。フッターとヘッダーが撮れないままを示している
  - 別の対象を選んで、そちらも撮れなかったときは出す
- 知らせの途中で次の契機が来たら、前の知らせを捨てて次を出す。撮り始めた知らせの途中で止めたら、バッジは出さない
  - 前の知らせが消える途中なら、その薄れを止めてから次を出す
  - 撮り始めた知らせの途中で撮り直しを待ち始めたら、その知らせを片付ける。止めた知らせ・撮れない知らせは残す
- 視差効果を減らす設定では、撮り始めた知らせを移さず、その場で消してバッジを出す

### ウィンドウ

- KIKIGAKIのパネルとして出す。撮影はKIKIGAKIを除くので、保存する画像には写らない
- クリックを素通りさせ、キーもフォーカスも取らない
- メニューバーと同じ層に置き、全画面のアプリの上と、どのデスクトップにも出す
- 画面共有の相手からは隠す設定にしている。効くかはmacOSと共有するアプリによる
- 知らせを出している間だけ、ディスプレイいっぱいの透明なパネルを置く。終わったら片付け、バッジの小さいパネルだけを残す
- 文字の倍率は掛けない

## 撮る契機の判定

`ScreenChangeDetector`(`KikigakiCore/ScreenChange.swift`)が、比べる相手を分けた2つの判定で保存を決める。動き続ける画面と、直近に公開した画面の規則を、この2つに重ねる。

- 落ち着き: 直前の観測フレームと比べて変わったマスの割合が `motion` を超えたら「動いている」。超えない状態が1.5秒続いたら「落ち着いた」
- 保存する価値: 落ち着いている間の最新フレームが、最後に保存した画像と `save` を超えて違えば保存する
- 動き続ける画面: 動いている状態が12秒続いたら、落ち着きを待たずに1枚保存し、動いたマスを比較から外す。下の「動き続ける画面」
- 直近に公開した画面: 保存しようとした画面が、最後に見てから12秒以内の公開した画面と同じなら保存しない。下の「直近に公開した画面」
- 試作との一致: 試作 `experiments/screen-capture` の判定器と同じ観測の列で同じ決定を出す。`ScreenChangeReplayTests` が合成の観測の列で固定する
  - 保存の失敗を3回に1回混ぜても、試作と同じ時刻に同じ理由で決め直す
  - 保存の結果を遅らせて返したときと一時停止を挟んだときは、試作との食い違いが小さいことを確かめる
  - 実画面の記録は、利用者の画面の縮小画像を含むのでリポジトリに置かない。手元で書き出して環境変数で渡すと同じテストで当てる。手順は [独立試作のREADME](../experiments/screen-capture/README.md) の「本体の判定器と突き合わせる」
- 比較の基準が無いときは、落ち着きを待たずに最新フレームを保存する。開始の直後、画像の寸法が変わった後(`reset`)、最初の保存の失敗後が当たる
- 一時停止からの再開(`restart`): 観測と動きは数え直し、比較の基準と結果待ちの決定は引き継ぐ。再開の直後の1枚は、基準と違えば落ち着きを待たずに保存する
- 保存した1枚は、話している間なら公開し、無音の間なら保留する。下の「無音の間の保留」
- 保存するのは観測したフレームの画像と時刻。保存を決めた時刻ではない
- 保存の結果: 呼び出し側が `saveSucceeded` / `saveFailed` で返す
  - 比較の基準は、結果を待っている決定と、保存に成功した画像のうち、受付の番号の新しい方。「いま撮る」の画像も同じ番号で並ぶ
  - 決めるのは、保存中でも使い終えてもいない最新の観測だけ。保存に成功した観測を、新しい観測が来るまでもう一度保存しない
  - 「いま撮る」の画像を基準に採ったら、押す前の観測は使い終える。後で保存すると、手動の画像より新しい受付の番号が付き、基準を古い画面へ戻すため。押した後の観測は残す
    - 観測の前後は、観測したときまでに受け付けた保存の数と、手動の画像の受付の番号で比べる
  - フレームの番号は観測を見分けるためだけに使い、新旧の比較には使わない。受付の番号は下の「受付の順と境界」
  - 失敗した決定は捨てる。複数の結果がどの順で返っても、書けなかった画像を基準に残さない
  - 失敗の後は5秒、次の保存を決めない。ディスク満杯などで判定のたびに書き直さないため。同じ画面のままなら5秒後に撮り直す
  - `reset` の前に決めた保存の結果は、後から返っても無視する

| 値 | 初期値 |
| --- | --- |
| 縮小画像の幅 | 128マス。高さは画面の縦横比から決める |
| マスの差 | 輝度8 |
| 動き | 変わったマス0.02% |
| 保存する価値 | 変わったマス0.1% |
| 落ち着く秒数 | 1.5秒 |
| メニューバー | 比較から外す |
| 動き続けて撮るまで | 動き始めてから12秒 |
| 外すマスを集める範囲 | 判定の時刻から直近10秒に1回でも変わったマス |
| 外すマスの広げ方 | 上下左右に1マス広げ、つながりごとに外接する長方形まで埋める |
| 外したマスを戻すまで | つながりごとに3秒変わらない |
| 直近に公開した画面の範囲 | 最後に見てから12秒 |
| 外すマスを直近の画面との比較で除く上限 | 比較に使うマスの50% |

- 値は判定器の定数として持つ。設定キーは無い
- 動きのしきい値は保存する価値のしきい値以下にする。逆にすると、動きに数えない小さなアニメーションで保存し続ける
- 1文字だけの修正は撮らない。拾える値ではカーソルの点滅や時計で余分が出続けた

### 動き続ける画面

動く画像や動画の入った画面は、落ち着かないので、上の2つの判定だけでは1枚も撮らない。

- 強制で保存する1枚: 動いている状態が12秒続いたら、その時点の最新フレームを保存する。保存の理由は `moving`
  - 動き始めた時刻: 落ち着いた状態から最初に動いた観測の時刻。強制で保存を試すたびに、その時刻へ進める。動き続ける間は12秒ごとに次を試す
  - 保存するのは、今の外すマスを除いて最後に保存した画像と `save` を超えて違い、直近に公開した画面と同じでないときだけ
  - 無音の間の1枚は、ほかの自動の保存と同じく保留する
  - 強制の1枚は、動いている所だけが違う画面でも撮る。保存を省いて外すマスだけを確定する形は試してやめた。経緯は [検証記録](records/screen-motion-alternation.md) の「保存を省く経路をやめた」
- 外すマス: 強制で保存した1枚の保存に成功したら、判定の時刻から直近10秒の観測で、直前の観測から1回でも変わったマスを集める。上下左右に1マス広げ、つながりごとに外接する長方形まで埋めて、比較から外す
  - 外すマスは、落ち着きの判定と保存する価値の判定の両方から外す。外したマスも割合の分母に残す
  - 前に外していたマスは引き継がず、強制で保存するたびに決め直す。引き継ぐと、送る前のスライドの動く画像の位置が、次のスライドでも外れ続ける
  - 確定は保存の成功で行う。失敗したら外さず、再試行の間隔5秒の後にすぐ試す
  - 外したマスを戻す時刻と、直近の画面の最後に見た時刻の起点は、保存を決めた時刻。成功が届いた時刻ではない
    - 決めてから成功が届くまでに、外す候補のつながりが変わったら、その変化の時刻を引き継ぐ。成功の直前まで動いていたつながりを、決めた時刻から3秒で戻さない
    - 理由: 保存の結果を遅らせて返す当て方で、試作の決定と食い違う数が少なかった。合成16本と実画面の記録1本の試作248枚で測った

    | 結果を返すまでの遅れ | 起点が成功の時刻 | 起点が決めた時刻 |
    | --- | --- | --- |
    | 0.25秒 | 10 | 0 |
    | 0.5秒 | 10 | 2 |
    | 1.0秒 | 14 | 6 |
    | 2.0秒 | 20 | 44 |

    - 符号化と書き込みは実画面の記録で0.1秒前後なので、遅れは0.25秒以下に収まる。2秒の遅れは想定しない
  - 外したマスが変わったら、そのつながりの最後に変わった時刻を進める。つながりごとに3秒変わらなければ比較へ戻す
- 10秒の理由: 強制で保存する時点の12秒前は、動き始めた時刻にあたる。送る前から画面が動いていると、12秒の範囲には送りで変わった本文まで入り、動く画像とつながって本文の全体が外れ続けた。10秒にすると、動き始めから2秒の間の変化は入らない
  - 動き始めた観測そのものは、12秒の範囲でも入らない。強制で保存するのは動き始めの12秒後より後の判定なので
  - 8秒・6秒は、外すマスが動く画像の全体を覆わない漏れと、描き込んだポインタで余分が増えた
- 一時停止からの再開(`restart`): 外すマスと動き始めた時刻は捨て、観測の世代を進める。一時停止の前に決めた強制の1枚が再開の後に成功しても、外すマスは確定しない
  - 理由: 再開の後の画面に、一時停止の前の動きで決めたマスを掛けないため
- 対象の切り替えと `reset`: 判定器を作り直すか、全部捨てる

### 直近に公開した画面

2つの画面を行き来するスライドや、少し前の画面へ戻る操作で、同じ画面を撮り直さない。

- 比べる相手: 最後に見てから12秒以内の、公開した画面。落ち着いて撮る1枚も、強制で保存する1枚も、これと同じなら保存しない
- 同じ画面: 今の外すマスを除いたマスの輝度の差が全て8以下。厳密な一致ではない
  - 外しているマスが比較に使うマスの50%を超えるときは除かず、全マスで比べる
  - 除く理由: 動く画像の入ったスライドで、別の所だけが入れ替わる画面を、動く画像の違いで別の画面とみなし、入れ替わるたびに撮った
  - 50%で絞る理由: 全画面の動画では外すマスが画面の全体になる。除くと比べるマスが無くなり、動画の各フレームが前の画面と同じとみなされ、動画の後にその画面へ戻っても撮らない
- 最後に見た時刻: その画面と同じ画面を観測している間は判定ごとに延ばす。12秒の範囲を出た画面は延ばさず、比べる相手から外す
  - 始める時刻: 自動の画像は保存を決めた時刻、「いま撮る」の画像は公開した時刻
  - 直近の画面へ入れるのは、どちらも保存の成功が届いた後
- 外すマスも、確定は保存の成功が届いた後。つながりの最後に変わった時刻は保存を決めた時刻から始め、決めてから成功までに観測したそのつながりの変化を引き継ぐ。成功までは外すマスを掛けない
  - 同じ画面かは、外すマスが観測の間にも戻るので、判定ごとに今の外すマスで求め直す
- 入れるもの: 保存に成功して、その場で公開したか保留へ入れた自動の画像と、「いま撮る」で公開した画像
  - 比べる相手にするのは公開した画像だけ。無音の間に保留した画像は、公開を受付の番号で知らせてから比べる
- その場の行き先: 保存の結果と一緒に、判定器へ1回で渡す
  - 公開した: 直近の画面として比べる
  - 保留へ入れた: 直近の画面に入れ、公開を知らせるまで比べない
  - 届いた時点で捨てた: 直近の画面に入れず、外すマスも確定しない。「いま撮る」より前に受け付けた無音の中の画面が当たる。比較の基準には受付の番号の順で入るので、基準は後に受け付けた手動の画像のまま
    - 保存の失敗とは分ける。失敗にすると、再試行の間隔だけ次の保存を決めない
  - 公開を拒んだ: 保存の失敗として返すので、入らない
- 後から知らせるのは、保留へ入れた画像の公開と破棄だけ。受付の番号で知らせる
  - 保留のまま捨てた画像は抜く。置き換え・「いま撮る」の境界での破棄が当たる。抜かないと、捨てた画面へ戻ったときに同じ画面とみなし、会議Markdownにも画像レーンにも1度も出ない
  - 知らせは保存の結果より後に判定器へ届く。結果は保留へ入れたMainActorの番で、知らせはその後の番で、同じ順序付きのキューへ流すため
- 比較の基準とは別に持つ。新旧は受付の番号で比べず、最後に見た時刻だけで範囲を決める。「受付の番号の新しい方が基準」の契約は変えない
- 一時停止からの再開: 比較の基準と同じく引き継ぐ。最後に見た時刻は一時停止の間も進むので、12秒より長い一時停止の後は比べない
- 対象の切り替えと `reset`: 判定器を作り直すか、全部捨てる
- 12秒の理由: 10秒おきの交互と、観測の間隔の最大1.4秒を足すと11.4秒

### 負荷

観測は1秒ごと、判定は0.25秒ごと。縮小画像は幅128で、高さは画面の縦横比から決まる。内蔵Retinaで約1万マス。

- 観測ごと: 直前の観測から変わったマスを数え、直近10秒分を持つ。外したマスのつながりの最後に変わった時刻を進める
- 判定ごと: 直近の画面の全部と、最新の観測を比べる。最大64件。最後に見てから12秒を超えた画面は、判定ごとに捨てる
  - 直近の画面は、保存した時刻ではなく最後に見た時刻で範囲に残す。直近12秒に1枚も保存していなくても、見続けて延ばした画面は残る
  - 保留中の画像も比べて、最後に見た時刻を延ばす。公開の状態を見るのは、保存を止めるかを決める所だけ
- 強制で保存を試すとき: 外すマスの候補を集め、つながりごとに外接する長方形まで埋める。保存に失敗した後の再試行で試し直すときも行う
- 保存に成功したとき: 候補のつながりに番号を振り、外すマスとして確定する

### 受け入れた限界

- 最後に見てから12秒以内に戻った画面は撮らない
- 輝度の差が8以下の変化だけの画面へ12秒以内に戻ると、撮らない
- ブラウザのタブ列の変化のように、意味の無い差で別の画面になると、余分を減らせない
- 動き続ける画面は12秒続くまで強制では撮らない。12秒より短く見せて送り、その間に落ち着かなければ残らない
- 外している間は、その中にだけ出た新しい中身を撮らない。動く画像の枠の中に出た注記が当たる
- 送った直後の動く画像のスライドで、入れ替わる図の一方しか撮らないことがある
  - 当たる場面: 動き始めから2秒より後に送った、または続けて何枚も送ってから着いた。送りで変わった本文が外す候補に入り、動く画像とつながって、動く画像が止まるまで本文の変化を比べない
- 全画面の動画は最初の1枚だけ撮る。動画の場面が替わっても撮らない
- 外すマスが動く画像の全体を覆わないと、覆わない所が変わったときに撮る。10秒の間に動く画像が枠の端まで動かなかったときに起きる
- 描き込んだポインタのように飛び飛びに動く小さなものは、外すマスがつながらず、12秒ごとに強制で1枚撮る
- 12秒より長い連続スクロールでは、途中の1枚が増える
- 動く画像のある画面を映したまま録音を始めたとき、または止まっていた動く画像が動き出したとき、動く所だけが違う1枚をもう1枚撮る
  - 当たる場面: 開始の1枚の後、動きが12秒続いて強制で1枚撮る。2つの画像は、動く画像の絵だけが違う
  - 理由: 強制の1枚は必ず撮る約束を保つ。動いている所を除けば同じだと言い切る条件は、足した中身を取りこぼす反例が続いた。余分の1枚より、取りこぼしを出さないことを優先する

### 無音の間の保留

誰も話していない間に撮った自動の画面は、録音中に公開せず保留し、話し始めに最後の1枚だけを公開する。話している間の画面は変化ごとに全部残す。

- 実装: 判定と保留は `VoiceActivity` と `ScreenSilenceHold`(`KikigakiCore/ScreenSilence.swift`)、公開の契機は `MeetingSession`
- 設計の経緯: 試用で会議の頭や黙って画面を探す間の画面が続けて残った。消すのではなく出さないことで、画像ファイル・会議Markdown・archive・AIへ送った画面のどれも後から消す場面を作らない

#### 声と無音

- 声のウィンドウ: 音量のトラックの0.1秒のウィンドウのうち、小音量の除外のしきい値以上のもの。欠測は声とみなさない
  - しきい値は除外のオン・オフによらず、その時点の値を使う。既定は −45 dBFS
  - 理由: 利用者が「声とみなす音量」を決める所を1つにする。2つ目の値を作らない
- 無音の中の画面: 観測した位置から過去3秒に、声のウィンドウが1つも無い画面。録音の頭では0秒より前を見ない
  - 3秒の理由: 2秒では発言の合間の息継ぎで切れやすく、5秒では黙ってスライドを2枚送る程度の間が無音にならない
- 音量で測る理由: 音量の計測は話者判別のオン・オフによらず常に動き、システム音声を混ぜた会議では混ぜた後の音を測る。話者判別より確定の遅れも無い
  - 受け入れた限界: 打鍵などを声と取り違えると、無音の中の画面を話している間の画面として残す。誤りは残しすぎる側に倒れ、画面を失わない

| 値 | 初期値 |
| --- | --- |
| 声とみなす音量 | 小音量の除外のしきい値。既定は −45 dBFS |
| 無音とみなす秒数 | 3秒 |
| 無音の間に残す画面 | 区間の最後の1枚 |

#### 保留と公開

- 自動の1枚は、書き込みを終えてからMainActorで受付の順に並べ、音量が観測した位置まで届いてから行き先を決める
  - 理由: 音量は消費のループで足すので、観測した位置より遅れて届く。届く前に無音と決めると、話し始めの直後の画面を保留してしまう
  - 届いている分にすでに声があれば、残りを待たずに公開する
- 話している間の画面: その場で公開する
- 無音の中の画面: 保留する。保留は1枚だけで、次の無音の中の画面が来たら古い方を画像ごと捨てる。捨てる画像は公開していないので、行も会議Markdownも指していない
- 公開は受付の順に行う。保留の古い1枚と話し始めの新しい1枚を入れ替えない
- 保留は、観測した位置と実時刻のまま公開する。行の位置はふだんの画面の行と同じ
- 保留へ入れた1枚を後から公開したか捨てたかは、受付の番号で判定器へ知らせる。判定器は公開した画面だけを直近の画面として比べる。上の「撮る契機の判定」の「直近に公開した画面」
- 保留を通さないもの: 「いま撮る」、イベントの行、話している間に撮った画面

#### 受付の順と境界

自動の保存は受け付けてから符号化と書き込みを終えて届くので、境界の操作の後に届くことがある。保留・公開・破棄は、届いた順ではなく受け付けた順で決める。

- 受付の番号: `ScreenRecorder` が保存を受け付けるときに、撮影中かと世代を確かめるのと同じロックの中で1つ取る。自動の保存も「いま撮る」も同じ列から取り、単調に増える
  - 新旧の物差しはこの番号1本にそろえる。保留の破棄と公開の境界、判定器の比較の基準の新旧、行の挿入位置のどれもこの番号で比べる
  - 自動の保存どうしでは、番号の順は観測の順と同じで、結果も同じ順にMainActorへ届く。「いま撮る」の完了は撮影の分だけ遅れる
  - 受け付けた数と、まだ届いていない数もこのロックで持つ。MainActor側は数を写さず、そのつど読む
- 境界は、その時点までに受け付けた保存の数で引く。番号がそれより小さい保存がまだ届いていなければ、境界の扱いを届いたときに当てる
  - 公開の境界(下の表の契機): 境界より前に受け付けた保存は、届いたらその場で公開する。保留しない
  - 「いま撮る」の境界: その受付の番号より小さい自動の保存は、無音の中の画面と決まったら保留せずに捨てる。話している間の画面なら公開する
- 一時停止・取得不能・切り替え・「撮らない」は、撮影を止めてから境界を引く。止めた後は新しい受付が無いので、境界より前の受付を数え終えている
- 行の並びも受付の番号で決める。声以外の行ごとに、録音中のメモリにだけ番号を持つ。会議Markdownと行の型には足さない
  - 画面の行: その画面の受付の番号
  - 手入力とイベントの行: 足したときまでに受け付けた保存の数
  - 遅れて届いた画面は、自分の番号より大きい最初の行の前へ置く。後に受け付けた画面と、受け付けた後に足した手入力・イベントの行より前になる。境界で公開した画面もこの番号で並ぶ
  - 例: 「いま撮る」のMを受け付け、次に自動のAを受け付けた。一時停止でAを公開し、手入力を足した後にMが届いた。行は「M → A → 手入力」
  - 理由: 併合は同じ音声位置の声以外の行を届いた順に並べる。録音の開始直後のように画面と取得不能のイベントがともに0秒だと、後から届いた画面がイベントの後ろに回る
  - イベントの行は取得不能・停止・再開。どれも撮影を止めた後か、始め直したストリームを動かす前に足すので、その時点の受け付けた数で受付の順に並ぶ。一時停止は行を持たず、時刻の対応で表すので、この食い違いは起きない
- 境界が重なったとき: 境界は当てた順に効く。例: 無音の中の自動の画面を受け付け、すぐ「いま撮る」を押し、どちらも届く前に一時停止した。自動の画面は先に届き、一時停止の境界で公開する。押した順に、自動・手動の順で並ぶ
- 話し始め: まだ届いていない自動の保存があるうちは、保留を公開しない。届いた画面が無音の中なら、そちらが無音の区間の最後の1枚になる
  - 保存の失敗も届いた結果に数える。失敗で待ちが解ける
  - 受け入れた限界: 話し始めの時点で落ち着き待ちの途中だった画面は、待ちに含めない。保存が決まると、保留の1枚と合わせて同じ無音の区間から2枚を公開する
    - 理由: 落ち着き待ちの候補まで話し始めの待ちに含めると、状態が増える。話し始めの時点でまだ落ち着いていなかった画面は、話している間の画面として扱う
    - 誤る向きは残しすぎる側で、画面を失わない
- 例: 無音の中の画面Aの保存を受け付けた直後に一時停止した。操作の時点では保留は空。Aは一時停止の後に届くが、境界より前の受付なのでその場で公開する。再開後の無音の中の画面Bに置き換えられない

保留を公開する契機。どれも、その時点で保留していた1枚と、音量を待っている画面を受付の順に全部公開する。まだ届いていない分は、上の公開の境界の扱いで届いたときに公開する。

| 契機 | 理由 |
| --- | --- |
| 話し始め: 保留の後に声のウィンドウが届いた | 話し始めの直前の画面を、話の中身と結びつける |
| 手動送信・「返答する」などAIへの送信の準備 | 値を取る前に公開し、AIに今の画面を渡す |
| 「会話をコピー」 | 同上 |
| 定期自動送信で、ほかの変更により送ると決まった後の送信の準備 | 同上。保留だけでは送らない |
| 一時停止で撮影を止めた直後、取得不能のイベントの行の直前 | 空白の手前の最後の画面を残す |
| 録音中の切り替えと「撮らない」で撮影を止めた直後 | 同上。替える前・切る前の最後の画面を残す |
| 停止の待ちの後、最終保存の前 | 最終保存と停止時の最後の1回に入れる |

- 音量を待っている画面も公開する理由: 無音かもしれないが、AIへ今の画面を渡すことと、話している間の画面を落とさないことを優先する
- 公開は同期で終わる: 符号化と書き込みを保留の前に済ませるので、送信の操作は公開を待たずに値を取れる。停止の3秒の待ちも使わない
  - 引き換え: 置き換えで捨てる画面も符号化して書く。保留の間は、公開していない画像が `<会議名>.captures/` に1〜数枚ある
- 定期自動送信: 判定は保留を公開せずに行う。保留中の画面は行に無いので「変更あり」にならず、黙って画面だけを替え続けても期限で送らない
  - 声や手入力などほかの変更で送ると決まったら、値を固定する前に保留を公開し、今の画面を一緒に渡す
  - 停止時の最後の1回: 停止で保留は公開され、会議Markdownの行になる。最後の1回は保存した会話の差分で決めるので、公開した画面の行だけが変更でも送る
- 会議の切替と無効化: 保留は会議ごとのメモリだけの値。録音の開始と片付けで、公開していない画像ごと必ず捨て、境界も忘れる。受付の番号は記録ごとに0から数え直すため。古い記録の保存は公開の確認で弾かれ、保留にも入らない
- 画像を消せなかったとき: パスを持ち続けてログに出し、録音の開始・停止・片付けで消し直す。無い画像は消えたものとみなす。公開した画像は消さない
  - 対象: 置き換えと「いま撮る」で捨てた保留、会議の切替で捨てた保留、公開を拒んだ画像。公開を拒むのは、停止の期限を超えた保存と、会議の切替の後に届いた古い保存
  - パスは絶対パスで持つので、会議が替わっても古い会議の保存先の画像を消し直せる
  - 受け入れた限界: クラッシュしたときは、公開しなかった画像が `<会議名>.captures/` に残りうる
- 一時停止: 撮影を止めた直後に公開し、判定器は比較の基準を引き継ぐ。再開の直後の1枚はふだんの規則で扱う
- 音声ファイルの書き起こしとreplayは画面を撮らないので、保留も無い
