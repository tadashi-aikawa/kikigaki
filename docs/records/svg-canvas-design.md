# SVGキャンバスの要件と全体設計

2026-11-15時点の、設計時の決定と検証の記録。現行の仕様ではない。実装した振る舞いは、実装と同じコミットで `docs/` 直下の文書へ書く。

## 目的

議事録の図を、MermaidではなくSVGで描いていく。そのために次の2つを足す。

- SVGの表現力を出す。いまは無害化して画像にするため、外部の画像・色の指定・文の折り返し・リンクが落ちる。経緯は [議事録の描画と検索](../minutes-rendering.md) の「SVGの図」
- 声だけでは伝えにくい操作を、手で補えるようにする

## 要件

### 人の操作の範囲

KIKIGAKIは話している前提のアプリで、図の中身は声でAIに頼める。人の手に持たせるのは、声が苦手なことだけにする。

| 操作 | 扱い | 理由 |
| --- | --- | --- |
| 見る | 作る | 拡大縮小と移動は、AIに頼む類のものではない |
| 指す | 作る | 「これ」「その右の」が声では伝わらない。付箋をクリックで選び、次の依頼でAIへ伝える |
| 動かす | 保留 | 指して話せば、領域をまたぐ移動は声で済む。プレビューが議事録を書き換える初めての機能になるため、「見る」「指す」を使ってから決める |
| 書く | 作らない | 文の書き換え・付箋の追加と削除・色・線は、声か手入力でAIに頼む |

- 書く機能を作らない理由
    - 手で描くなら専用のツールに及ばない。KIKIGAKIの価値は、話すだけで図ができること
    - 編集の入り口を増やすほど、AIと人が同じ図を書き換える衝突が増える
    - AIは自由な形のSVGを書く。人の編集画面は付箋の形を固定するしかなく、AIの表現を縛る

### 決めたこと

タダシが質問票で決めた。

- キャンバスの置き場: 本文の中に置き、「広げる」でペイン全体をその図にする
- 指せるもの: AIが印を付けたものだけ。枠・見出し・背景は選ばない
- AIへ伝える時点: 送る瞬間に指しているものだけ
    - 受け入れた限界: 1回の送信に2つの「これ」を混ぜると、後の1つしか伝わらない
- 更新の見せ方: 変わった付箋だけを光らせる
- AIの並べ直し: AIの判断で、前からある付箋を動かしてよい
- ボードタブ: 今回は触らない

### 範囲外

- ボードタブの図。Mermaidのまま
- 付箋のドラッグと、議事録への書き戻し
- 図の文字の検索。いまも画像なので検索に出ない
- 図の中の、CSSの `url()` で指す画像と、`use` などで指す外のファイル。出る画像は `<image>` と `<img>` のものだけ
- SVGに書かれたscript
- `![](図.svg)` ・ `![[図.svg]]` で参照したSVGファイル。従来どおり画像で描き、拡大モーダルも従来どおり
- マウスを重ねたときのCSSの反応。理由は「見る」
- キーボードだけで付箋を選ぶ操作

## 実際のWebKitで確かめたこと

使い捨てのWKWebViewで、本番と同じCSPのページから確かめた。ハーネスは残していない。ここに無い挙動は確かめていない。

- `sandbox="allow-scripts"` を付けた `srcdoc` のiframeは、本体CSPの `frame-src 'none'` のままで描ける
- `srcdoc` のiframeは本体のCSPを継ぐ。iframeの中のmetaで緩めても効かない
    - 通ったもの
        - HTTPSとdata URIの画像
        - `<style>` の色
        - foreignObjectの折り返し
        - `minutes-app:` から読むスクリプト
        - 親へのpostMessage
    - 止まったもの
        - SVGの中のinlineの `<script>` とイベント属性
        - `fetch`
        - 親のDOMとlocalStorage
        - 親の遷移
        - iframe自身のHTTPSへの遷移。止めたのは本体CSPの `frame-src`
        - `minutes-app:` の画像
- `minutes-app:` のページをiframeの `src` にする形は、本体CSPの `frame-src` を緩めれば描け、独自のCSPを持てる
    - 使いどころ: 将来SVGの中のscriptを許すなら、こちらへ切り替える。今回は使わない
- iframeに `pointer-events:none` を付け、親の要素へ `transform` を掛けて3倍に拡大しても、文字と線は鮮明なまま
- 親が受けたクリックの座標をiframeへ渡すと、iframeの中の `elementFromPoint` でその場所の付箋を引ける
- `pageZoom` はiframeの中にも掛かる
- iframeを別の親要素へ移すと読み込み直す。読み込み直さずに移す `moveBefore` は、このWebKitに無い
- iframeの中から、`minutes-image:` のローカル画像を読める
- 子のCSPをnonceで狭めると、nonceの無いスクリプトは、同梱の資産を指していても読まれない
- 2026-11-14のふりかえりMTGの議事録にある12枠のサンプルは、全部描けた

## 全体設計

### 構成

| 置き場 | 持つもの |
| --- | --- |
| 親ページ `web/minutes/preview.js` ほか | SVGを拾う、無害化、iframeを作る、拡大縮小と移動、選択の保持、アプリへの報告 |
| iframeの中 `canvas.js` | 描画、座標から要素を引く、選択の枠と更新の強調を描く |
| アプリ `MinutesWebView` ほか | サブフレームの遷移の許可、選択の保持、送信と追記への添付 |
| Core `AIEnvelope` ・ `AIAppendix` | `canvas_selection` の形式検証と保存 |
| 配布Skill | 図の書き方の規則、選択の読み方 |

iframeはイベントを受けない。操作は全部、親の要素が受ける。

- 理由: 既存の `DiagramInteractions` のピンチ・ドラッグ・スクロールをそのまま使える。iframeの中へのジェスチャーの配送を新しく確かめなくてよい

### 図と付箋の名前

指す・AIへ伝える・更新の強調は、名前で図と付箋を突き合わせる。

- 図の名前: ルートの `<svg>` の `id`
    - 議事録の中で重ならないこと。重なる名前の図と、名前の無い図は、指せない
    - 理由: 図の順番で突き合わせると、図を足したり並べ替えたりしたときに、別の図の同じ名前の付箋へ選択が移る
    - 重なりの判定には、ボードの節の図も含める
        - 理由: 議事録タブへ渡る本文はボードの節を除いたもの。AIは元のファイルの全体から図を探すので、ボードの節に同じ名前があると候補が2つになる
        - 方法: ボードを使う会議では、アプリがボードの節の原文も議事録タブへ渡す。ページは本文と同じ拾い方でそこの図の名前を集める。描きはしない
        - ボードの節だけが変わったときも渡す。議事録の本文は描き直さず、ページが指せる図を判定し直す。名前が重なった図の選択は外して、アプリへ知らせる
- 付箋の名前: `id` と `data-kind` の両方を持つ要素の `id`
    - 図の中で重ならないこと。重なる名前の要素は指せない
    - 入れ子なら内側を採る
- 長さ: 図と付箋の `id` はUTF-8で1〜64バイト、`data-kind` は1〜32バイト。空白と制御文字を含まない。外れる要素は指せない
    - 長さの単位はどれもUTF-8のバイト数に揃える。ページとアプリで数え方が食い違わない
- 名前の無い図も、描く・見る・更新の強調は効く。拡大縮小の状態は、従来どおり見出しのIDと節の中の順番で引き継ぐ

### 描く

- 対象: 議事録タブの、`svg` のコードフェンスと閉じたSVGブロック。拾い方は変えない
    - ボードタブで描く文書は、従来の画像のまま。ボードを移すかを決めるときに揃える
- 無害化: 親でDOMPurifyに通す。外すのはscript・イベント属性・埋め込みとフォームの要素・`meta` ・ `link` ・ `base`
    - 残すもの: `style` 要素と属性、`foreignObject` とその中の文書要素、`image`、`use`、`a`、アニメーションの要素、`id` と `data-*`
- 無害化したDOMから、親が図の寸法、指せる要素の一覧、リンクの一覧を読む
    - 理由: iframeの読み込みを待たずに、寸法と一覧が揃う
- 寸法: 表示する大きさと、SVGの中の座標は別に扱う
    - 表示する大きさの決め方。上から順に採る
        - `width` と `height` の両方が、単位なしかpxの正の数
        - 片方だけが有効で、`viewBox` がある。もう片方を `viewBox` の比で補う
        - `viewBox` の幅と高さ
        - 300×150
    - 割合・0以下・数でない値は、無いものとして扱う
    - 理由: `width="200"` と `viewBox="0 0 1000 500"` の図は、従来どおり幅200で出す
- 最初の大きさ: 従来の画像と同じ。表示する幅がペイン幅を超える図は幅へ収め、小さい図は引き伸ばさない
- iframe: `sandbox="allow-scripts"`、`srcdoc` に子のCSPのmeta、無害化したSVG、`canvas.js` の読み込みだけを入れる
- 画像: 図の中の `<image>` と、foreignObjectの中の `<img>` を出す
    - HTTP・HTTPS・data URIは、書かれたとおりに読む
    - ローカルのパスは、親が無害化のときに、本文の画像と同じ `minutes-image:` のURLへ書き換える
        - 書ける形: 議事録からの相対パス、絶対パス、`~/` 始まり。本文の画像と同じ
        - 例: 議事録が参照する画像、画面の記録の画像
        - 読み込みの制限も本文の画像と同じ仕組みを通る。1枚24MiBまで、1回の描画の合計96MiBまで
    - 書き換える属性: `image` の `href` と、`img` の `src` 。入れ子のSVGとforeignObjectの中も全部たどる
        - `image` に `href` と `xlink:href` の両方があれば `href` を採る。`xlink:href` は外し、`href` 1つへ揃える
        - `img` の `srcset` は外す。本文のHTMLと同じ
    - 読めなかった画像: `canvas.js` が画像ごとの成否を見て、図の世代を付けて親へ知らせる
        - 親は図の下に、読めなかった画像の件数を「画像を表示できません」と出す。図の中は変えない
        - 次の描き直しで読み直す
- 外のファイルを指せる場所は、`image` ・ `img` ・ `a` だけにする
    - ほかの要素の `href` は、`#` で始まる同じ図の中の参照だけを残す。`use` ・フィルタの画像・`textPath` が当たる
    - CSSと表示の属性の `url()` も、`#` で始まるものだけを残す。`<style>` ・ `style` 属性・`fill` や `filter` の属性が当たる
        - CSSはCSSOMで読んでから確かめる。エスケープした書き方で抜けられない。本文のHTMLと同じやり方
        - `@import` と `@font-face` は外す
        - URLを組み立てられる書き方も外す。`image-set()` 、カスタムプロパティの宣言、`var()`
            - 例: 変数に文字列でURLを入れ、`image-set()` へ渡すと、`url()` を書かずに画像を読める
    - 理由: 図が自分で書いた `minutes-image:` のURLと、CSSからの外への通信を減らす。グラデーション・模様・影・矢印の先は同じ図の中の参照なので残る
    - 限界: CSSの検査は、分かっている書き方を外す形。漏れたときに読めるのはHTTPとHTTPSの画像で、`image` で許している通信と同じ種類。ローカルのファイルは、アプリのhostの照合が止める
- 書体: 指定の無い文字は本文と同じゴシックになる。従来は明朝だった
- リンク: 親が無害化のときに図の中の `<a>` へ番号を振り、番号とリンク先の対応を親が持つ
    - クリックで `canvas.js` が返すのは番号だけ。親は自分の対応からリンク先を引き、従来のリンクの判定へ渡す
    - `#見出し` は本文の中の移動、ほかはHTTP・HTTPS・mailtoだけを開く
- 図をクリックしたときの拡大モーダルは無くなる。「広げる」が置き換える

### 見る

Mermaidの図と同じ作法にする。詳細は [議事録の描画と検索](../minutes-rendering.md) の「Mermaid図の選択と拡大縮小」。

- 図をクリックで選ぶ。選んだ図でピンチ・ドラッグ・2本指スクロールが効く
- 操作列: 「− 倍率 + 全体 戻す」に「広げる」を足す
- 「広げる」: ペイン全体をその図にする。広げた瞬間に全体を収める
    - 戻り方: 「たたむ」かEsc。広げる前の倍率と位置へ戻る
    - 名前: 既存の「戻す」は等倍・初期位置へ戻す操作なので、別の名前にする
- Esc: 1回につき1つ戻る。指した付箋の解除、たたむ、図の選択の解除の順
- マウスを重ねたときのCSSの反応は出ない
    - 理由: iframeがイベントを受けないため。アニメーションは動く
- `DiagramInteractions` は、図の中身がSVG要素でもiframeでも寸法を引ける形へ広げて使う。ミニマップとノードのフォーカスはボードだけのまま
- 文字の倍率は図にも掛かる。座標の変換と配置は100%と200%で確かめる

### 指す

- 操作: 選んだ図の中で、ドラッグではないクリックを使う
    - 付箋の上: その付箋だけを選ぶ
    - ⌘を押しながら: 付け外しする。20件まで選べ、21件目は足さない
    - リンクの上: リンクを開く。選択は変えない
    - どちらでもない場所: 選択を外す
    - まだ選んでいない図の最初のクリックは、図を選ぶだけ
- 流れ: 親がクリックの座標をiframeの座標へ直して送り、`canvas.js` がその場所の結果を返す
    - 結果は3種類。付箋の `id`、リンクの番号、何も無い
- 範囲: 選択は1つの図の中だけ。別の図を指すと、前の図の選択は外れる
- 保持: 図の名前と付箋の名前の組で持つ
    - 描き直しで同じ名前が残っていれば選んだまま。AIが付箋の場所を変えても外れない
    - 名前が消えた付箋は選択から外す
    - 別の議事録・別の会議への切替で捨てる
- 選択の枠は `canvas.js` が図の中に描く。回転した付箋にも沿う
    - 形と色は、実装のときに実物を並べてタダシに選んでもらう

### 図の世代

表示している図と、その一覧と、選択は、同じ原文から作った1組として扱う。

- 原文が変わった図は、新しいiframeの準備ができた瞬間に、iframe・一覧・選択を組ごと入れ替える
    - 入れ替えまでのクリックは、表示している側の一覧で解く。見えている付箋と違う文を送らない
- 親とiframeのメッセージには、図の世代の番号と操作の番号を付ける。合わない返答は捨てる
    - 例: クリックの返答が、図の入れ替えや選択の解除より後に届いた
- 組を入れ替えたら、選択を新しい一覧で引き直してアプリへ知らせ直す
    - 理由: 同じ名前のまま文・種類・領域が変わったとき、アプリの持つ値を古いままにしない
- 原文が変わらず使い回した図でも、描き直しが済んだら選択をアプリへ知らせ直す
- 選択の知らせは、描画のticketではなく、表示対象の世代で照合する
    - 表示対象の世代が進む場面: 表示対象か会議が替わる、本文を隠す。同じ議事録の描き直しでは進まない
        - 本文を隠す場面: 議事録の読み込み失敗、対象の解除、WebContentプロセスの終了
    - 理由: 描画のticketは描き直しを頼んだ時点で進む。その間も前の図は操作できるので、ticketで照合すると、画面で外した選択がアプリに残る
    - 描き直しの準備中は、表示している図の操作をそのまま受ける
- 世代が進んだら、アプリは持っている選択を空にする。古い世代の知らせは捨てるので、遅れて届いた知らせで選択が戻らない
    - 本文をもう一度描けたら、ページが新しい世代で選択を知らせ直す
- 1つの図のiframeの読み込みに失敗したら、その図の選択を外して知らせる

### AIへ伝える

- 親は選択が変わるたび、または組を入れ替えるたびにアプリへ知らせる。付箋の種類・領域・文は、親の一覧から引く
    - iframeから受け取るのは `id` だけ。一覧に無い `id` は捨てる
- アプリは議事録タブの今の選択を1つ持ち、送信操作を受け付けた時点で採る。採る位置は `captured_at` と同じ、最初のawaitより前
    - 手動・自動・声の合図・確認への返答で同じ。再送は固定済みのrequestを使う
    - 添える条件: 議事録ペインが開いていて、議事録タブが前に出ている。選択が空でない
        - 理由: 見えていない選択を黙って送らない
    - 送ったあとも選択は残す。同じ付箋について続けて頼める
- envelopeの `participant` に、省略できるキー `canvas_selection` を足す

```json
"canvas_selection": {
  "minutes_path": "/Users/example/Documents/notes/ふりかえり.md",
  "figure": "kpt",
  "heading": "KPT",
  "elements": [
    { "id": "k2", "kind": "note", "area": "keep", "text": "午後はだいたい5並列 17時以降は7並列" }
  ]
}
```

- `minutes_path`: 図がある議事録。プレビューの表示対象で、書き先の `minutes_path` と違うことがある
    - 検証は既存の議事録パスの規則をそのまま使う
- `figure`: 図の名前。AIは元のファイルで `<svg id="kpt"` を探せる
    - 理由: 表示側にはボードの節を除いた本文が渡り、描けた図だけを数えるので、通し番号は元のファイルの順番と合わない
- `heading`: 図のすぐ上の見出し。補助の情報で、無ければ省く。600バイトまでで、採る側で文字の境目で切り詰める
- `elements`: 1〜20件。`id` と `kind` は「図と付箋の名前」の長さ。`area` は32バイト、`text` は600バイトまで
    - `area` は省ける。32バイトを超える `data-area` は省く
    - `text` は空白を1つに畳み、採る側で文字の境目で切り詰める
    - 選べるものは必ず検証を通る。画面で選べたのに送信で拒否される組み合わせを作らない
- 検証: 欠損は未指定として読む。明示nullと、形の合わない値は拒否する
    - 注意: 保存済みのstateは全requestを検証して読む。規則を後から強めると過去の会議を読めなくなる。緩めるのは構わない。境界の値のテストを置く
- 会話ファイルと「会話をコピー」には載せない

作業中の依頼への追記にも添える。契約は [AI参加者の設計](../ai-participant.md) の「作業中の依頼への追記」。

- 追記の保存値に、受け付けた時点の選択を足す。欠損した旧い追記は未指定として読む
- 追記を送るときは、元の依頼の選択ではなく、その追記の選択を渡す
- 返事に番号が無かった追記を新しい依頼へまとめて送り直すときは、選択が同じ連続した追記だけを1つにまとめる。選択が変わるところで依頼を分ける
    - 理由: 別々に送った「これ」を、アプリの都合で1つの依頼へ混ぜない

### 更新の強調

- 比べる単位: 指せる要素。図の名前・付箋の名前・文字で突き合わせる。名前の無い図は、見出しのIDと節の中の順番で図を引く
- 光らせるもの: 新しく現れた付箋と、文字が変わった付箋
- 光らせないもの: 位置・色・大きさだけが変わった付箋、消えた付箋
    - 理由: AIは並べ直してよいので、位置で光らせると更新のたびに全部が光る。並べ替えと削除だけでは光らせないのは、本文と同じ
- 比べる基準の側にも今の側にも指せる要素が無い図だけ、原文が変わったら図の枠を光らせる。従来の画像と同じ
    - どちらかに指せる要素がある図は、付箋ごとの差が無ければ何も光らせない
    - 例: 最後の1枚の付箋を消した図は光らせない
- 基準と寿命は本文と同じ。既存の `UpdateHighlighter` に乗せる
    - 比べる項目は本文の置き場に結び付け、目次の印を本文と同じ規則で付ける
    - 強調を消すときは、親からiframeへも伝える
- 描くのは `canvas.js` 。親が `id` を渡し、付箋の外形に本文と同じ淡い紫を重ねる

### 描き直し

本文は描き直すたびに全部のDOMを差し替える。iframeは親要素を移すと読み込み直すので、そのままではAIが議事録を更新するたびに全部の図が読み込み直される。

- 要件: 原文が変わっていない図を、描き直しで消さない
- 決め方: 最初のステップの冒頭で、次の2つを同じ条件で測って選ぶ。測り方は既存の図の更新の計測と同じで、図が無い状態が画面に現れる回数を数える
    - 単純な形: 描き直しのたびに読み込み直す。図が無い状態が現れなければ、こちらを採る
    - 層に置く形: 図の枠を本文のDOMの外の層に置く。本文には同じ寸法の置き場だけを置き、層の図を置き場の位置へ重ねる
        - 原文が同じ図はそのまま使う。原文が変わった図は、新しいiframeの準備ができるまで前の図を残す
        - ローカル画像を含む図は、原文が同じでも使い回さず、描き直しのたびに作り直す。準備ができるまで前の図を残す
            - 理由: ローカル画像のURLは描画のたびに変わり、前の描画への要求は取り消される
            - 理由: 同じパスでも、ファイルの中身が変わっていることがある。本文の画像は描き直しのたびに読み直している
        - 読めなかった画像のある図も、使い回さずに作り直す。待つ上限を超えた画像も読めなかったものに数える
            - 理由: 外部の画像が一時的に読めなかっただけなら、次の描き直しで出る
        - 準備ができたとは、図の中の全部の画像の成否が出たこと。待つ時間に上限を置く
    - 測る図には、ローカル画像を含む図を入れる
- 層に置く形を採るときに、試作で確かめること
    - 層の座標の取り方
    - 置き場の位置が変わる契機を全部拾えること。描画、ペイン幅、見出しの折りたたみ、文字倍率、図より前の画像の遅れた読み込みと読み込み失敗、`details` の開閉
    - 置き場が隠れている・祖先に切り取られている間の、層の図の隠し方
    - 目次・検索・画像のモーダルとの重なり順
    - 本文の要素に付けている、ペインへフォーカスを知らせる処理のつなぎ直し
- 見送った形: 変わらない祖先ごとDOMを残す差分更新。本文の全部を差し替える今の流れを変えることになる

### AIとの約束

配布Skillの `references/meeting.md` へ書く。

- 指せる図は、ルートを `<svg id="…">` の形にする。`id` は議事録の中で重ならない
- 指せるまとまりは `<g id="…" data-kind="note" data-area="…">` の形にする
    - `id` は図の中で重ならない。文や位置を変えても同じ `id` を保つ。消した付箋の `id` を別の付箋へ使い回さない
    - `data-area` は省ける
- 並べ直しはAIの判断でしてよい
- `canvas_selection` があるとき、依頼の「これ」「この付箋」はその要素を指す。指す言葉の無い依頼では使わない
- 指した付箋を直す依頼では、`canvas_selection` の `minutes_path` のファイルを直す。ほかの議事録の更新は、従来どおり `participant.minutes_path` に従う
    - 理由: 別のAIの通知で表示対象だけが替わると、指している図のファイルと書き先が食い違う。利用者が指しているのは、見えている図
    - 作業許可とボードの節の保護は、従来の規則のまま
    - `canvas_selection` のファイルを直したときは、`minutes` の通知を省く
        - 理由: そのファイルは送った時点の表示対象で、プレビューはファイルの変化を見て描き直す
        - 理由: 通知は1つのrequestにつき1つのパスまで。別のパスを通知済みのrequestへ、図を指した追記が届いても競合しない
- 図の中の画像は `<image href>` で書く。HTTPSのURLか、議事録からの相対パスか、絶対パス。scriptは動かない
- 付箋の文をforeignObjectで折り返す書き方は、描けるが、標準にはまだしない
    - 理由: Obsidianなど他のアプリでの見え方を確かめていない

### 実行境界

変わる前提は、SVGを画像ではなく文書として描くこと。プレビューが議事録を書き換えないことは変わらない。

止めるものごとに、どの守りが受け持つかを分ける。1つの守りに複数の役目を期待しない。

| 止めるもの | 受け持つ守り |
| --- | --- |
| inlineの `<script>` とイベント属性 | 無害化。継いだCSP |
| SVGが書いた、同梱の資産を指す `<script src>` | 無害化。子のCSP |
| 外への通信 | 継いだCSPの `connect-src` |
| 親のDOMと保存領域 | sandbox |
| 親の遷移、ポップアップ、フォーム送信 | sandbox。アプリの遷移の判定 |
| iframe自身の遷移 | 無害化。継いだCSPの `frame-src` 。アプリの遷移の判定 |
| 入れ子のiframe | 無害化 |

- 子のCSP: `srcdoc` の先頭のmetaで、動かせるスクリプトを、親が付けたnonceを持つ要素だけに狭める
    - nonceは図を描くたびに親が作る乱数。`canvas.js` を読む要素にだけ付ける
    - 理由: 継いだCSPの `script-src minutes-app:` は、SVGが書いたscriptと同梱のコードを区別しない。URLで狭めても、SVGが書いた `canvas.js` を指す要素は区別できない
    - nonceの無いスクリプトが読まれないことは確かめた
    - `canvas.js` は2回読まれても壊れない作りにする。親は操作の番号で、重なった返答を捨てる
- sandboxは `allow-scripts` だけ。付けるのは同梱の `canvas.js` を動かすため
    - sandboxはiframe自身の遷移を止めない。遷移は上の表の3つが受け持つ
- 入れ子の `srcdoc` は、`frame-src` では止まらない前提で扱う。無害化で `iframe` を外す
- アプリの遷移の判定: サブフレームは `about:srcdoc` だけを通す。本体の `index.html` をサブフレームへ通さない。メインフレームは従来どおり
- 親が受けるメッセージは、受け取る1か所で確かめる
    - 送り主が、親が作ったiframeであること
    - 種類と形が決めたとおりで、図の世代と操作の番号が合うこと
    - `id` とリンクの番号が、親の一覧に在ること
    - リンクの知らせは、親が出したクリックへの返答だけを受ける
- 外への通信: 図の中の `image` と `img` の画像。HTTPとHTTPSへ出る
    - CSSからの画像の読み込みは、分かっている書き方を外す。漏れても同じ種類の通信にとどまる
    - 扱い: 議事録に書かれた外部画像と同じ、受け入れたリスク。`CLAUDE.md` の記述を、図の中の画像を含む形へ直す
- ローカルのファイル: 図の中から読めるのは、本文の画像と同じ仕組みを通る画像だけ
    - 扱い: 議事録の外にあるローカル画像も絶対パスで指せば表示する。本文の画像と同じ、受け入れたリスク
    - 図が自分で書いた `minutes-image:` のURLは通らない。受け持ちは2つ
        - アプリ: `minutes-image:` のURLは描画ごとに変わるhostを持つ。hostの合わない要求を拒む。図はそのhostを知り得ない
        - 無害化: 属性に書かれた `minutes-image:` を外す。CSSの `url()` は `#` で始まるものだけを残す
    - スクリプトが動かないので、読んだ画像の中身を取り出す手段が無い
- AIへ渡る文字: 付箋の文の先頭。出どころは議事録の本文と同じで、長さに上限を持つ
- 重い図は止めない。議事録を書くのは利用者自身と、利用者が設定したAI

### 実装の順

ステップごとにコミットし、受入試験とタダシの検分を挟む。

2. 更新の強調。変わった付箋だけが光る
3. 指すと、AIへ伝える。Skillの規則もここで足す

## レビュー

GPT-6 Astraが設計をレビューし、11件の指摘を全部反映した。

- 追記の経路で選択が欠ける: 追記にも選択を固定し、送り直しは選択が変わるところで分ける
- 図の順番で突き合わせると選択が別の付箋へ移る: 図にも名前を持たせる
- 表示している図・一覧・選択の世代がずれる: 1組として入れ替え、メッセージに番号を付ける
- 指している図のファイルと書き先が食い違う: 指した付箋を直す依頼は、図のファイルを直す
- 守りの受け持ちを広く読みすぎている: 止めるものごとに受け持ちを分け、子のCSPを足す
- 層の位置合わせの契機が足りない: 単純な形と測り比べてから選び、試作で確かめる項目を挙げる
- 位置だけの変化で図の枠が光る: 枠を光らせるのは、指せる要素の無い図だけにする
- `id` だけを返す契約ではリンクを扱えない: リンクに番号を振り、結果を3種類に分ける
- 選べる条件と検証の上限がつながっていない: 選べる条件と長さの単位を先に決める
- `viewBox` を寸法にすると従来の大きさと変わる: 表示する大きさと座標を分ける
- 図の通し番号を元のファイルから引けない: 図の名前を渡す

反映を確かめる2周目で、6件の指摘を受けて反映した。

- 図のファイルを直すと、通知できるパスが1つの契約とぶつかる: 図のファイルを直したときは通知を省く
- 描画のticketで照合すると、描き直しの準備中に外した選択がアプリに残る: 選択の知らせは表示対象の世代で照合する
- 最後の付箋を消すと図の枠が光る: 枠を光らせるのは、基準の側にも今の側にも指せる要素が無い図だけにする
- ボードの節と図の名前が重なっても気づけない: ボードの節の原文も渡し、重なりの判定に含める
- URLで狭めたCSPは、SVGが書いた `canvas.js` を指す要素を区別できない: nonceで狭める
- 長い見出しの扱いが決まっていない: 文字の境目で切り詰める

3周目で、2件の指摘を受けて反映した。

- 議事録の読み込みに失敗して本文が隠れても、選択が送られる: 本文を隠すときも表示対象の世代を進め、選択を空にする
- ボードの節だけが変わると、図の名前の重なりを判定し直せない: ボードの節だけの更新でも原文を渡す

タダシの検分で、1点を直した。

- 図の中のローカル画像を範囲外にしていた: 議事録が参照する画像や画面の記録の画像を図に出したい。本文の画像と同じ仕組みで出す
- 送ったあとの選択は残す、図が見えているときだけ添える、の2つは設計のとおりで決まった

ローカル画像の分をGPT-6 Astraがレビューし、4件の指摘を反映した。

- CSSの `url()` は無害化で選別されない: 外のファイルを指せる場所を `image` ・ `img` ・ `a` に絞り、CSSの `url()` は同じ図の中の参照だけを残す
- 画像の成否を親が知る契約が無い: `canvas.js` が画像ごとの成否を親へ知らせ、読めなかった件数を図の下に出す
- 同じパスの画像を上書きしても、使い回した図は古い画像のまま: ローカル画像を含む図は描き直しのたびに作り直す
- 書き換える属性が決まっていない: `image` の `href` と `img` の `src` に揃え、`srcset` は外す

2周目で、2件の指摘を受けて反映した。

- `url()` を書かなくても、変数と `image-set()` でCSSから画像を読める: URLを組み立てられる書き方も外し、CSSの検査の限界を書く
- 外部の画像が読めなかった図を使い回すと、読み直さない: 読めなかった画像のある図も作り直す
