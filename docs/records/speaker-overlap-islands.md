# 被りの島の補正を段階的に強める試験

2026-09-26 の試験の記録。現行の仕様ではない。採用した島の補正の条件と、凍結との整合は [話者の割当と固定](../speaker-assignment.md) を参照する。この文書には段階の比較と試し方を残す。

話し手の発話に別話者の声が重なった区間で、話し手の本文の一部が別話者の行へ割れる。これを段階的に直す補正を試験として実装し、比較の結果から `cross` を本番にした。[採用](#採用)

- 前提: [話者補正の除外比較とフレーズ固定の試験](speaker-correction-trial.md) で採用した吸収なし・フレーズ固定
- 以下の「補正」から「試し方」までは、段階を切り替えられた試験版 `66be821` の説明。採用後は `cross` の条件だけが残る

## 採用

2026-09-26 にタダシが、比較結果の質問票から `cross` を選んだ。

- 本番: `cross` の条件を常に当てる。凍結の条件5(間の無い後続の文の確定待ち)も常に効く
- 撤去: `off`・`cut`・`phrase` の切替と環境変数 `KIKIGAKI_TRIAL_ISLAND`。指定すると録音を始めずに止める
- 段階の比較: 試験版 `66be821` のビルドを scratch の worktree で組み、同じ dump に `--align-compare` を当てる
- 記録: `meta.json` の `islands` に `cross` を残す。再生の照合は `islands` が `cross` の記録だけで行う
- 検証: 採用後の本体を10記録に当て、試験版の `cross` と全文・固定待ち・停止時との不一致が全て一致した
    - 試験版の `cross` で録った `2026-09-26_1323` は、再生がアプリの凍結列と全描画で一致した
- 凍結の条件5に合わせ、最後の文を凍結させていた単体テスト10件へ、間を空けた後続の文を足した。各テストが見る条件1〜4の意図は変えていない
    - 対象: `SpeakerFreezeTests` 4件、`SpeakerTrialTests` 4件、`SpeakerBoundaryTests` と `TranscriptMergeTests` 各1件
- `swift test` は755件が成功した。known issue は吸収の廃止で残した14件と、返答の既知の制約1件

## 何が起きているか

9/26 等倍の記録 `2026-09-26_1146` の 66〜77秒。区間のラベルは話者判別の出力で、実際の話者の正解ではない。

| 本文 | 秒 | 窓判定 | 区間 |
|---|---|---|---|
| る | 66.60–66.66 | 堀田 | イチロー 65.51–66.72 と堀田 66.40–67.10 が重なる |
| だ | 68.58–69.66 | 堀田 | 1.08秒の1文字。前半はイチローの区間が途切れて堀田だけ、末尾 0.22秒でイチローの区間が戻る |
| 話で少 | 71.58–72.18 | 堀田 | イチロー 69.44–73.16 の中に堀田 71.13–72.59 がすっぽり入る。窓の重なりが同点で、番号の小さい堀田に倒れる |
| よね。で、 | 75.24–76.32 | 堀田 | 堀田 74.98–75.94 が文末と次の文頭にまたがる。どのトークンにもイチローの区間が 0.12秒以上ある |

- 事実: 上の区間とトークンは記録した dump の値
- ユーザーの指摘: 以前の版ではこの辺りが分裂しなかった。これらの断片は全てイチローの発話
- 推測: 堀田の区間は相槌で、その言葉は文字になっていない。原音で全文を確かめたものではない
- 既存の補正で直らない理由
    - 語内補正は文字数の過半数で揃える。「い / る」「少 / し」は1対1の同点で動かない
    - 長い語頭の付け替えは同じ語の中だけ。「だ / から」はNLTokenizerが別の語に分ける
    - 旧来の吸収も「よね。」は文末の保護で残していた

最新の録音 `2026-09-26_1258` (進行役が等倍で再取得) でも「そ / ういう」「話も少 / しかぶります」「けど、」「だ」「ね。で、」が同じ形で割れる。

## 補正: 被りの島を両隣の話者へ戻す

1つの規則を、適用範囲だけ段階的に広げる。実装は `SpeakerIslands`。規則の条件1〜3は現行と同じで、現行の条件は [話者の割当と固定](../speaker-assignment.md#被りの島の補正) にある。

有意文字のトークンを時刻順に並べ、同じ話者の連続を「島」と呼ぶ。島 R (話者X) を次の全てを満たすとき、両隣の話者Yへ戻す。

1. 島の直前と直後の有意文字がどちらも同じ既知話者Yで、Xも既知でYと違う
2. 島の長さ (最初の文字の開始〜最後の文字の終端) が1.5秒以下
3. 島の各有意文字に、Yの区間が `min(文字の長さ, 0.12秒)` 以上重なる
4. 段階ごとの範囲の条件 (下表)

| 段階 | 範囲の条件 | 凍結 |
|---|---|---|
| `off` | 補正なし。既定 | 従来どおり |
| `cut` (控えめ) | 両隣が同じフレーズで、島の端が語を切る (「少 / し」「い / る」) | 従来どおり |
| `phrase` (中間) | 両隣が同じフレーズ。語を切る条件は無し | 従来どおり |
| `cross` (強め) | 両隣との間に0.35秒以上の間が無ければ、文末・結果境界をまたいでよい | 後続のフレーズの確定を待つ |

- 段階は包含関係にある: `cut` ⊂ `phrase` ⊂ `cross`
- 判定は語内補正と長い語頭の付け替えの後、句読点の付け替えの前に置く。句読点だけのトークンは島に数えず、句読点の付け替えが直前の文字の話者へ揃える
- 不明 (区間なし) の島は補わない
- 語を切る判定は、語内補正と同じ `WordBoundaries` の語で、島の先頭か末尾の境界が語の内側にあること
- 条件3は、島の間も話し手の区間が続いていることを確かめる。話し手の区間が途切れた間の返答は戻さない

### 既知の制約

話し手の区間が重なる中で、別話者が実際に言った「はい」「そうですね」も、`phrase` と `cross` では話し手へ戻す。

- 区間だけでは、文字にならなかった相槌と、文字になった返答を区別できない
- `cut` は語を切らない島を戻さないので、完結した語の返答は残る
- 相槌の辞書で例外を作ることはしない。段階の意味と副作用をそのまま比較に出す
- 合成の反例をテストに `withKnownIssue` で残した
- 9つの記録で見つかった差からは、返答を奪っていないと断定できない。差の正解は確かめていない

## 凍結との整合の検証

島の判定を補正前のラベルで行うこと、凍結済みの行から始まる島の扱い、`cross` の後続待ち(凍結の条件5)の現行の条件は [話者の割当と固定](../speaker-assignment.md) に移した。ここには検証の記録を残す。

- 負荷: 補正前のラベルを計算し直すのは境界の手前の数フレーズだけ。1120秒の記録で、全段階の録音中の再生を含む比較が約91秒。`off` だけの判定時間は従来と同じ
- 見送り: 島の候補があるときだけ後続を待つ最適化は、採用が決まってからの独立した課題として見送った

### 確かめたこと

- テスト: 次の反例で、1トークンずつ届けて順に凍結した結果が停止時の一括判定と一致する
    - 「0 1 0 1 0」の交互。補正前ラベルの計算し直しを外すと食い違うことも確かめた
    - 右の隣が、後から届く丁寧語尾で語内補正が変わる形。右の隣のフレーズの確定待ちを外すと食い違うことも確かめた
    - 9/26 の実録区間を全段階で
- 再生: 10記録・全段階で、停止時との不一致と凍結後の変化は0
    - 記録時と同じ段階の再生は、アプリの実際の凍結列と全描画で一致した。`off` の記録2本と `cross` の記録1本

### 既存の既知差

吸収の廃止で残した既知差の14件は、どの段階でも解消しない。

- 確かめ方: 一時的に既定の段階を切り替えて全テストを流した。既存のテストの結果は全段階で変わらなかった
- 理由: 不明の断片・Sortformer 時代の区間・区間を持たない事例で、島の条件を満たさない

## 直らない分断

- 「最 / 悪はもう。」「そ / うさせていただいて」のように島にならない語頭の分断
    - 左の隣が前の話者で、両隣が同じ話者の島ではない
    - 語内の同点で、長い語頭の条件にも当たらない
- 話し手の区間が途切れた間の別話者の1文字。2人対談の「な / んできそうな」「サーバーじ / ゃ」など
    - 条件3を満たさない。本当に別話者が発した可能性があり、補わない

## 試し方

試験版 `66be821` での手順。採用後の本体では環境変数を指定すると止まる。今も動く再比較の手順は [話者判定の再比較手順](../speaker-compare.md) を参照する。

試験用 `.app` を組む。起動中の通常の `.build/KIKIGAKI.app` には触れない。

```sh
KIKIGAKI_TRIAL=1 ./scripts/make-app.sh
```

マイクで試す。段階は録音開始時に読んで会議ごとに固定し、stderr へ `[trial] islands=...` を1行出す。

```sh
TRIAL=.build/trial/KIKIGAKI-Trial.app
open -n $TRIAL --env KIKIGAKI_TRIAL_ISLAND=cross --args --config <設定ファイル>
```

- `KIKIGAKI_TRIAL_ISLAND` は `off|cut|phrase|cross`。未指定は `off`。それ以外の値は録音を始めずに止める
- 録音中の表示・凍結・停止時の判定・停止後の統合の再計算・AI送信の会話固定の全箇所で同じ段階を使う
- 話者判別が無効の会議では使わない
- release ビルドでは読まない

録音を replay して比べる。`KIKIGAKI_TRIAL_DUMP` を付けると、記録時の段階が `meta.json` の `islands` に残る。

```sh
APP=.build/trial/KIKIGAKI-Trial.app/Contents/MacOS/KIKIGAKI
KIKIGAKI_DEBUG_DIARIZATION=on KIKIGAKI_DEBUG_TYPED_VERIFY=1 KIKIGAKI_DEBUG_REPLAY_REALTIME=1 \
KIKIGAKI_TRIAL_ISLAND=cross KIKIGAKI_TRIAL_DUMP=<作業用ディレクトリ>/dump \
  "$APP" --config <設定ファイル> --replay ~/Documents/KIKIGAKI/2026-09-26_1250.wav

.build/debug/Kikigaki --align-compare <作業用ディレクトリ>/dump/<会議名> --out <作業用ディレクトリ>/compare \
  --names 0=司会,1=堀田,2=イチロー
```

- 出力
    - `comparison.md`: 段階ごとの最終判定と録音中の固定、`off` との差の本文
    - `comparison.json`: 同じ内容の機械可読版
    - `transcripts/<段階>.md`: 段階ごとの全文
    - `transcript.md`: `off` の全文。前の版の出力と `diff` で比べられる
- 再生の照合は、記録時と同じ段階だけ行う。他の段階は「対象外」と出る
- 差の本文は、全ての有意文字が正解区間の中の場合だけ「正解区間」と出す。一部だけなら「一部だけ正解区間」、それ以外は「未確認」
- 記録の中身は会話本文を含むので、出力先はリポジトリ外の作業用ディレクトリに限る
