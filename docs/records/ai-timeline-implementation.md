## 変える理由

タダシの申告は「本文がすぐ見えない」「送信と返事が別行」「発話に割り込む」「状態が分からない」の4点で、備考は「AIのやりとりを人間のやりとりと別々にしているから分かりにくい」。原因は、AIだけが別種の畳んだ1行として置かれ、読むのに開く操作が要ることにある。実寸モック3案から案Aを採用した。正とするモックは `plan-a-normal.png` と `plan-a-busy.png`。

| 1 | 既読の成立条件 | AIの本文・未読ピルの明示クリックだけ。フッターは移動だけ | 末尾追従で画面に入ることは読了を意味しないため、可視化による自動既読を廃止する。自動送信のansweredも同じ条件に揃える |

当時の「既読」の節は次のとおり。

**AIの行の本文または未読ピルをクリックしたときだけ既読にする。** フッターの未読アイコンは該当行への移動だけを行い、既読にはしない。末尾追従・スクロール・前面表示・滞在時間では既読にしない。本文のアクセシビリティの押下も明示操作として扱う。現在の会議と過去会議で同じ条件を使い、可視化の監視とタイマーは置かない。

保存と強調は次のとおり。

- 既読は `AIConversationController.markRead` で保存する。UIだけで隠さない
- 自動送信のansweredも未読で取り込む。既存の保存済みの既読状態は変更しない
- 確認待ちの金の帯と「返答する」は、既読とは独立に、返答されるまで残す
- 通知音の対象は変えない

### 段3のUIレビュー反映

クロディーヌのレビューで必須4・推奨7・任意6を受け、いずれも採用した。必須のうち3件は「設計どおりに書いたつもりが画面に出ていない」型だった。

- **引用の左罫と字下げが出ていなかった**。`alignmentRectInsets` は手動フレーム配置では参照されず、罫もボタンの内側に描いていたので文字に隠れていた。字下げをフレームで与え、罫は別のサブビューにした
- **送信行と返事行が隣接すると同じ文が2回出ていた**。上の引用の節のとおりCoreで落とす
- **自動送信の細い1行が2.6:1**だった。この地色では11ptを薄めて弱める余地がない。`Washi.muted` へ戻し、自動の区別は語に任せる
- **「AI」「自動」の印に枠が無かった**。混雑した画面では、自動の返事を人の依頼への返事と見分ける唯一の手掛かりがこの語になる。枠のピルにした
- 金地の白文字が3.25:1だったので、塗りピルの文字色を地の色で選ぶようにした。行のピルとフッターのバッジの両方
- 宛名から枠を外した。宛名はラベルで状態ではない。枠つきピルを状態専用に残し、枠の有無がそのまま「注意が要るか」になる
- **既読の可視判定を行と可視域の重なりに変えた**。上端だけを見ると、画面いっぱいの長い返事はスクロールしながら読んでいる間ずっと対象から外れる
- 時刻は人と同じ粒度に揃える。実機FBを受け、現在は全行を `HH:MM:SS` にしている。取消・準備中の送信行の色を抜き、返答後も `?` を残し、親の注記を「#Nで返答」にした
- フッターの操作を行の操作と同じ枠のピルに揃えた。同じ「押すもの」が2種類の見え方をしていた
- 任意6件も採用した。「対象:」を落とし、失敗の帯を12ptにし、「取消」を「考え中…」の行の右端へ寄せ、読み取り専用で失敗の時刻が浮かないようにした
- **AIの色を紺から紫へ変えた**。4枡が埋まった実画面を撮ったところ、紺は4枡目の青緑と近い。紫は4色のいずれとも色相が離れる

### 段2のCore実装

`AITimeline.items` を実装した。`AIConversation` を走査し、requestごとに送信の要素を必ず1つ、返事・失敗の要素を条件付きで1つ作る。

- 送信の形は `trigger == .scheduled` → 細い1行、`question_source == .voice` → 細い1行、それ以外 → 人側の行の順に決める。**自動送信は `question_source` がtypedなので、この順序でないと人側の行になってしまう**
- 返事側は失敗・結果あり・返事待ちの順に判定する。`delivery_unknown` は成否が分からないので要素を作らず、送信の注記へ「送達不明」を足すだけにする。送れた前提の進行表示を出さない
- 失敗の判定は状態だけでなく**結果の種類も見る**。取消後に届いた結果は状態が `cancelled` のまま残るので、状態だけを見ると失敗が通常の返事に化ける
- 取消後に届いた結果は要素を作り、「取消後の返事」の注記を付ける。`AIInlineMark` の既存の扱いを引き継ぐ。失敗の帯は1行なので、この注記も同じ行へ連ねる
- 失敗と返事の表示時刻は到着時刻。到着が無い送信前の失敗は、固定した送信時刻を出す
- 引用は `sendRow` のときだけ非空にする。声は発話そのものが送信文で、自動は毎回同じ定型文になる
- 並べ替えは `(slot, rank, 日時, 送信か返事か, 記録順, request番号, 生成順)` で全順序にする。`rank` は afterUtterance・at・tail の順。同じ入力からは必ず同じ列になる

段2はGPT-6のクロスレビューを受け、順序・分類・情報の受け渡しを直した。指摘は同時刻の返事が記録順を失うこと、日時が単調でない発話列で挿入位置が変わること、取消後の失敗を通常の返事に分類すること、`Item` だけでは詳細と状態を作れないこと、送信前失敗の時刻がnilになること、文書の同時刻の順序が実装と逆であること。いずれも上記へ反映し、再現例をテストへ足した。

`AIInlineMark` と `AIMarkRow` はまだ残してあり、差し替えは段3で行う。段2では既存の描画経路に触れていない。

### 段3の描画実装

`Sources/Kikigaki/AITimelineRows.swift` に `AISendLineRow`・`AITypedSendRow`・`AIReplyRow` を置き、`AIInlineMark` と `AIMarkRow` を削除した。`AIReplyRow` が返事待ち・返事・確認質問・失敗の帯を1つのビューで扱い、行IDを共有する。

- **AIの色**: `Washi.ai` を1色追加した。`AvatarView` に `accent` と `glyph` を足し、話者枡の色と記号を差し替えられるようにした
- **人側の送信行**: 墨の丸に `paperplane.fill`、名前は「AIへ送信」、右端に宛名の枠ピル。「手入力」の名前と鉛筆は使わない
- **行の操作**: 「返答する」「取消」「再送」は枠のピルで描く。押せない場面ではボタン自体を出さないので、無効時に面を足す状態を作らない
- **既読**: 本文・未読ピルのクリックから `onReadAI` を呼び、保存する。可視化監視の `AIReadWatcher` とタイマーは廃止した
- **確認質問**: 未読でも返答済みなら金の帯を外す。未読の朱にはしない。既存の `AIBadgeKind.unread` が確認を除いているのに合わせる
- **「ペインを開く」**: 書き起こしウィンドウの「…」メニューへ1つだけ置く。開けるペインがある時だけ出す
    - 更新: 過去会議ウィンドウは撤去した

実画面で見つけて直したもの。`AIStatusPill` の初期表題が `NSButton` 既定の「Button」のままだったこと、失敗の帯に確定時刻が無かったこと、返事待ちに「AI」の印と時刻が出ていたことの3点。

`MarkdownBodyView` の高さを測る前に、表示と同じ幅の枠を与えるようにした。**幅0のまま最初に測ると、表やコードを含む返事の高さが11倍ほどに跳ね上がり、その値が幅ごとの計測キャッシュへ残る。** 畳んだ印だった頃は、展開まで測らなかったので表に出ていなかった。

### 段3のクロスレビュー反映

GPT-6のクロスレビューで中4件・低3件を受け、既読・再送・回帰テストを直した。

- **返送された失敗も既読の対象**にした。Coreは `.failed` の結果を未読にするのに、行が可視判定から外れ印も無く、未読件数と「前の会議に返事あり」が残り続けていた。帯の中へ未読の印を置き、可視化の対象にも含める。**送信前の失敗はそもそも未読にならない**ので印は出ない
- **既読の判定を `AIReadWatcher` へ切り出し**、書き起こしウィンドウと過去会議ウィンドウで共有する。過去会議には可視化の経路が無く、確認質問は既読にする手段が無かった。会議を切り替えたら滞在時間を捨てる
- 滞在時間は**単調時計**で測り、キー喪失・最小化・アプリの非活性で数え直す。可視域が変わった時点でも外れた行の時間を捨てる。0.25秒の評価の合間に出入りした行の時間を足し続けないため。タイマーは**common modes** へ入れ、スクロールのドラッグ中も止めない
- **「再送」は元requestを渡す**。`onResendAI` を新設し、送信文・宛先・親への対応付け・作業許可を戻したシートを開く。以前は新規の問いを開いていたので、別の下書きが入っていると違う依頼になり、確認への返答だった場合は親を失っていた。**宛先はシートへ固定の枠として渡す。** 選択欄を隠すだけでは `owningSlot` が選択値を見るので、送信先と取消先が食い違い、取り消したはずの依頼が送信され得る
- タイマーはウォッチャーの破棄で止め、参照先が消えたコールバックでも自分を止める
- **確認待ちの金の帯は返答まで残す**。実装が既読で消していたのを文書へ合わせた。既読の管理は帯とは別で、可視化と印が担う

確認への返答が失敗・取消で終わったときは、**同じ確認へ送り直せる**ようにCoreの契約を変えた。親の `answeredByRequestID` が失敗した返答を指したままだと、再送が「返答済み」として `AIError.mismatch` で拒否される。失敗・取消で終わった返答は返答済みとして数えず、参照を新しいrequestへ付け替える。復元時の検証も、付け替えで外れた古い返答が失敗・取消であることを条件に許す。

この「返答済みか」の判定は `AIQuestion.isAnswered(_:in:)` に1つだけ置き、**表示・件数・自動送信の抑止・保存のすべてがここを通る**。`answeredByRequestID` の有無だけを見る場所を残すと、送り直せる状態なのに「返答する」と確認待ちの件数が消える。

回帰テストは実コントロールを通すようにした。印の表題と有効・無効、失敗の帯の時刻、返事待ちのチップと時刻の非表示、引用の実クリックと開閉の保持、待機から返事への同一ビューでの変化、非キー状態を挟んだ中断、過去会議の既読の配線を確認する。
