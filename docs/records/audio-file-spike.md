# 音声ファイルの書き起こしの試作記録

2026-10-24の試作と、仕様を決めた記録。現行の仕様ではない。仕様は [音声ファイルの書き起こし](../audio-file.md) を参照する。

## 結論

**品質を変えていたのは流す速さではなく、速報の並走だった。速報を止めれば、最速で流しても等倍と本文・話者が一致する。**

## 方法

- 対象: 保存済みの実録WAVを3本。話者判別はオン
- 経路: `--replay` のDEBUGビルドに、未コミットの試作用環境変数を2つ足した
    - 流す倍率: 0.5秒のチャンクごとの間を倍率で割る。0は間を置かない
    - 速報: `AppleTranscriber` の `usesFastResults` を切り替える
- 比較: 会議Markdownの本文から時刻と話者を除いた文字列の一致率と、一致した文字の話者ラベルの一致率。話者の記号は条件ごとに振り直されるので、多数決で対応させた
- 基準: 等倍・速報なし

## 結果

| 音声 | 流し方 | 処理時間 | 基準との差 |
|---|---|---|---|
| `2026-09-26_0237.wav` 5分・3話者 | 速報なし・間なし | 3秒。モデル読込を含む初回は10秒 | 本文・話者とも完全一致 |
| 同上 | 速報なし・間なしの2回目 | 3秒 | 完全一致 |
| 同上 | 速報なし・10倍/4倍/2倍 | 34秒/80秒/158秒 | 完全一致 |
| 同上 | 速報なし・等倍の2回目 | 315秒 | 完全一致 |
| 同上 | 速報あり・等倍 | 315秒 | 本文の約0.7%が違う。話者は一致 |
| `2026-09-14_0728.wav` 3分46秒 | 速報なし・間なし | 4秒 | 等倍と完全一致 |
| `2026-09-14_0044.wav` 18分40秒・4話者 | 速報なし・間なしを2回 | 約9秒 | 2回で完全一致 |

速報ありとの違いは主に句読点だった。ほかに「第三者工程/肯定」「すごい勢いで首」の有無など語の違いが数件あった。

`2026-09-14_0728.wav` の等倍は、3分46秒の音声に888秒かかった。本文は間なしの結果と一致した。チャンクの間の `Task.sleep` がApp Napで間引かれた疑いがある。間を置かない経路は待たないので影響しない。

## 決めたこと

タダシと質問票で決めた。全問とも推奨の案。

- 入口: 録音と同じ開始シートを、音源がファイルの形で開く。メニューバーと書き起こし窓へのドロップから入る
- 速さ: 品質が落ちない最速。試作の結果から、速報を止めて間を置かずに流す
- 範囲: 書き起こし中は時間に依存する機能を止め、流し終えたらAIへ「最後の1回」を送る
- 日時: 録音した日時
- 開始シート: 使わない行は出さず、AIの行は「完了時に送信」にする
- 書き起こし中のヘッダー: 「書き起こし中 12:30 / 32:15」

## 実機確認の後に変えたこと

タダシの実機確認で「話者を特定する機会が無い」と分かった。「完了時に送信」は保存と同時に飛ぶので、AIが「話者A」のまま議事録を書いていた。質問票と会話で次のように決め直した。

- 開始シートの「完了時に送信」を外し、書き起こしの後に「仕上げ」を挟む。話者を決めてからAIへ頼み、「完了」で閉じる
- 話者の推定は専用の操作を作らず、既存の `identifySpeakers` を強くする。仕上げでフラグ付きの宛先へ手動で頼めば足りる
    - 推定の根拠: 名乗りと呼びかけへの直後の応答だけから、話の流れも使えるように広げた
    - 付けてよい名前: 候補名だけから、会話の本文に出てきた人名も足した
    - 範囲: 録音の会議にも効かせる。外れが目立てば後で選べるようにする
- 話者ごとの声の再生は入れない。効き具合を見てから別の作業にする
