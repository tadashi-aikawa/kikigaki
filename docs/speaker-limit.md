# 話者人数の上限と統合

録音開始前に「人数上限」を自動または1〜4人から選ぶ。TOMLの `maxSpeakers` は省略すると自動。指定したときだけWeSpeakerを追加ロードし、Sortformerの話者枠ごとに重複発話を除いた音声特徴を照合する。モデル初回取得以外は端末内処理。

設定例:

```toml
maxSpeakers = 2
```

画面で選んだ上限はアプリ実行中の次の録音にも引き継ぐ。設定ファイルには書き戻さない。上限指定をやめる場合は画面で「自動」を選ぶか、設定ファイルの `maxSpeakers` を削除して録音停止中に再読込する。

新たに十分な声を得た枠は、まず既存の基準話者と照合する。一致すれば統合し、一致せず上限に余裕があれば新しい基準話者として保持する。上限到達後の余分な枠も基準話者と照合する。短い音声や僅差で判断できない場合は話者不明として残す。人数を指定しても話者の正しさは保証されない。モデルの取得・抽出失敗は独立した警告欄へ示し、自動統合は保留する。

「話者…」から検出された元の枠と統合先を確認・訂正できる。自動へ戻す操作と、元の枠へ戻して分離する操作も用意する。手動指定が自動より優先し、利用者が明示的に分離すれば人数上限を超えることも許す。統合は会議単位で、声や統合指定を次の会議に持ち越さない。

ボタンの人型アイコンは人数上限の数を並べ、統合後の認識人数だけ塗りつぶす。自動なら4人分。手動分離で上限を超えた場合は実人数まで増やす。停止後はその会議の人数上限を表示し、次回用の設定変更では変えない。検出枠の消費は別に「使用枠 3/4」と表示する。CをAへ統合した場合、人型は2人分が塗りつぶされても、検出枠はA・B・Cの3枠を使用している。

元の話者番号を保持し、表示・通常Markdown・省略前Markdown・AIへの受け渡しへ同じ統合を適用する。停止後の訂正は元トークンから省略候補を再計算し、以前の統合に伴う相槌の削除を復元できる。話者区間を重ねて多数決の重みを増やす方式は使わない。

録音中の凍結値は元の話者番号を保持する。相槌候補に使う窓判定と多数決後の判定の両方へ統合を適用する。音声は直近20秒だけ保持し、各枠の重複していない単独発話から最大3つの特徴を採取する。手動統合先は表示名の枠への直接指定で、連鎖させない。元の枠への自己指定は分離を意味する。

## 声の照合

2秒以上、最大6秒の単独発話から256次元の特徴を取得し、各特徴を正規化した平均同士でコサイン類似度を比較する。採用条件は類似度0.5以上、次点との差0.08以上。無効な特徴は使わない。これは初期の実験値であり、広範な声・音響条件で精度が保証された閾値ではない。

特徴抽出は音声入力と別のタスクで、同時に1バッチだけ行う。音声入力を推論待ちにせず、待ち行列も増やさない。音声バッファは有効20秒、配列の整理待ちを含め通常22秒以内。停止時は実行中の照合が完了してから保存する。

WeSpeakerの保存容量は約8MB。現行Sortformer fastの約240MBに追加される。実行時メモリは保存容量と異なる。初回はHugging FaceからWeSpeakerのディレクトリだけを取得し、以後はキャッシュを使う。音声や特徴は外部送信しない。特徴は会議終了後に破棄する。

## 制約

統合単位はSortformerの元の枠。1つの枠に複数人が混ざった誤判定を、発言ごとに分離する機能ではない。最初の数本の特徴が同じ人の声を代表できない場合も誤統合し得る。「話者…」に元の枠をすべて残し、手動指定で修正する。

アプリ側で統合してもSortformer内部の検出枠は空かない。4人の会議で途中に分裂が起これば、残る人物を別の枠で検出できなくなる可能性がある。人数アイコンの輪郭は設定上限を表し、新たな人物をその人数だけ認識できる保証ではない。

人数指定なしでは特徴抽出を行わず、従来の自動判定を保持する。この場合も手動での統合は使える。話者不明の発話本文は省略しない。過去の保存Markdownを開き直して統合する機能はなく、訂正できるのはアプリが保持している現在の会議。

既存キャッシュが破損した場合の自動修復は行わない。モデルをロードできなければ警告し、手動指定へ切り替える。
