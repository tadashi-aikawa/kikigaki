# 小音量発話の計測

以下は計測段階の記録。現在の除外操作と設定は[小音量発話の除外](audio-exclusion.md)を参照する。現在は診断表示をOFFにしても内部計測と除外機能は有効で、診断の有無は会議開始時に固定する。

## 今回の範囲

自会議の小声と別会議の声の音量差を実会議で確認するための実験機能。`measureAudioLevels = true` で次の会議から有効にする。省略時は無効。録音中・停止後の音声行へ音量と小音量候補の注釈を表示する。手入力は対象外。

この段階では発話を除外しない。通常のMarkdown本文・会話コピー・手動AI送信・自動AI送信は従来どおり全発話を含む。注釈は「小音量候補・未除外」とし、別会議の断定はしない。自動除外・解除のUIは計測結果を受けた次の段階で実装する。

## 計測と候補の仮判定

- 音源が変換した16 kHz・モノラルのFloat PCMを、`PauseFlag.accept` 通過後の `makeConsumer` 内で計測する。Speechへの供給後にある既存のMainActor更新で同じチャンクを計測器へ追記し、画面には行の集計結果だけを渡す。計測のための供給前の待機は追加しない。ASR通知が先着した区間は未計測となり、次の画面更新で補う。波形を捨てたり変更したりしない。
- 100 ms単位のRMSを記録し、`20 * log10(RMS)` をdBFSとする。0は保存可能な有限値−120へ丸める。非有限サンプルを含む窓は欠測扱い。
- チャンクをまたぐ100 ms窓は連続して集計する。末尾の端数窓も保持する。一時停止中は既存の入力処理が受け付けないため、時刻は文字起こしと同じ収録位置に揃う。
- 行の音量は区間内の窓の90パーセンタイル。窓の中心が行区間内にあるものを用いる。ごく短い行で窓が入らない、音声がまだ届いていない、欠測を含む場合は未計測とし候補にしない。
- 絶対値−45 dBFS未満を候補とする。直前の計測済み音声行が8件以上あれば、直近60行の上位25%の中央値を基準とし、基準より15 dB以上小さい行も候補にする。比較対象に当該行や未来の行は含めない。
- 数値は今回の観察用の仮値。距離・話者の所属・判定精度を保証しない。短い衝撃音や同時発話を分離する機能ではない。
- 基準は各表示の音声行集合に追従する。停止・統合・相槌省略で行の区切りが変われば候補を再計算する。通常Markdownと相槌省略前Markdownは、それぞれの行集合で計測表を生成する。改名だけでは判定は変わらない。

## 保存と互換性

有効な会議では停止時に、同名の `.levels.json` へ窓ごとの音量トラックと元の発話行・話者名・開始時刻・一時停止の情報を保存する。録音WAVを保存しない場合も記録する。通常Markdownの末尾には計測表を追加し、本文を残したまま時刻・話者・音量・候補を確認できるようにする。

停止後の改名・統合では元の音量トラックから表と `.levels.json` を再生成する。AI会議のarchiveにもoptionalでトラックを保持する。旧archiveは欠損を無効として読む。既存の同名計測ファイルだけが残った場合も録音名を予約済みとして扱い上書きを避ける。計測表はAIセクションの後に置く。

トラックは窓ごとの数値配列で1時間あたり36,000点。AI返信時のarchive再保存にも含まれるため、1時間相当の保存処理時間を検証する。

計測ファイルの保存に失敗しても本文保存は試みる。本文の保存成否とは別に `levelsSucceeded` を持ち、警告を保存結果に保持して再試行の対象にする。計測だけの失敗では最後の自動AI送信を中止しない。録音の取り止めでは計測ファイルを作らない。クラッシュ前の逐次保存は今回の対象外。

## 受け入れ確認

- 既知振幅・無音・端数・チャンク分割差・非有限値・短い区間の計測を検証する。
- 未来の大声で過去の判定が変わらないこと、手入力が候補にならないことを確認する。
- 設定省略、旧archive、有効時の往復保存、既存ファイル衝突、保存失敗を検証する。
- 実Speechのreplayで話者判別無効の即時表示と計測を併用し、本文・コピー・AIから発話が消えないことを確認する。
- 実会議でUM04の近い声・遠い声を比較する。これはタダシの環境での次の確認段階とする。
