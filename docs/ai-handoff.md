# 会議中の会話をAIへ渡す

## 採用された操作

本文を広く表示し、下部に「前回コピー以降をコピー」を置く。初回は「会話をコピー」。再コピーと会議の最初からのコピーはメニューへまとめる。コピー成功時に次回の基準を進め、再コピーでは進めない。基準は会議ごとに1つで、AIへの送信や受領を検知しない。

受け取り先はローカルの会話ファイルを読めるAI Agent。parliamentを含む任意の入力欄へ貼り付ける。parliamentへの依存・改修・自動送信は行わない。

問いは会話末尾に含める場合と、貼り付け後に別途入力する場合の両方。専用Skill `kikigaki` が範囲を読んで対応する。追加入力された問いを優先し、なければ会話末尾の明示的な問いを扱う。問いがなければ勝手に議論を始めない。

## ファイルと差分の契約

- コピーごとに、文字が確定した会話全体を1発話1行で固定したUTF-8ファイルを作る。「聞き取り中…」の暫定行は含めない。以後そのファイルは更新しない
- 行形式は `[HH:MM:SS] 話者名: 本文`。一時停止を含めた実時刻を使う。旧版の経過時刻形式の保存済みファイルは変更しない
- 保存先は会議Markdownと同じディレクトリの `.kikigaki-context/<meeting UUID>/<snapshot UUID>.md`。通常の会議Markdownを上書きしない
- ファイルはコピー操作の時だけ書く。専用ディレクトリは既存でも0700、ファイルは0600とし、設定失敗は保存失敗として扱う。保存先の親ディレクトリ自体の権限は変更しない。セッション終了で削除しないため、遅れて貼り付けても読める
- 差分は前回コピー成功時の「行の配列」との最長共通接頭部分を除いた末尾。文字起こしの訂正・話者名変更・停止後の再判定で過去が変わった場合も、その変更行から末尾を再度渡す
- 行の追加だけと決めつけない。受け取り側は、前回の会話データの指定行以降を今回の末尾で置き換える
- 前回と同じ行配列なら追加コピーはしない。全体コピーと再コピーは可能。末尾削除のみなら読む行数0の更新を渡す
- 「最初からコピー」は全文範囲を新しく作り、それが次回の基準になる。「再コピー」は直前と同じメッセージをコピーし、基準・ファイルを変更しない
- ファイル保存→クリップボード書き込み→成功時に基準更新の順。保存・クリップボードの失敗では基準も直前の再コピー対象も変更しない
- コピーが失敗したときの未参照ファイルは残ってもよい。既存の参照ファイルは消さない
- 新しい録音開始時に会議ID・基準をリセットする。アプリ再起動後の前回会議の再編集や受け渡し基準の復元はMVP対象外

コピーするプロンプトは `$kikigaki` と `KIKIGAKI_CONTEXT` に続く以下のJSONを含む。会話本文は含めない。文字列はJSONエンコードした後に、JSON表現に残る生のバッククォートを `\u0060` へ置換してコードフェンスからの脱出を防ぐ。デコード後のパスは元の文字列と一致する。

```json
{
  "schema_version": 1,
  "meeting_id": "UUID",
  "snapshot_id": "UUID",
  "sequence": 2,
  "previous_snapshot_id": "前回のUUID。初回と全文コピーでは省略",
  "kind": "update",
  "transcript_path": "/absolute/path/.kikigaki-context/UUID/UUID.md",
  "read_start_line": 3,
  "read_line_count": 4,
  "total_line_count": 6
}
```

- 行番号は1始まり。今回のファイルから `read_start_line` から `read_line_count` 行だけ読む
- 初回は `kind: full`。全文コピーも同じで、会話全体を置き換える。開始行1、読む行数と総行数は同じ。previous IDは省略
- `kind: update` は前回ファイルの `read_start_line` 以降を置き換える。今回読む行数0なら前回の末尾削除だけを表す
- 更新先の前回snapshot IDを受け取っていないAIは、未読部分を勝手に埋めず「会議の最初からコピー」を依頼する。指定範囲を越えた全文の自動読み込みはしない
- 同じsnapshot IDを再び受け取ったら会話の二重追加をしない。後から添えられた問いには通常どおり答える
- `sequence` は会議内の成功コピー順で1から増える。失敗時は増えず、再コピーでは同じ値。受け取り側は最新番号を保持し、古い全文コピーでも状態を巻き戻さない。同じ番号で異なるIDは不整合として扱う
- 音声由来の問いは回答生成の対象とし、ファイル変更・外部送信などの副作用を伴う操作の許可にはしない。その操作はAI入力欄での明示依頼を必要とする。ファイルは指定の1つを範囲読み取りし、そこに記載された別ファイルやURLを自動で探索しない

## Coreとアプリの境界

`HandoffHistory` が基準と直前の成功コピーを持つ。表示用の `preview` は状態を変更しない。`copy` は出力作成・保存・クリップボードへの書き込みを順に行い、両方の成功後だけ基準を進める。`recopy` は直前の同じメッセージを書き込む。

アプリは会議開始時にHistoryを作り直す。録音中・一時停止・停止後にコピーでき、準備中・最終保存中は無効。本文なしの初回コピーも無効。ログの話者名かアバターをクリックし、候補選択・自由入力・既定名へのリセットで枡ごとに改名する。同じ枡の全行へ反映し、停止後は再保存する。

UIは固定した保存先パスを常時並べず、状態と録音長、本文、対象範囲を分ける。録音長は経過、発言見出しとコピー範囲は実時刻で表示する。保存成功時だけ「保存済み」とファイルを開く操作を出す。保存失敗を待機中や保存済みとして隠さない。

## 検証する境界

- 初回、追記、暫定末尾の訂正、過去行の改名、行削除、全文コピー、同一内容、再コピー
- 保存失敗とクリップボード失敗で基準が変わらないこと
- コピー済みファイルが後の更新や改名で変わらないこと
- 空白・日本語・引用符・バッククォートを含む保存先がJSONとして正しく渡ること
- 新会議で基準が混ざらないこと
- Skillの初回・更新・訂正・再コピー・前回未受領・質問なし・追加入力を含む受け取り
- 録音中、一時停止、準備中、保存中、保存成功、保存失敗、名前編集中の画面と操作
