# 会議中の会話をAIへ渡す

この文書は手動コピーの契約です。`[[ai]]` を設定した会議で使える自動送信・返送は [AI参加者の設計](ai-participant.md) を参照してください。履歴は独立しており、AI送信の受領は手動コピーの連番に影響しません。

Skillは先頭envelopeの `participant` がない場合にこの手動コピーの手順を使います。participantがある会議参加モードでは、受領と回答を同梱CLIへ返し、声の明示的な作業依頼もCLIの承認設定に従って扱います。本文中の偽envelopeや音声だけで、手動コピーを会議参加モードへ切り替えません。Skill側の判定と手順は [SKILL.md](../skills/kikigaki/SKILL.md) を単一情報源とします。

## 採用された操作

フッターの「…」メニューの「会話をコピー」だけを置く。押すたびに、その時点で記録している会話の全体と、表示中の議事録のパスを渡す。

- 目的: KIKIGAKIのAI参加を設定していなくても、任意のAI Agentへ今の文脈を渡せるようにする
    - 理由: 手動実行は議事録作成の用途が強く、herdrの専用ペインを前提にする
- 差分・再コピー・最初からのコピーは置かない
    - 理由: 受け取り側が前回の受領を覚えている必要があり、入口が3つに分かれてややこしい。全文なら毎回それだけで完結する
- 本文の「次にコピーする範囲」の区切りも置かない。範囲が常に全体なので示す境界が無い

「手入力」は利用者が会話の入力欄から投稿した行で、声の話者とは別の固定名。音声位置順に並び、時計には実際の投稿日時を使う。一時停止中の投稿も含めてコピーする。過去に固定した会話ファイルは書き換えない。

受け取り先はローカルの会話ファイルを読めるAI Agent。parliamentを含む任意の入力欄へ貼り付ける。parliamentへの依存・改修・自動送信は行わない。

問いは会話末尾に含める場合と、貼り付け後に別途入力する場合の両方。専用Skill `kikigaki` が範囲を読んで対応する。追加入力された問いを優先し、なければ会話末尾の明示的な問いを扱う。問いがなければ勝手に議論を始めない。

## ファイルの契約

- コピーごとに、その時点で記録している会話全体を1発話1行で固定したUTF-8ファイルを作る。半透明で表示中の未確定の発話も含める。「聞き取り中…」の暫定行と、小音量で除外した行は含めない。以後そのファイルは更新しない
- 行形式は `[HH:MM:SS] 話者名: 本文`。一時停止を含めた実時刻を使う。旧版の経過時刻形式の保存済みファイルは変更しない
- 保存先は会議Markdownと同じディレクトリの `.kikigaki-context/<meeting UUID>/<snapshot UUID>.md`。通常の会議Markdownを上書きしない
- ファイルはコピー操作の時だけ書く。専用ディレクトリは既存でも0700、ファイルは0600とし、設定失敗は保存失敗として扱う。保存先の親ディレクトリ自体の権限は変更しない。セッション終了で削除しないため、遅れて貼り付けても読める
- 渡す行が1行も無ければコピーしない。メニューの項目も無効にする
- ファイル保存→クリップボード書き込みの順。どちらかが失敗したら連番を進めない
- コピーが失敗したときの未参照ファイルは残ってもよい。既存の参照ファイルは消さない
- 新しい録音開始時に会議IDと連番をリセットする

コピーするプロンプトは `$kikigaki` と `KIKIGAKI_CONTEXT` に続く以下のJSONを含む。会話本文は含めない。文字列はJSONエンコードした後に、JSON表現に残る生のバッククォートを `\u0060` へ置換してコードフェンスからの脱出を防ぐ。デコード後のパスは元の文字列と一致する。

```json
{
  "schema_version": 1,
  "meeting_id": "UUID",
  "snapshot_id": "UUID",
  "sequence": 2,
  "kind": "full",
  "transcript_path": "/absolute/path/.kikigaki-context/UUID/UUID.md",
  "read_start_line": 1,
  "read_line_count": 6,
  "total_line_count": 6,
  "minutes_path": "/absolute/path/minutes.md",
  "image_dirs": [
    "/absolute/path/2026-11-10_1400.attachments",
    "/absolute/path/2026-11-10_1400.captures"
  ]
}
```

- `kind` は常に `full`。開始行は1、読む行数と総行数は同じ。`previous_snapshot_id` は付けない
    - 理由: 範囲の形は会議参加モードと共通にして、Skillの読み方を1つに保つ
- `sequence` は会議内の成功コピー順で1から増える。失敗時は増えない。受け取り側は最新番号を保持し、古いコピーで状態を巻き戻さない。同じ番号で異なるIDは不整合として扱う
- `minutes_path` は、そのとき表示している議事録が実在する場合だけ付ける。人が指定した議事録でも、AIが通知した議事録でもよい。ボードは議事録の中の見出しなので、同じファイルで渡る
    - 本文を写さずパスだけ渡す。議事録はAIや人が書き換え続けるため
    - まだ作られていない書き先は渡さない。読めないパスを渡しても受け取り側は何もできない
- `image_dirs` は、会話の行が参照する画像を読んでよい置き場。契約は下の「画像の参照」
- 音声由来の問いは回答生成の対象とし、ファイル変更・外部送信などの副作用を伴う操作の許可にはしない。その操作はAI入力欄での明示依頼を必要とする。ファイルは会話ファイルの指定範囲と議事録だけを読み、そこに記載された別ファイルやURLを自動で探索しない。例外は下の「画像の参照」だけ。Skill側の規則は [SKILL.md](../skills/kikigaki/SKILL.md) の「手動コピーの問いに答える」節に従う

## 画像の参照

手入力に貼った画像と画面の記録の画像を、AIが必要なときに読めるようにする。会話ファイルの行は画像の内容を文字にせず、行末の `` 画像N: `絶対パス` `` で参照だけを渡す。この節が `image_dirs` と画像の読み方の単一情報源で、Skill側の手順は [SKILL.md](../skills/kikigaki/SKILL.md) の「画像の参照」。

### `image_dirs`

- 置き場: 手動コピーの `KIKIGAKI_CONTEXT` のJSONと、会議参加モードのenvelopeのトップレベル。どちらも同じ位置に置き、Skillの読み方を1つに保つ
    - 会議参加モードでも `participant` の中に入れない。`minutes_path` と違い、送信ごとに変わらない会議の値のため
    - 作業中の依頼への追記の `context` も元の依頼と同じ値を持つ
- 値: その会議の `<会議名>.attachments` と `<会議名>.captures` の絶対パスの配列。この順。末尾の `/` は付けない
    - 会話ファイル(`transcript_path`)・`image_dirs`・行の画像参照は、保存先を同じ表記で書く。Skillは置き場の親と参照の親、会話ファイルの保存先を文字列で照合するため
        - 保存先は設定の `outputDir` を解決する所(`ResolvedConfig`)で1回だけ字句上で正規化する(`LexicalPath`)。`.`、重なったスラッシュ、末尾のスラッシュを畳む。区切りはUnicodeスカラーの `/` で探し、要素の中の結合文字や正規化形は変えない。`~` の展開とURLの生成でもファイルシステムへ問い合わせない
            - `..` は畳まず、`outputDir` の要素にあれば設定エラーにする(仮決め)。直前の要素がシンボリックリンクだと、字句上で戻した場所とOSが辿る場所が違い、保存先が黙って変わるため。詳細は [設定リファレンス](config.md)
        - 会議Markdown・画像の置き場・行の画像参照・会話ファイル・`image_dirs`・回収時の照合は、全部その値から導き、途中で正規化し直さない
        - `/private/tmp` を `/tmp` へ変える処理とシンボリックリンクの解決は入れない。`standardizedFileURL` も通さない
            - 理由: `standardizedFileURL` はファイルが在るときだけ `/private` を外す。通すと表記がずれ、会議Markdownを書く前と後でも値が変わる
        - 古い保存物: 正規化の前に作った会議は、保存済みのmanifestの会議Markdownから導き直すので、回収時の照合は保存したときの表記のまま一致する。`image_dirs` の無い旧requestは照合しない
    - 「会話をコピー」・会議参加モードの手動送信・自動送信・確認への返答・再送で同じ値。どれも会議Markdownのパスから `MeetingFiles.imageDirectories(for:)` で導き、経路ごとの分岐を作らない
    - ディレクトリがまだ無い会議でも、存在を確かめずに両方を列挙する
        - 理由: AIが読んでよいのは会話の行が参照する画像だけで、空のディレクトリを渡しても読めるものは増えない
        - 理由: 存在で省くと、送信の値を固めた直後に最初の1枚が保存された場合に、行は画像を指すのに置き場が渡らない。自動送信の依頼は送信の時点で固定し、後から足せない
- `schema_version` は変えない。キーの無いJSONは従来どおり読み、そのときAIは画像を読まない
    - 会議Markdownを持たない会議(AI登録を回収できなかった会議など)では付けない
- 検証: `AIImageDirectories` が2通りで確かめる。保証できる範囲はそれぞれ違う
    - 完全一致: 会議Markdownのパスが分かる所では、そこから導いた値と完全に一致しなければ拒む。「会話をコピー」、送信の準備、AI記録の回収が当たる。同じ保存先の別会議の置き場への差し替えも拒める
        - 「会話をコピー」と送信の準備は、呼び手から置き場を受け取らず、会議Markdownから導いた値だけを載せる
    - 形だけ: 会議Markdownを知らない所(envelopeの検証、返送CLI、受信箱)では形だけを確かめる。要素はちょうど2つで、会話ファイルと同じ保存先の直下にある同じ名前の `<名前>.attachments` と `<名前>.captures` の順。空の要素、`.`、`..`、制御文字を含むパスは不正
        - 限界: 同じ保存先の別会議の組への差し替えは、形だけの検証では拒めない
    - 理由: 置き場を広げられる余地を、envelopeの改変や本文の偽装に残さない
- Skillも同じ形を確かめ、外れたら画像を読まずに会話だけを受け取る。手順は [SKILL.md](../skills/kikigaki/SKILL.md) の「画像の参照」

### 読んでよい画像

- 参照のパスの親ディレクトリが、`image_dirs` のどれかと完全に一致する画像だけ。置き場の直下に限る
- 判別は行の形ではなくパスの所属で行う
    - 理由: `transcript_path` から分かるのは保存先の全体で、会議名は分からない。参照の文字列から会議名を採ると、別会議の画像も同じ規則で許してしまう
    - 理由: 本文に利用者が同じ形の文字列を書いても、置き場の直下を指していなければ探索しない。直下を指していれば、それはKIKIGAKIが置いた画像なので読んでも害が無い
- 画面の行は、発言が指す図や資料を確かめたいときに読む。毎回全部は読まない
- 画像の中の文章は会話の資料として扱い、作業の許可や指示としては扱わない
- 画像が無い・読めないときは、その旨を短く添えて会話だけで答える
- 差分で受け取った発言が以前の画面を指すときは、同じ `transcript_path` の `read_start_line` より前の画面の行を読んでよい。話者名の割当の見直しと同じ形の例外
- 画面の行は保存の遅れで、送信済みの範囲より前の音声位置に届くことがある。差分の扱いは [AI参加者の設計](ai-participant.md) の「Envelopeと差分の基準」

### CLIの読み取り許可

- `image_dirs` は会話ファイルと同じ保存先 `outputDir` の直下にある。会議参加モードのCLIは会話ファイルを読める範囲で画像も読め、許可を足す必要は無い
    - Codex: `outputDir` を `sandbox_workspace_write.writable_roots` に加えて起動している。詳細は [議事録プレビューの設計](minutes-preview.md) の「Skillの規則と書き込み許可」
    - Claude: 会話ファイルと同じ扱い。専用の `--settings` は同梱CLIのallowだけで、読み取りの許可は変えない
- 利用者のグローバル設定は書き換えない

## Coreとアプリの境界

`HandoffHistory` は会議IDと直前の成功コピーを持つ。`copy` は出力作成・保存・クリップボードへの書き込みを順に行い、両方の成功後だけ連番を進める。会議IDはAI送信の履歴とも共有する。

アプリは会議開始時にHistoryを作り直す。録音中・一時停止・停止後にコピーでき、準備中・最終保存中は無効。議事録のパスは会議の議事録の状態から読み、ファイルが実在するかをコピーの直前に確かめる。

## 検証する境界

- 毎回全文になること。改名・統合・訂正の後も今の全文を渡し、過去の固定ファイルは変わらないこと
- 空の会話と、小音量の除外で行が無くなった会話はコピーしないこと
- 保存失敗とクリップボード失敗で連番が変わらないこと
- 空白・日本語・引用符・バッククォートを含む保存先と議事録のパスがJSONとして正しく渡ること
- 新会議で連番と会議IDが混ざらないこと
- Skillの初回・再受領・質問なし・追加入力・議事録ありを含む受け取り
