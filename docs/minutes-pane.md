# 議事録ペイン

書き起こしウィンドウの右に開く、議事録の閲読用ペインの仕様。AIとの受け渡しの契約は [議事録プレビューの設計](minutes-preview.md)、本文の描画・検索は [議事録の描画と検索](minutes-rendering.md)、録音開始シートでの指定は [録音開始シート](start-sheet.md) を参照する。

## 動作の前提

- ペインは「対象なし」で始まる。既定の議事録パスを設けず、会議開始だけでは議事録ファイルを生成しない。
- 表示ONで右へ広げ、標準状態は600→1800pt。会話側の幅を維持し、画面に収まらない分を縮める。OFFではその時点の左ペインの幅へ戻す。分割位置と表示状態は再起動後も復元する。
- ペインは閲読用で、パス欄の操作で議事録本文を書き換えない。
- 録音開始シートで指定した議事録は、開始と同時にペインを開いて人の指定として扱う。

## ウィンドウと操作

開閉の「議事録」ボタンは1つだけ置き、いつもウィンドウの右上に見せる。SF Symbolは `sidebar.right` 系を用い、「議事録を表示」または「議事録を隠す」のツールチップとアクセシビリティラベル、ON/OFFのアクセシビリティ値を付ける。メニューバーアイコンのStatusItemメニューと「表示」メニューにも「議事録を表示／隠す」を置き、閉じたウィンドウを開いてから切り替える。状態と表題はヘッダーと共有する。フッターの「…」には追加しない。無効時は色を抜き、無効状態だけの背景面を足さない。

- 閉じている間: 左ペインのヘッダー右端。薄墨で地なし。600pt未満では文字を隠す
- 開いている間: 右ペインの上部バーの右端へ移し、罫色の地と墨の図の押し込み表示にする。地で状態が分かるため図だけにする
- 位置: 右端からの余白と縦の中心を左のヘッダーに揃え、開閉してもウィンドウの右上から動かない

開閉は約0.25秒のease-outで動かす。ウィンドウを伸縮できるときは開閉の直前の会話側の幅を保ってウィンドウが右へ伸び、右端に右ペインが現れる。ズームボタンやウィンドウ管理アプリなどライブリサイズ以外で変わった幅も、開閉の直前に希望幅として取り直す。タイル・全幅など伸ばせないときは、右ペインが右端から滑り込み会話側が縮む。閉じるときは、ウィンドウの大きさによらず開いていた会話側の幅を保ち、右ペインの分だけウィンドウを縮める(左端は固定)。開く途中で閉じたときは開く前の枠へ戻す。右ペインは途中も最終の幅のまま右端の外から出入りさせ、中身を細い幅で組み直さない。状態・メニュー・AX値は押した時点で切り替え、配置だけが後を追う。途中で再び押すとその場から戻り、途中の幅を希望幅として保存しない。「視差効果を減らす」と、ウィンドウが見えていないときは一瞬で切り替える。左端を固定して右へ伸ばす `fitting` の規則は変えない。

左右の `NSSplitView` にし、仕切りは `Washi.rule` で描く。左には従来のヘッダー・検索・会話・入力・フッターをまとめて置く。右は上部の編集可能パス欄と「ファイルを選ぶ…」、下部の独立したスクロール領域。対象が無いあいだは上部の「ファイルを選ぶ…」を隠し、空の案内の下の同じボタンだけを出す。

パス欄はReturnで確定し、Escapeで編集中の文字を取り消す。パス欄の内側の右端には、検索欄と同じ見え方のクリアボタン(`xmark.circle.fill`・薄墨・16pt)を置く。クリアはペインを隠さず、表示中の議事録を外して対象を解除する(空欄の確定と同じ経路。起動直後と同じ空の状態へ戻る)。表示対象があるときだけ見せ、その間は文字がボタンの下へ潜らないよう右の内側余白を取る。ペインの表示切替は「議事録」ボタンとメニューだけが行う。NSOpenPanelは単一の `.md` ファイルに限定し、取消では対象を変えない。未作成パスはパス欄から指定する。編集中の通知で入力文字を置き換えず、パス欄の下に対象が変わった旨を1行表示し、編集の確定・取消時に反映する。

パス欄の右にはNeovim・Obsidianで対象ファイルを開くアイコンボタンを置く。動作は [議事録の描画と検索](minutes-rendering.md) を参照する。⌘Fは焦点のあるペインを検索する。

| 右ペインの状態 | 表示 |
| --- | --- |
| 対象なし | 「議事録のファイルを指定するか、AIに書かせると表示します」 |
| 読込中 | パスを残して読込中を表示。別ファイルの古い本文を出さない。 |
| 読込成功 | Markdown本文。空ファイルは「議事録はまだ空です」。 |
| 人の指定ファイルなし | 「指定したファイルはまだありません。作成されると自動で表示します」。パスを残して監視を続ける。 |
| AIの通知ファイルなし | 「AIが通知したファイルはまだありません。作成されると自動で表示します」。パスを残して監視を続ける。 |
| 読取失敗 | 権限・文字コード・サイズ等の原因を簡潔に表示し、再読込できる。 |

非表示中のAI通知はフッターのスペーサー右、ピンの手前へ、薄墨の `doc.text` と下ラベル「議事録」を表示する。クリックでプレビューを開き、同じ印を消す。通知音と前面化はしない。表示中の通知は対象を切り替えて描画し、印は立てない。人のファイル選択だけでは印を立てない。印は内容を確認した証明やファイル実在の保証ではない。

右上部バーは題を置かず1行にし、左ヘッダーと区切り線の高さを揃える。パス欄は和紙地と細い輪郭、フォーカス中だけ墨の輪郭にする。上部バーと本文は左余白24ptで揃える。本文と表はペイン幅に追従し、幅の上限を設けない。幅に収まらない表・コード・図は、本文全体を押し広げずにそれぞれ横スクロールする。本文全体の横スクロールは設けない。対象なしの案内は上から約1/3へ置き、ファイル選択は直下にだけ置く。

## 最近表示したファイルの履歴

パス欄へフォーカスすると、最近プレビューに表示できたファイルを最大10件、欄の直下に和紙色の一覧で出す。人のパス入力・ファイル選択と、AIの `minutes` 通知による切替を同じ扱いにする。選択や読込開始だけでは記録しない。`MinutesWebView.onRendered` の現行描画完了時に記録し、空ファイルの正常表示も含める。読込・描画失敗、非表示中の通知、対象変更や停止で無効になった描画は含めない。

保存はアプリ全体のUserDefaultsの `KikigakiMinutesHistory` 1キーに絶対パスの配列を置く。新しい順で、同じパスの再表示は先頭へ移し、10件を超えた分を末尾から落とす。Coreの純粋な値型 `MinutesHistory` が順序・重複・上限を扱い、アプリ側が読書きする。読み出すたびに最新の配列を使い、複数の会議ビューが古い写しで上書きしない。復元時の不正パスは既存の `MinutesPath` 検証で除く。symlink解決や実在確認で同一性を変更しない。

各行はファイル名を12ptの墨、親ディレクトリを11ptの薄墨で表示する。親が直前の行と同じなら従段を省き、44ptの行を28ptへ縮める。長い親パスは先頭を省略し、全パスはツールチップへ置く。ホバーとキーボード選択は薄い地で示し、一覧には影を付ける。存在しないファイルも削除せず、ファイル名は墨のまま行末に11ptの薄墨で「見つかりません」を添える。選択後は既存の未作成案内に任せる。

開いた直後は先頭を選択し、Returnだけで最近のファイルを開ける。クリック、または上下キーで選んでReturnを押すと、パス欄に値を入れて既存の確定経路で開く。選択変更時はVoiceOverへファイル名と不存在の注記を通知する。入力を編集すると選択を解除し、Returnは入力中のパスを確定する。Escapeは一覧を閉じる操作を先に行い、もう一度押すと既存の下書き取消になる。一覧の余白クリックでも閉じ、欄のフォーカスは残す。IME変換中は候補操作を優先する。フォーカスが欄から外れたとき、ウィンドウが非キーになったとき、会議切替、プレビュー非表示でも閉じる。履歴が空、または表示可能な高さが44pt未満なら一覧を出さず、上下キーとReturnを奪わない。同じパスが履歴の先頭なら再描画時にUserDefaultsへ書き直さない。ヘッダーのボタン配置は変更しない。

会議の `minutes.json`、AI通知の契約、envelopeの `minutes_path` は変更しない。履歴は表示の便宜であり、会議の記録やAIの書き先を自動的に引き継ぐ仕組みではない。個別削除は持たない。検証ハーネスとテストには隔離したUserDefaultsを注入する。

## 幅と復元

- 初回ONの要求幅は、現在の会話幅+1200pt。600ptなら合計1800ptで、区切り線は追加分に含める。左端と上端を維持して右へ広げる。
- OFFはその時点の左ペイン幅までウィンドウを縮め、その幅を希望幅にする。区切り線をドラッグした後の幅もそのまま使う。表示中の手動リサイズでは原則として右側を伸縮し、区切り線のドラッグで左右配分を変更する。
- 再ONは保存した左右の幅を復元する。初期値、明示的なドラッグ、ウィンドウリサイズの扱いを純粋な幅計算へ分離する。左の最小幅420pt、右320pt。ON中の `minSize` は両者と区切り線の合計にする。
- 切替・画面変更ごとに現在の `NSScreen.visibleFrame` を取り直す。まず右側の追加幅を画面右端まで縮め、必要なら左端を画面内へ移動する。それでも両ペインの最小幅が収まらない画面では画面内に収めることを優先する。
- UserDefaultsの1キー `KikigakiMinutesLayout` に `{visible, leftWidth, rightWidth}` を保存する。起動時のframe autosaveから採るのは位置と高さだけで、幅はこの1キーから再計算する。利用者のリサイズは `inLiveResize` で判別し、画面制約による一時的な縮小を希望幅へ上書きしない。
- フルスクリーン・タイル中にONにするときはウィンドウ幅を変えず、分割だけを切り替える。希望幅は保存しない。
- OFFはタイル中でも左ペイン幅まで縮める。タイルの状態から外れることは受け入れる。
    - 例外: ネイティブのフルスクリーン(`styleMask` の `.fullScreen`)はウィンドウ幅を変えられないので、分割だけを外して会話が全幅に広がる。希望幅も保存しない
- 解除時とライブリサイズ終了時に希望幅を画面へ合わせ直す。タイルは公開状態がないため、画面全高かつ半幅または全幅で左右端に接する配置から推定する。同じ配置を手動で作った場合との区別はできない。

`NSSplitView.autosaveName` は使わない。希望幅の正本を上記の1キーに統一する。Apple公式資料: [分割配置の保存](https://developer.apple.com/documentation/appkit/nssplitview/autosavename-swift.property)。

## 保存先の扱い

ペインは現在の会議の `MinutesStore` に接続する。人の指定の保留、適用失敗時の扱い、停止後の指定、対象範囲は [議事録プレビューの設計](minutes-preview.md) の「会議ごとの保存と回収」を参照する。AI未設定でも人によるパス指定と保存・監視は使える。

## ファイル監視と描画

監視は本文の真偽を保証せず、再読込のきっかけに限る。対象ファイルと親ディレクトリを `DispatchSource` で監視し、2秒間隔のTimerで通知欠落とinode差し替えを補う。ファイルが存在しない場合もTimerを維持する。fdに結び付く通知とcancel handlerでのcloseはAppleの契約に従う。資料: [DispatchSourceFileSystemObject](https://developer.apple.com/documentation/dispatch/dispatchsourcefilesystemobject)、[Dispatch Sources](https://developer.apple.com/library/archive/documentation/General/Conceptual/ConcurrencyProgrammingGuide/GCDWorkQueues/GCDWorkQueues.html)。

- `.write`、`.rename`、`.delete`、`.revoke`、`.extend`、`.attrib` を再走査の契機にする。読取前に `(dev, ino, size, mtime_ns)` を比較して無関係な親ディレクトリ更新を除き、置換なら監視を付け直す。親ディレクトリ自体の置換・消失も定期走査から復帰させる。既存のディレクトリ固定の `AIInboxMonitor` とは別にファイルとsymlink解決先の監視を実装する。
- 通知から約200msのデバウンスを置く。読取はUIスレッドの外で行い、Markdown解析と図・数式の描画は議事録専用WebKitで行う。会議ID・パス・読込世代が今の対象と一致する結果だけ反映する。
- 監視のopen前にstatで通常ファイルかディレクトリかを確認し、差し替えにも備えてO_NONBLOCKを付ける。読取は通常ファイルを確認し、FIFO等を待たない。ユーザーの議事録は0600や単一hardlinkを要求しない。symlinkは読み取り用途として解決先を辿り、元の指定パスを保持して付け替えを再検知する。
- UTF-8を読み、同一本文は再描画しない。本文上限は4MiBで、超過時は「大きすぎるため表示しません」にサイズを添えて表示し、切り捨てない。iCloudの実体待ちは待機表示と取消を用意する。「ファイルとフォルダ」の許可を拒否された場合は、アクセス許可がなく読めない旨を表示する。
- 読取失敗はstampが変わるまで再読込しない。ファイル無しとiCloud待ちだけを定期再試行する。
- 読取中の置換はfdとパスの再照合で検出し、旧inodeの結果を反映せず再読込する。非原子的な書込の途中なら次の通知・定期走査で再読込する。200msは保存完了の保証ではない。
- 同じファイルの更新時は先頭可視ブロックとその画面内オフセットをアンカーにして戻し、短縮時だけ有効範囲へ収める。本文選択も範囲を補正して維持する。末尾への自動追従はしない。別ファイルへの切替時は先頭へ戻す。
- 非表示中は本文読取・解析・描画を停止し、表示ONで必ず最新ファイルを読む。受信箱の回収は継続する。ウィンドウ破棄・会議切替ではTimer、監視、保留読込を終了し、cancel完了後にfdを閉じる。

更新箇所の強調の基準は表示だけの扱いで、`ai/minutes.json` にも会議Markdownにも保存しない。仕様は [議事録の描画と検索](minutes-rendering.md) を参照する。
