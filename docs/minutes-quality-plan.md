## 目的と優先順位

主要発言を正しい話者に帰属させ、語や文が不用意に分断されない議事を作る。短い相槌や一瞬の発話を漏れなく残すことは優先しない。SortformerとApple Speechは継続する。

優先順は次のとおり。

1. 主張・判断・承認・否定・訂正を別人の発言にしない。
2. 本筋の文章を語途中で分断しない。不確かな短い判定で話者を頻繁に切り替えない。
3. 読みやすさのため、意味を持たない相槌の省略を許容する。
4. 小さな相槌を独立話者として保持する網羅性は、上の3点より優先度を下げる。

短い別話者の発話を省くことと、本文を残して主話者の発言に付け替えることは区別する。「いいえ」「違います」「それでお願いします」のような短い発言は意味を変えるため、秒数だけで一律に省かない。声だけから意味を確実に判定できない箇所は、原文を残し不確かさを扱う。

## 実装を分けて比較する

### A. 長い文字時刻と発話区間の突き合わせ

現行は各トークン中央の前後0.5秒で話者を決める。1文字の時刻に発話前の間が含まれると、無音や前話者の末尾を拾う。

- 文字区間内の発話部分との重なりと、同一語・前後の発話の連続性を用いる候補を比較する。
- ごく小さい重なりだけで話者を断定しない。境界が曖昧な場合は前後両方向と重複発話を評価する。
- 全トークンを末尾へ寄せたり、最寄り話者を無条件に選んだりしない。未知話者や本当の交代を誤って埋めるため。
- 文字列を変更せず、まず話者の帰属と行分割だけで効果を測る。

### B. 議事優先の発話単位

- 日本語の「1語として完結した短い発話を常に残す」という現行条件を、議事優先の目的から再設計する。
- 主たる話者の安定した継続と、十分な裏付けのある本当の交代を分ける。0.1秒の判定変化だけで別人の行を作らない。
- 短い相槌を省略する場合は、話者を統合して別人に言わせず、候補として省く。本文の原本は保存できることを前提にする。
- 承認・否定・訂正の保持は、長さ・音量だけでなく発話内容と前後の文脈を評価する。単純ルールで保証できない部分は明記する。
- A単独とA+Bを分けて評価し、語頭の修正と相槌の省略が混ざって改善して見えることを避ける。

### C. 序盤の遡及処理

現行も停止時は表示の凍結を外して全体の突き合わせを再実行している。これと、声の履歴を蓄えたモデルで音声を再解析することは別。

- まずA+Bで序盤の誤りがどれだけ残るか測る。
- 必要な場合だけ、冒頭音声の一時保持と再解析を試作する。
- 話者スロットの対応・時刻の重複・録音中の本文の揺れ・メモリ量・停止待ち時間を測る。
- 効果が確認できなければ採用しない。学習済みキャッシュへ過去音声を単に追加するだけで正しく再判定できるとは仮定しない。

## 採用基準

| 観点 | 合格条件 |
|---|---|
| 主要発言の帰属 | 原音で確定した修正対象の誤帰属が解消し、保留評価区間と回帰音声で新たな誤帰属を確認しない |
| 語途中の分断 | 確定した語頭分断を解消し、主要発話の途中に新しい不明・話者切替行を作らない |
| 本文 | Aでは認識済み本文を完全保持。Bの省略は対象一覧を比較し、意味のある承認・否定・訂正を消さない |
| 不明と省略 | 不明行数の減少だけを成功にしない。全て同じ話者にする・削除して見えなくする結果は不合格 |
| 録音中 | 途中の複数時点と停止後の両方を比較し、古い主要発言の話者が繰り返し変わらないことを確認 |
| 処理性能 | 同じMac・同じ音声で基準版と比較し、実時間で追従できることと停止待ち時間を確認 |

単体テストは実装担当のガードレールとする。受け入れの根拠は原音と変更前後の議事の比較。主たる書き手と別モデルによる仕様・コードのレビューを入れる。

## 進行方法

現時点の推奨は、解析文脈を持つAstraが継続し、Fableが目的・仕様・評価結果を独立にレビューする形。今回の課題に対する両モデルの比較実験はしておらず、性能の優劣を断定しない。指揮をFableへ交代する場合も、本計画・原音の正解・基準版のログを渡し、同じ採用基準で進める。

現在並行して行われているUI・AI連携の変更を巻き込まないよう、実装時には独立作業領域か編集ファイルの分担を確保する。録音や基準ログはローカルに置き、リポジトリへ音声を追加しない。
