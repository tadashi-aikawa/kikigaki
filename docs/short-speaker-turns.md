# 短い返答の話者を残す条件

1.5秒未満の別話者区間を多数派へ揃える処理に、語境界を使った例外を設ける。設定の追加はなく、録音中と停止時の両方に適用する。凍結済みの話者は変更しない。文字は削除・補完せず、元の窓判定を残す。

## 保持する条件

- 元の窓判定が既知の同一話者で続いている区間である
- 空白・句読点を除いた両端が、日本語の語境界に一致する
- 文字・数字が2文字以上含まれる
- 1語だけで完結するか、文末句読点まで含む。ただし多数派の声が区間全体を覆う場合、または同じフレーズ内で区間の直前と直後がともに多数派の場合は、相槌・応答のプリセットに一致するものだけ保護する。この場合は複数語の定番応答も完全一致で保持する
- 上記とは別に、両端が語境界に一致する0.6秒以上の区間で、末尾が「ですか」「ますか」の場合も保持する。フレーズ先頭か句読点の後から始まり、直後が「どうか」でないことも必要。句点が欠けた短い応答を吸収しないための限定条件

語境界はフレーズ全体を `NLTokenizer` の日本語・単語単位で解析する。区間だけを解析すると、語の一部分も完全な語として扱われてしまうため。境界が得られない場合は従来どおり多数派へ揃える。

文中の複数語を一律に残すと、「経過報告」のような本文に出た短い誤判定も分断として残りやすい。このため1語・文末・上記の応答末尾に限定する。それでも誤判定は残り得る。語境界や末尾表現は話者交代の証明ではなく、意味のある応答をすべて保持する保証もない。

## 前後が主話者につながる文中の一般語

同じフレーズの直前・直後がともにフレーズ多数派なら、1.5秒未満の一般語は多数派へ戻す。音声側の区間が途切れていても適用する。「代表」のような完全な1語であることだけを、独立した返答の根拠にしないためである。

前後のラベルには、語内補正後・短い区間の吸収前の値を使う。先に吸収した区間を、新しく隣り合った別の区間を吸収する根拠にしない。別フレーズや第三話者の境界をまたいで主話者を探すこともない。

句読点だけの隣接トークンは発話の証拠にしない。同じ話者ラベルの句読点を越えて文字のあるトークンまで確認し、フレーズ端や別話者に達したら連続性を使わない。凍結境界が別話者区間の内側にある場合も、後半だけの吸収による語の分断を避けるため、その区間を保持する。

相槌の保持には既存の `WordBoundaries.backchannelWords` を使う。前後の空白と句読点を除き、区間本文全体が一致した場合だけ保持する。「はいの意味」のような部分一致は対象外。繰り返しの生成や未知語の推測はしない。

プリセットでも両端の語境界を確認する。「そうめん」の「そう」のような語の断片は保護しない。複数語の定番応答は引き続き保持する。「分かりました」などが本人の文の末尾なのか相手の応答なのかは、この語彙と語境界だけでは識別できない。句読点が省かれた相手の応答も残すため、文頭限定にはしていない。

| 種類 | プリセットの例 |
|---|---|
| 相槌 | はい、うん、ええ、はいはい、うんうん、へえ |
| 同意・反応 | そうですね、そうです、そうですよね、確かに、なるほど、なるほどね |
| 理解・受領 | 了解です、わかりました、分かりました、わかります、分かります、承知しました |

全プリセットの正本は `WordBoundaries.backchannelWords`。追加した定番応答は「そうです」「そうですよね」「そうなんです」「なるほどね」「なるほどですね」「わかりました」「分かりました」「わかります」「分かります」「承知しました」「承知です」。設定の追加はなく、文字の省略とも別の処理である。

この判定は文の意味を理解するものではない。相手が「反対」などのプリセット外の1語を実際に返していても、短く同じフレーズ内で主話者に挟まれる場合は吸収され得る。1.5秒以上の発話交代、凍結済みラベル、フレーズ端の完全語・文末の保持、限定した質問末尾の保持、語頭修復で救済する複数語の扱いは変えない。

## 多数派に覆われた文中の1語

### 前後の連続性とプリセットを加えた検証

保存済み実録4本の同一トークン・同一話者区間を、変更前後の `Aligner.speakers` に渡して比較した。レビュー修正後の最終版は計13,164トークンで、本文と時刻はすべて一致。話者の変更は3箇所・10トークンだった。

- 22分55秒の録音では、文中の「これ」2文字が前後の主話者につながった。
- 同じ録音の「はいはい」4文字が主話者の行から別話者へ分離された。
- 同じ録音の「そう / ですね。」が1人につながった。「ですね。」の4トークンを移し、語尾だけの分断を解消した。
- 残る3録音では話者割り当ても一致した。

22分55秒の音声は初期修正版で変更前後のアプリでも再処理し、開始時刻を除いた保存結果の差分が「これ」「はいはい」の2箇所であることを確認した。レビュー後に語境界の確認を加えた最終版の全経路音声再処理は未実施で、上記3箇所は同一入力での判定処理の比較結果である。原音に人手の正解ラベルを付けた精度評価ではない。

### 従来の音声区間による補正

`2026-09-06_1416_2.wav` の 24.60〜26.82秒で、「はい管理のプロ代表の松村です。」の「代表」(25.62〜25.92秒)だけが相手の話者になった。相手の相槌が重なり、音声側の区間が 0.2〜0.5 秒刻みで交互に出る場面で、トークン中央 ±0.5 秒の窓判定が両隣の相手の区間を足して 0.52 対 0.48 で相手へ倒れた。「代表」自体は主話者の区間 25.44〜25.92 に収まっていた。

主話者の区間が島全体を覆う場合は、主話者が喋り続けている最中とみなし、1語でも多数派へ戻す。ただし相槌・応答の語彙に一致する1語(はい・うん・ええ・そう・なるほど・いや・いいえ・確かに 等)は残す。重なった相手の「うん」が文字として出たとき、主話者の本文へ混ぜないためで、語彙は「消す一覧」ではなく帰属変更を慎重にする保護条件として使う。品詞(`NLTagger` の `lexicalClass`)は日本語で提供されないため、語彙で限定する。

主話者が黙って相手の返答を聞いた場面では、主話者の区間が島の前で切れて後で再開するため覆われない。現在は上記の前後の連続性も確認するので、このことだけで一般語を保持するとは限らない。`2026-09-05_1529.wav` の「はい」は182.88で主話者の区間が切れ、183.36で再開するが、相槌プリセットで引き続き保持する。

実録4本(`2026-09-05_1412` / `1529` / `1735` / `2026-09-06_1416_2`)の再処理で変わったのは3箇所。`1416_2` の「代表」が主話者へ戻り、同じ録音の終盤で相手の返答の頭「そうですね。」が主話者の行末から相手の行頭(「そうですね。一応今日3つまとめてきました」)へ移り、`1412` の「積み重ねみたいなね。/ 積み重ね / これじゃ…」の真ん中の「積み重ね」(相手の復唱の可能性がある)が主話者へ吸収された。復唱の吸収は本筋を割らない優先順位に沿うとして許容した(タダシの判断)。「はい」「すごいね。」「あ、本当ですか」「思い通り行きます。」は保持。主話者が喋り続ける最中の、語彙にない単独の返答(「反対」など)は吸収され得る。

## 語の途中を切る不明の島

どの話者区間にも当たらないトークン(不明)は話者交代ではない。1.5秒以上の島を残す条件は本当の話者交代のためのもので、不明の島には適用しない。ただし語として完結する長い不明の島(2文字以上の1語か文末まで)は、従来どおり不明のまま残す。声の証拠が無い長い発話を多数派に断定しないためである。

`2026-09-06_1727.wav` では、発話前の間を含んで 1.92 秒になった語頭の「欲」(765.90〜767.82秒)と 2.52 秒の「で」(586.20〜588.72秒)がどの区間にも当たらず、「考えて。/ ?: 欲 / しいなと。」「?: で、/ 具体的には」と不明の行に割れていた。語の途中を切る不明の島は長さに関係なく多数派へ付ける。同じ録音の 898.50 秒の「そう」は単独のフレーズで多数派が無く、不明のまま残る。

## 実録を使った回帰テスト

`2026-09-05_1529.wav` の再処理で、次の窓判定が多数派へ吸収されていた。

- 182.82〜183.18秒の「はい」
- 185.22〜186.06秒の「すごいね。」

これらを保持することをテストする。同じ音声の「じゃあもう10分の1」付近は、別話者の塊が「ゃあもう10分の1そ」になっており、語境界に合わない。後続の [語頭・語尾補正](speaker-boundaries.md) で扱う。複数語を含む1個のASRトークンを分割して境界を作ることはしない。

「読みやすい」の語途中、文中の複数語、1文字、不明話者、凍結済みの扱いもテストする。窓判定は人手で正解付けした話者ラベルではない。原音による品質評価は別途必要。

## 相槌省略との関係

`dropRepeatedBackchannels` は停止時の文字の省略を制御し、この話者保護とは別の処理。語境界に合わない短い島を吸収する従来の処理は残るため、前回の「うんうん先週」に対する相槌省略は引き続き検証する。

## APIの根拠

[Apple公式のNLTokenizer資料](https://developer.apple.com/documentation/naturallanguage/nltokenizer)で語単位の解析と言語指定を確認した。インスタンスは共有せず、解析の呼び出し内で作る。
