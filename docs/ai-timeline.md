# AIを会話の参加者として並べる

AIの送信と返事を、人の発話と同じ行の形で時系列に並べる。会議参加モードの契約は [ai-participant.md](ai-participant.md)、定期自動送信は [ai-scheduled.md](ai-scheduled.md)、返事本文の描画は [ai-markdown.md](ai-markdown.md) を参照する。この文書は書き起こしウィンドウでのAIの行の並べ方・種類・中身を扱う。

AIだけを別種の畳んだ1行にすると、本文がすぐ見えず、送信と返事が別行になり、発話に割り込み、状態が分からない。そこでAIの行を人の発話と同じ形で並べる。

## 変えないもの

- 会議Markdownの `## AIとのやりとり` と `## 書き起こし` の形式。表示だけの決まりで、保存物の互換は保つ
- 受信箱・request・envelope・保存済みJSONの形式と `schema_version`
- AIを `Utterance` にしないこと。AIの行は書き起こし・snapshot・AI文脈・コピー範囲のいずれにも入らない
- 声の送信印を `voiceUtteranceStart` の直下へ置く規則。`AIRequest.voiceAnchorIndex(in:)` をそのまま使う
- 到着時に前面化しないこと。末尾追従中はAIの行と状態変化も人の発話と同じく追い、上へスクロール中・検索中だけ位置を動かさない

フッターとロボットの見た目と操作は [ai-scheduled.md](ai-scheduled.md) を正本とする。

## 行の種類

AIの送信と返事は4種類の行で表す。

| 行 | いつ出るか | 形 |
|---|---|---|
| 送信の細い1行 | 声からの送信、および自動送信 | `└ 迅雷へ送信 · 4発言 · 14:06:24`。11pt薄墨。自動は「迅雷へ自動送信」とし、色は変えない |
| 人側の送信行 | 問い欄へ入力した手動送信、確認への返答 | 発話と同じ枠。アバター・名前・時刻・本文は送信文全文。右端に宛名 |
| AIの行 | 送信試行済みで取消・送信前失敗でないrequest | アバター・名前・チップ・時刻・本文と、その下にモデル表記の1行。返事待ちは同じ行へ進行文と4分割バーを出す。詳細は [AI依頼の進行表示](ai-progress.md) |
| 失敗の帯 | 送信できなかったrequest | 朱の細い1行。理由と「再送」と時刻。返送された失敗は帯の下へ本文を全部出す |

AIの行は常に展開し、畳む操作は持たない。

通常回答と確認質問では、名前行の時刻の右に11ptの薄墨で「· 所要 1:20」を添える。送信試行 `sendAttemptedAt` から、回答行の時刻にも使う結果到着 `resultReceivedAt` までを計算する。AI側のイベント記録時刻 `recordedAt` は起点・終点に使わない。小数秒は切り捨て、時計が巻き戻った場合は0秒にする。1時間を超えても「所要 61:05」のように分:秒で表示する。

保存済みの両時刻があれば、復元した会議でも同じ所要時間を表示し、時刻欠損・非有限値・失敗・取消では出さない。取消後に返答が届いた場合も所要時間は出さない。表示専用の値として `AITimeline.Item` へ導出し、保存JSONとMarkdownは変更しない。幅が足りない場合は時刻や確認ピルへ重ねず末尾を省略し、ツールチップで全文を読める。

### 送信の表し方の分岐

送信の形は `question_source` だけでは決まらない。自動送信は `autoPrompt` を送るので `question_source` はtypedだが、人側の行にはしない。

| 条件 | 送信の行 | 返事の上の引用 |
|---|---|---|
| `trigger == .scheduled` | 細い1行「迅雷へ自動送信」。日時順に置く | なし |
| `question_source == .voice` | 細い1行「迅雷へ送信」。`voiceAnchorIndex` の発話の直下へ置く | なし。発話そのものが送信文 |
| 上記以外の手動送信 | 人側の送信行 | あり |

確認への返答は手動のtypedなので人側の送信行になる。`in_reply_to_request_id` を持つ送信行の名前の右へ「#1への返答」を薄墨で添える。

### 返事の上の1行引用

キーボード入力の送信に限り、AIの行の本文の上へ送信文を1行の引用として置く。薄墨・12pt・本文から12pt字下げし、空いた左へ `rule` の2pt罫を置く。末尾は省略する。送信行と返事行の間に発話が入るため、何への返事かを返事側だけで読めるようにする。クリックで全文へ伸ばし、再クリックで1行へ戻す。開閉状態は行ビューが保持し、発話追加・改名では失わない。

**送信行と返事行が同じ位置で隣り合うときは引用を出さない。** 間に何も入らなければ同じ文が2回続くだけで、引用の目的が消える。送って即待ちは会議中の最頻ケースなので、隣接は例外ではなく既定になる。判定はCoreの並べ替え後に行い、描画側に残さない。

### AIの行の中身

| 部品 | 内容 |
|---|---|
| アバター | プロファイルの `avatar` 画像。省略・取得失敗時は参加者名の頭文字とAI専用色の紫 |
| 名前 | `participant.participantName`。`AIViewState.participant` ではなくrequestの固定値を読む |
| チップ | 手動は「AI」、`trigger == .scheduled` は「自動」。10pt・`rule` の枠・薄墨 |
| 時刻 | 到着時刻 `resultReceivedAt`。返事待ちの間は出さない |
| 状態ピル | 未回答の確認質問だけを朱の塗り・白文字の「要返答」で表示。通常の返答にピルは置かない。返事待ちは進行文で示す |
| 本文 | `MarkdownBodyView`。返事待ちは1行の進行文と4分割バー。返答到着の1.5秒だけ全段を点灯したまま同じ見た目を保つ。確認質問は本文の先頭に `?` を外付け |
| モデル表記 | 本文の下の1行。`[cpu] Codex · gpt-6-astra (high)` と `[folder] minutes` の2つの塊を12pt離して置く。11pt薄墨。相手の塊は録音開始シートの宛先と同じ表記で、effortは括弧でモデルに掛ける |
| 注記 | 必要なときだけモデル表記の下へ薄墨1行。「取消後の返事」「旧接続からの返事」「#Nで返答」。返送未確認は進行文へ含める |
| 操作 | 確認待ちの「返答する」は本文の下、返事待ちの「取消」は進行文と同じ行の右端 |

モデル表記は「どのモデル・どの設定・どこで動いているAIに頼んだか」を返事行で見分けるためのものなので、**値はプロファイルからしか採らない**。CLI名 (`Codex` / `Claude`) を先頭に置き、`model` が未設定ならCLI名だけになる。CLIの既定モデルは推測しない。推測した名前を出すと、実際に動いたモデルと画面が食い違っても気づけない。`effort` は未設定なら飛ばし、末端ディレクトリは既定cwdでも出す。

**表記は名前行ではなく本文の下へ置く**。名前行は名前・チップ・時刻・所要で埋まっており、そこへ足すと時刻の場所を奪い合う。頼んだ相手 (`model` と `effort`) と頼んだ場所 (末端ディレクトリ) は意味が違うので、中黒で1本に繋がず、`cpu` と `folder` のアイコンを先頭に付けて12pt離す。行の高さはこの1段ぶん (18pt) 増える。

出すのは返事待ち・回答・確認質問の行で、返事待ちでは進行文と4分割バーの下に来る。**失敗の帯には出さない**。帯は見出しと理由だけの1行なので、段を足さない。

1行は折り返さないので、幅が足りなければ **作業場所の塊 → エフォート** の順に落とす。落ちるのは表示する塊だけで、段を落としても行の高さは変わらない。落とした塊に関わらず、全部入りの表記は名前とフッターのツールチップ、および行の読み上げから読める。復元した会議も保存済みプロファイルから同じ表記を作る。保存形式・Markdown・envelope・受信箱は変えない。

要返答は行全体へ11%の朱の地色と3ptの左帯を敷き、返答するまで残す。通常の返答には地色・帯を敷かない。

確認質問の `?` は状態ではなく本文が問いであることの印なので、返答したあとも `rule` へ落として残す。

失敗は2種類あり、言い方を分ける。送信そのものができなかったものは「〜へ送信できませんでした」、モデルが返した失敗報告は「〜から失敗の報告」とし、**後者は帯の下へ本文を全部出す**。「一部の更新に失敗しました / 更新済み: A / 未更新: B」のような報告は、どこまで進んだかが画面から読めないと使えない。

送達不明は返事待ち行を出さないので、**取消は送信の行に置く**。他に取り消す場所がなく、`isAwaitingResult` が残る間は次の送信も止まる。取消は行の高さを変えない位置へ置く。結果が届いて取消が消えたときに行が縮むと、末尾を読んでいる利用者の画面が動く。

送信の詳細は細い1行と人側の送信行へ寄せる。「N発言」は常に出し、`作業許可なし`・`暫定末尾を含む`・`送達不明` は該当するときだけ ` · ` で連ねる。時刻範囲と全文はtooltipへ置く。時刻は人の発話・手入力・AIの行・送信の細い1行すべて `HH:MM:SS` にし、1本の時間軸に2つの桁数を混ぜない。

取消・送信準備中の送信行は、送れた送信と同じ重さで会話に残さない。面は足さず本文と記号の色を抜く。

## 範囲の境界

対象は会議で自動送信を開始した宛先slotひとつだけ。手動で選んだ別の宛先は含めず、自動送信がない会議では何も出さない。自動送信を停止しても、録音を停止して保存しても残す。宛先を変えて再開した場合は新しい宛先を表示する。

会話を新しい側から「AIに未読」「受領済みで返事待ち」「受領済みで返事済み」に分ける。Coreの純関数 `AIRangeBoundaries.resolve(history:questions:utterances:)` は、自動送信先の `AIStreamHistory`、questions、現在表示する発話配列を入力に、返事済みと受領の境界の発話添字2つを返す。

- 「ここまで返事済み」: 現stream・世代で最後に到着したansweredが受領したrequestの末尾
- 「ここまで受領」: accept済みで返事待ちの最新requestの末尾。同じ位置なら返事済みの1本だけにし、それより古い受領も重ねない
- 停止後の再分割で発話の添字は動くため、受領時の行数を現在の配列添字として使わない。envelopeの `participant.audioCutoffSeconds` を使い、現在の発話配列で `start <= cutoff` を満たす最後の添字へ写す。手入力も同じ音声位置の条件に含める。本文の再生成は不要。空範囲や該当発話がない場合には線を出さない
- 準備だけ・送信だけ・取消・別streamの受領では境界を進めない。AIセッションを作り直すと新streamの範囲になる

行間に0.5ptの薄い水平線と、右寄せ9ptの薄墨ラベルを重ねる。境界の発話に紐づく送信の細い行・返事待ち行なども含め、最後の行の下に置く。返事済みは薄墨の線、受領は金の線。マーカーは常に最前面に置くが、行の高さ・文書の高さ・スクロールアンカーに加算せず、検索中や上へスクロール中の位置を保つ。

宛先の保存は表示用の付随情報なので、失敗しても自動開始・送信・紐づけを続け、警告だけを出す。回収済みの会議のmanifestは変更しない。

最後に開始した自動送信のslotをmanifestの省略可能な `automaticSlot` に保存する。旧記録では最後のscheduled requestのslotを使い、自動送信の記録がなければ表示しない。

## 並べ方

`TranscriptEntries.merge` は変えない。AIの行はUtteranceではないので、併合結果へ混ぜず、別の純関数で位置だけを決める。

`KikigakiCore/AITimeline.swift` に副作用のない `AITimeline.items(conversation:utterances:timeline:generation:endedAt:)` を置く。返すのは表示に必要な値だけを持つ `AITimeline.Item` の列で、AppKit型・色・フォント・時刻の書式を含めない。時刻はDateのまま返す。

```swift
public enum AITimeline {
    public enum Kind: Equatable, Sendable {
        case sendLine(automatic: Bool)   // 細い1行
        case sendRow                     // 人側の送信行
        case reply(ReplyState)           // AIの行。waiting / answered / needsInput
        case failure(reason: String, returned: Bool)  // 朱の帯。returned はモデルが返した失敗報告
    }
    public enum Anchor: Equatable, Sendable {
        case afterUtterance(Int)   // 声の送信。voiceAnchorIndex の直下
        case at(Date)              // 日時順
        case tail                  // 末尾。返事待ちの行だけ
    }
    public struct Item: Equatable, Sendable {
        public let kind: Kind
        public let anchor: Anchor
        public let slot: Int       // 直前に置く発話の添字。-1は全発話より前
        ...
    }
}
```

`Item` は行が要る値を全て持つ。`requestID`・`number`・`participantName`・`automatic`・`date`・`durationSeconds`・`question`・`parentNumber`・`body`・`notes`・`timeRange`・`needsAnswer`・`canCancel`・`rowID` で、描画側に判定を残さない。`notes` は「対象: 4発言」「作業許可なし」「暫定末尾を含む」「送達不明」「取消後の返事」などの完成した文字列にする。`AIRequest.automaticLabel` と同じく、表示用の短い文字列はCoreに置く。

返事待ちの接続状態と返送未確認は `AIProgress` で進行文を導き、`notes` へ重ねない。宛先slotと世代を渡し、世代の異なる観測はAIProgressで不明として扱う。詳細は [AI依頼の進行表示](ai-progress.md) を参照。

順序の規則は次のとおり。

- `afterUtterance` はその発話の直後へ、同じ発話に複数あればrequest番号順に置く
- `at(date)` は**最初に自分より新しい発話の手前**へ置く。発話の日時は音声位置と投稿順で並ぶので単調とは限らず、最後の一致で探すと間の発話を飛び越える。**同時刻なら人が先で、AIはその後ろへ付く**
- 録音を停止した日時を入力に受け、それ以後に届いた返事は末尾へ置く。時計が飛んでも「停止後の返事は末尾」を保てるようにするため
- `tail` は全ての発話とAI行より後に置く。**返事待ちの行が上へ跳ねないようにするための規則**で、送信時刻の位置ではなく常に末尾側へ置く。返事が届いた時点で `at(resultReceivedAt)` へ変わり、そのときの末尾がそのまま確定位置になる
- 返事待ちが複数あるときは `sendAttemptedAt` の順に末尾へ並べる
- 同じ位置・同じ日時では送信が先。返事同士は**記録順** `resultOrder` で並べ、記録を持たない送信前の失敗を先頭へ置く。request番号ではない。最後に生成順で必ず全順序にする

行IDは `requestID + "/send"` と `requestID + "/reply"` の2種類にする。送達不明は送信の行の注記なので `/send`、それ以外の状態は `/reply` を指す。

## 行ビューと再利用

`TranscriptDocument` の再配置とアンカーの仕組みは変えない。行の同一性だけを整理する。

- 返事待ちの行と返事の行は**同じビュー・同じ行ID**にする。差し替えではなく状態更新にすることで、返事の到着で行が消えて生まれ直すことがなくなり、高さの変化がアンカーの候補から外れない
- 送信の細い1行・人側の送信行・失敗の帯もrequest単位のビューを再利用する。`TranscriptWindow.aiRows` の辞書は、現在の行IDに無いビューを更新のたびに捨てる
- 末尾追従中はAIの行追加と状態変化でも末尾を追う。AIだけの更新で `atBottom` を落とさず、上へスクロール中はアンカー、検索中は `followsBottom` により位置を保つ
- 引用行の開閉は行の高さの変更として `reflow` へ渡し、開いた行の上端をその場に保つ
- 高さの計測は `MarkdownBodyView.height(for:)` を使い、`cellSize` と混在させない。幅が変わったときの再計測も既存どおり

上へスクロール中・検索中は到着で読んでいる位置を動かさない。行の追加位置が可視域より下なら現在の見出しを保ち、上なら `anchor.candidates` の生き残り行を基準に位置を戻す。遅れた返事が可視域より上へ入る場合も、このアンカーで高さの変化を吸収する。

## フッターからの移動

フッターの朱の丸の件数と下の「要返答」は、未回答の確認質問の件数を示し、0件なら隠す。クリックで該当する最初の行へ移動する。警告はクリックで対象の行へ移動し、対象の行がないときは全文を表示する。manifestが欠損した会議の登録だけの回収警告は出さない。

## 検索と複数プロファイル

- **検索**: `TranscriptWindowSearch` は `snapshot.utterances` だけを走査し、ヒットを `RowID` へ紐づける。AIの行はUtteranceではないので対象外。本文を検索対象へ入れると `SearchHit` の設計が変わるため、扱っていない
- **複数プロファイル**: 宛名は `question.request.envelope.participant.participantName` からだけ読み、会議単位の既定値へ依存しない。細い1行と人側の送信行の宛名にその名前を入れる。行の色は全プロファイルで同色にし、名前で区別する。プロファイルの設定は [ai-profiles.md](ai-profiles.md) を参照する

## 設計の判断

| 論点 | 決定 | 理由 |
|---|---|---|
| AIのアバター色 | `Washi` へAI専用色を1つ足す。複数プロファイルでも同色にし、名前で区別する | 話者の枡の色を流用すると、その枡を使う会議で人とAIが同色になる。プロファイルごとに色を配ると枡の色と衝突する組合せが増えるため、AIは1色に固定して名前で分ける |
| 人側の送信行の名前 | 「手入力」を流用せず、墨の丸に `paperplane` のアバター、名前は「AIへ送信」、右端に宛名を出す | 「手入力」は会話へ残る投稿の固定名で、会議Markdownの `## 書き起こし` にも出る。AIへ送っただけの文が議事録に載っていると誤解される。行の形は人側のまま変えない |
| 引用の全文の出し方 | クリックでその行を全文へ伸ばし、再クリックで1行へ戻す | ポップオーバーやtooltipは、本文と並べて読み比べられない。既存の開閉と同じ `reflow` の経路を使えるので、位置の保ち方も検証済みのものを流用できる |
| 「ペインを開く」の置き場所 | 行から外し、フッターの「…」メニューへ1つだけ置く | AIの行は常に展開されるので、全ての返事の行に同じボタンが並ぶ。保存の再試行などの接続の操作は既にフッターにあり、そこへ揃える |
| AIの本文を検索対象へ入れるか | 対象外にする | `SearchHit` は `RowID` と発話の添字に紐づいており、AIの行を入れると検索の設計自体が変わる。Markdown描画の `NSTextStorage` へのハイライトも別の作業になる |
| 自動送信の返事待ちを行として出すか | 出す。手動送信と同じ進行文とバーの行にする | 自動だけ状態を隠すと3分ごとに理由の分からない行が生えることになる。目立たせないのはチップと薄墨で足りる |
