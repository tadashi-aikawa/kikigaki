# 繰り返し相槌の省略

`dropRepeatedBackchannels = true` で、停止時に短い繰り返し相槌の候補を省く実験機能。既定は無効。録音中には適用しない。

## 対象と限界

- 「うん」または「そう」の2回以上の連続を、トークンを丸ごと連結して認識する。1個のトークンに本文も混ざっている場合は削らない
- 候補は同一フレーズ内で1.5秒未満。多数決後はすべて同じ話者で、候補の直後に同じ話者の本文が続くことを要求する
- 候補内の窓判定をトークンの実時間長で集計し、過半数が別の同一話者に属するときだけ省略する。窓の重なりが同点の場合も不明とし、不明・非正の長さを含む候補は省略しない
- 1回だけの「うん」「はい」や、独立した返答は対象外。窓判定自体の誤りや通常の文章との区別には限界があり、誤削除ゼロは保証しない
- 最大の繰り返し全体で判定し、長い反復の一部分だけを短い相槌として切り出さない
- 同じ語の反復だけを扱う。空白・句読点は反復の途中に挟まない。直後のトークンが空白・句読点だけ、無音が0.35秒以上、フレーズ末尾の場合は省略しない

74〜75秒の実録ログでは「うんうん先週」の別話者の塊が「んうん先」になっていた。話者の塊ではなく、文字列で完結した相槌を先に探す理由は、本文の「先」を巻き込まないため。

## 保存と再設定

- 有効時は通常の `.md` に省略後の結果、同名の `.raw.md` に省略前の結果を保存する。省略が0件でも原文を保存する
- 原文保存に失敗した場合は省略を適用せず、画面と通常の `.md` は原文に戻す。その会議は以後の改名でも省略を再適用しない
- 話者名を付け直すと両方へ反映する。設定の再読込は次の録音から適用する
- 省略前と省略後の発話を別々に保持する。ファイルごとに原子的に更新し、原文成功後に通常ファイルが失敗した場合は原文を保持してエラーを表示する。2ファイル同時の更新は保証しないため、失敗時は名前が不一致になり得る
- 同じ分に録音を始め直しても既存の `.md`、`.wav`、`.raw.md` を上書きしないよう、使用済みの名前には連番を付ける
- 音源開始前に `.md` を排他的に予約する。開始失敗時は自分が予約した空ファイルだけを片付ける。この予約手順を使うアプリ同士の衝突を防ぐもので、外部プログラムによる録音中のファイル変更までは保護しない

## 検証

実録ログのトークン時刻を回帰テストへ使い、本文を保持すること、長い反復・同一話者・不明・同点・混在トークンを残すことを確認する。同じ音声をreplayして、省略前後の保存物を比較する。原音での正解付けは別途必要で、ログ上の推定話者を正解扱いしない。

## 実録で確認した範囲

`2026-09-05_1412.wav` のreplayでは、74.58〜75.06秒の「うんうん」1件が候補になった。「先週も言ってました。」は残り、省略前後の本文差分は「うんうん」の4文字だけだった。無効時の書き起こし本文と、有効時の `.raw.md` の本文も一致した。

146秒付近の「そうそうそうそう」は、窓判定も多数決後も周囲と同じ話者のため残る。これは本人の発話だと確定した意味ではなく、今回の条件では省く根拠が足りないという意味。実際の話者や省略品質の人手評価は未実施。

保存失敗時はエラーを優先して表示するため、通常の `.md` と画面の一致を保証しない。原文保存が成功していれば `.raw.md` から参照できる。音源の開始失敗時に既に作ったWAVは救済用に残す。
