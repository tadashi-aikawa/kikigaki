# 録音開始シート

「録音を開始」を押すと、その会議だけの指定をまとめて決めるシートが出る。指定を終えてから録音が始まる。

## 目的

会議ごとに変えたいものは、話者判別・議事録・自動送信の3つに集まる。以前はそれぞれ別の場所(人型ポップオーバー・右ペインのパス欄・ロボットのシート)にあり、録音を始めてから設定し直すことになっていた。始める前に1枚へ集める。

設定ファイルに書くもの(保存先・話者台帳・CLIの種類)はここへ置かない。会議ごとに変える値ではないうえ、シートから書き戻すと設定ファイルの正本が2つになる。

## 出す場面と決めるもの

シートは `MeetingSession.start` の**前**に出す。取消は録音を始めないので、会議の巻き戻しは要らない。

| 行 | 決めるもの | 既定値 |
|---|---|---|
| 話者判別 | 「区別する(最大4人)」/「区別しない」 | 前回の選択(UserDefaults) |
| 小音量除外 | ON/OFFのスイッチ。しきい値は文字で見せるだけで、調整は録音中の「話者…」に残す | 次回設定の値 |
| 議事録 | 絶対パス。履歴・「ファイルを選ぶ…」・`.md` のドロップから入れる | 空欄(指定なし) |
| 自動送信 | 宛先・間隔・プロンプト・作業許可・最後の1回 | 宛先は `autoStart` のプロファイル、無ければ「送らない」 |

`[[ai]]` が無ければ自動送信の行ごと出さない。宛先メニューの各行はアバター・名前・CLIとモデルとeffort・プロンプトの先頭で、同じ名前と型のプロファイルを依頼の中身で見分けられるようにする。プロンプトは畳まず、幅いっぱいの欄に数行ぶん見せてそのまま書き換える。

**説明文は置かない。** 「録音を始めると変えられません」「開始と同時に右のペインへ表示します」のような補足は、毎回読まされる割に決めるものを増やさない。読めない議事録の指定に出す理由の1行だけを例外にする。

シートの幅は640pt。既定のウィンドウ(600pt)より広いが、議事録の絶対パスを縮めずに読めることを優先した。

⏎ と ⌘⏎ のどちらでも開始する。プロンプト欄に焦点がある間だけ、素の⏎は改行になる。Escと「取消」は何も始めない。

## 値の行き先

シートが決めた値はこの録音にだけ効き、設定ファイルへは書き戻さない。

- **話者判別**: 開始時に `setDiarizationEnabled` を呼ぶ。次回の既定にもなる。取消した選択は残らない
- **小音量除外**: 開始時に `setAudioExclusion` へON/OFFだけを重ねる。しきい値は次回設定のまま。こちらも次回の既定になる
- **議事録**: `MeetingSession.prepareMinutes` で預ける。**この場では表示中の会議のstoreへ当てない。** 停止後も前の会議のMarkdownは残っているので、いま当てると前の会議の議事録になってしまう。`start` が会議を切り替える時点で待機指定へ移し、`previewMinutesStore` が新しい会議へ引き継ぐ。指定があれば開始と同時に右ペインを開く
- **自動送信**: `MeetingSession.pendingAutomaticSchedule` へ枠と `AIScheduleOptions` を預け、`startAutomaticSchedule` が設定の `autoStart` の代わりに使う。**「送らない」を選んだ会議では、設定に `autoStart` があっても始めない。** 指定は1回だけ効き、次の録音へは持ち越さない

宛先を選び直すと、その宛先の `autoPrompt`・`autoIntervalMinutes`・`allowWork` を初期値として出す。シートの中で書き換えた文面と間隔は宛先ごとに覚え、選び直して戻れば元に戻る。

## 出さない場面

- **replayと検証**: シートを出さず、前回の値と `KIKIGAKI_DEBUG_*` の指定で同じ開始経路を通す。`pendingAutomaticSchedule` は未設定のままなので、設定の `autoStart` が従来どおり効く
- **待機中以外**: `kikigaki://` のリンクが録音中・準備中・保存中に届いてもシートは出さない。始まっている会議の議事録を後から差し替えると、どの会議の議事録なのかが分からなくなる

## URLスキーム

`kikigaki://start?minutes=<パーセントエンコードした絶対パス>` で、議事録を入れた状態のシートを開ける。議事録を用意する側がリンクを出し、人がクリックして開始シートが出るところまでが役目で、リンクから録音そのものは始めない。押し間違いや古いリンクで勝手に会議が始まらないよう、開始を押す一手は人に残す。

| 届いたもの | すること |
|---|---|
| 検証を通った `minutes` | パス欄へ入れてシートを出す。開いている最中なら差し替える |
| 読めない `minutes` | パス欄は触らず、議事録欄の下の1行へ理由を出す |
| `minutes` が無い | パス欄はそのままでシートを出すだけ |
| `start` 以外のホスト・別スキーム | 何もしない。別アプリ宛のURLで画面を出さない |
| 待機中以外に届いたリンク | シートを出さず、ヘッダーの1行へ理由を出す |

- **解析は `KikigakiCore.KikigakiURL.start`**。`~/` は展開し、`~他人/` は展開せず絶対パスでないものとして落とす。検証は議事録の指定と同じ `MinutesPath.validate` に合わせ、ここだけ緩めない。ファイル自体は未作成でもよく、作成後に自動で表示する既存の契約に乗る
- **`minutes` 以外のクエリは無視する**。リンクを出す側が先に新しい指定を書いても、古いアプリが黙って開始シートまでは出せるようにする
- **受け口は `applicationWillFinishLaunching` で開ける**。`open kikigaki://…` での起動では、`NSAppleEventManager` への登録が終わる前にイベントが届く。配線が済むまでは `AppDelegate.pendingURL` へ持っておき、`applicationDidFinishLaunching` の最後にまとめて流す
- **受け入れた値は記憶しない**。人が確定した指定と同じで、この録音にだけ効く
- **検証はDEBUGの `--open-url <url>`**。LaunchServicesは同じバンドルIDのうち先に登録された `.app` へURLを配るため、`open` では組んだばかりの `.app` に届くとは限らない

## 決めなかったこと

- **議事録欄の初期値に前回のパスを入れない。** 議事録は会議ごとに別のファイルになるほうが多く、前回のパスが残っていると気づかないまま前の会議の議事録を上書きさせてしまう。1クリックで選べる履歴があれば足りる
- **「前の会議」の行と停止後ヘッダーの保存先表示は出さない。** 設定ではない情報を設定の並びへ混ぜない
- **グローバルショートカットは廃止した。** 開始が対話操作になったので、キーだけで始められる意味が無くなった。設定の `[hotkeys]` と `[ai.hotkey]` は読み飛ばし、エラーにも警告にもしない
- **録音の取り止め(`abandon`)も外した。** 開始前に取消せるので、始まった会議を保存せず巻き戻す経路が要らなくなった

## 検証

- `StartSheetTests`: AI区画の有無、宛先の既定と選び直し、「送らない」の畳み、プロンプトの展開、議事録の検証とドロップ、取消
- `StartSheetScheduleTests`: シートの値での自動送信、「送らない」で設定の `autoStart` を使わないこと、議事録を次の会議へ持ち越すこと
- `URLSchemeTests`: リンクの解析。パーセントエンコード・`~` 展開・別ホスト・別スキーム・余分なクエリ・読めない議事録
- `URLSchemeAppTests`: リンクからのシートの表示と差し替え、読めない議事録での1行、待機中以外での断り
- 見た目は `KIKIGAKI_START_SHEET_CAPTURE=<出力先> swift test --filter StartSheetTests` でPNGへ撮り、モックと突き合わせる
