# 話者判別の切替

会議開始前に話者判別を選び、無効時は文字起こしの確定後すぐに発言として表示する。

## 目的

1人での壁打ち、話者を区別しない会議、5人以上の会議では、話者判別を停止して文字起こしの確定結果をすぐ利用できるようにする。

「即座に確定」はApple Speechが確定結果を返したら話者待ちを加えない意味とする。暫定結果は従来どおり薄く表示し、後から訂正される文字を確定扱いしない。SpeechTranscriberは暫定から確定まで同じ範囲を更新する契約を持つ。発話開始からの遅延ゼロは保証しない。

出典: [Apple SpeechTranscriber.Result](https://developer.apple.com/documentation/speech/speechtranscriber/result)

## 利用方針

- 録音開始前に選び、その会議では固定する。準備中・録音中・一時停止中・最終処理中は変更できない。
- 初期値は有効。前回の選択を次の会議とアプリ再起動後にも引き継ぐ。
- 無効時の音声行は全員共通の「発言」とし、話者の改名・統合の対象にしない。手入力・AI返答の表示は独立して維持する。
- 確定トークン間の1秒以上の間隔、または文末の句点・疑問符・感嘆符で新しいフキダシにする。確定結果のIDだけでは区切らない。語の途中で結果が切れることがあるため。
- 長く話し続けても単一のフキダシにならないよう、既に30秒以上ある行は次の確定結果境界で区切る。語分割は後続文脈で変わるため、この上限の判定には使わない。トークンを文字単位に分割せず、長さの上限は目安とする。閾値は実録replayで確認する。

録音中の切替は行わない。

## UI

既存ヘッダーの人型ボタンを「話者」設定の入口として継続使用する。ポップオーバーで「次の録音」の設定と「表示中の会議」の話者統合を別の区画にする。ヘッダーは表示中の会議の状態を表す。会議がない待機中だけ次回設定を予告する。

- 開始前: スイッチ操作可。「話者を区別しないと、文字起こしの確定後すぐ表示します」など効果を短く説明。
- 録音中: 現在の有効・無効を表示。スイッチは操作不可で「録音開始前に変更できます」と理由を添える。
- 無効時: ヘッダーの件数を「なし」にし、人型に斜線を加える。色だけに頼らず状態を示し、統合用の空枠を並べない。発言行は中立色のマイク記号と、薄墨の「発言」ラベルを使う。
- 停止後: 次の録音の選択を変えても、ヘッダー・表示中の会議の行・保存物・名前は変わらない。

クロディーヌのUIレビューを反映。録音中も次回設定だけ操作できる提案は、ユーザー承認済みの開始前限定を優先し採用しない。準備中から最終処理中まではスイッチを無効にし、変更できる時点を併記する。

## 実装の境界

### 設定とエンジン

選択は専用のUserDefaultsキーで永続化し、MeetingSessionの開始時に値コピーする。次回の選択と現在の会議のモードは別に保持する。既存TOMLへは書き戻さない。replayとテストには明示的に値を注入し、日常設定を汚染しない。

無効設定で起動したときはSortformerモデルをロードしない。有効設定での起動と有効へ切り替えたときは先読みし、録音開始までに準備する。進行中のロードと成功分を共有し、失敗Taskは捨てて次の開始で再試行できるようにする。

無効時はSpeakerDiarizerの生成・モデル取得・音声投入・末尾の無音補完・最終判定を実行しない。AppleTranscriberへの入力はそのまま続ける。

### 確定表示と分割

無効モード用の共通行生成をCoreに置く。LiveTranscript、MeetingResult、AICaptureが同じ行境界を使う。有効時のAlignerとSpeakerFreezeの動作は維持する。

無効モードはfinalCountまでを確定扱いにし、pendingSpeakerRowsを常に空にする。AppleTranscriberの結果更新を通知し、MainActorで会議世代を照合して再表示する。確定増分は直ちに表示し、暫定だけの変化は0.5秒間隔にまとめる。末尾に1回の反映を予約するため、通知が止まっても最後の暫定文字を捨てない。録音中・一時停止中とも反映し、古い会議や停止処理の結果を上書きしない。

既に閉じた行は後続の確定結果で結合し直さない。最後の行への追記は許容する。停止時も同じ区切りを使い、全体が1行に戻らないようにする。

### 行の意味と保存互換

話者なしを話者Aや判定失敗の「?」に偽装しない。会議単位で保存・受け渡しされるSpeakerNamesに話者判別モードを1つ保持する。属性の欠損は従来の有効と読み、古い不明話者の表示は「?」のまま残す。Utteranceの入力種別や保存形式は変更しない。

表示名はSpeakerNames.displayNameで「発言」へ解決し、画面・検索・コピー・Markdown・AI文脈・再起動後の過去会議で一致させる。新しい属性はMeetingArchive.original.namesへ保存する。AIとの外部envelopeは文字列の行を使うため、JSON契約を増やさない。旧アプリでarchiveを書き直すとこの未知属性が落ち、会議全体が従来の「?」表示へ戻る。ダウングレード後の意味の保持は保証しない。

無効時は話者の同一性を前提にする繰り返し相槌省略を適用せず、原文を残す。停止時に話者判定を走らせない。次会議の選択変更で過去会議を書き換えない。

AIConfirmationWaitはASRの暫定結果・未処理入力を最大3秒待つ既存仕様で、話者の30秒を直接待たない。ここは待ち時間を変更せず、AICaptureが無効モードの行生成を使用するようにする。

## 受け入れ検証

- 無効で開始するとモデル取得と話者処理を呼ばず、ASR確定の次の表示更新で通常行になる。静音時・一時停止直後の確定通知も確認する。
- 暫定結果の訂正は確定列に混ぜず、確定した本文を重複・欠落させない。
- 無音、句点、結果ID境界が語中にある発話、長い独話を検証し、停止前後・コピー・AI文脈・保存後で区切りが一致する。
- 有効→無効→有効の会議を開始し、モデル再利用・設定永続・会議ごとの固定を確認する。
- 無効会議の再読込は「発言」、旧archiveの不明話者は「?」、手入力とAIの名前・時刻・検索は維持する。
- 実録を同じ条件でreplayし、音声位置・ASR確定受信・画面反映の実時刻を分けて測る。replayは早回しなので発話からの実遅延評価には使わず、モデル呼び出しゼロとASR確定後の追加待ちがないことを確認する。
- Swiftの関連ユニットテスト、全テスト、ビルド、UI状態別確認。
- `KIKIGAKI_TEST_SPEECH=1 swift test --filter DiarizationTests` は実際のApple Speechに無音を流し、モデル呼出ゼロ・省略用rawなし・会議ごとの切替を検証する。マイクは使わず、一時ディレクトリへ保存する。通常の全テストではこの実エンジン部分だけスキップする。
