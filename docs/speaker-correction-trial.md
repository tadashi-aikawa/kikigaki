# 話者補正の除外比較とフレーズ固定の試験

Nemotron fast128 の話者区間に対して、KIKIGAKI 側の話者補正がどれだけ効いているかを、同じ入力で補正を外して比べる。あわせて、録音中の話者固定を30秒猶予からフレーズ確定条件へ置き換える案を試す。

比較の結果から、短い島の吸収を外し、フレーズ固定を本番にした。あわせて語内の長い語頭の付け替えを足した。[採用](#採用)

- 比較の対象はトークンへの話者の割当と補正だけ。ASR自体と話者判別モデルの出力は全条件で同じ
    - 繰り返し相槌の省略は、比較でも試験の replay でも無効にした。保存の `.md` とは違う場合がある
    - 手動の話者統合・速報と高精度の合流・小音量の除外は対象外で、比較に含めない
    - 行の区切り(同じ話者で1秒以上の無音)は補正ではなく、全条件で同じ規則を使う

結果: [比較結果](#結果)

## 採用

2026-09-26 にタダシが選んだ組合せを本番にした。試験用の条件切替は本体から外した。

| 項目 | 採用 | 選択肢 |
|---|---|---|
| 話者の割当 | `current-absorb`。窓判定・tail・word・punct。吸収と保護、evidence は削除 | 現行を維持・窓判定だけ・点判定 |
| 録音中の固定 | `phrase` | 30秒猶予 |

- 吸収を外すと、evidence と protect は効果を持たない。コードごと削除した
- 追加の補正: タダシから「先頭1文字だけ話者が異なるケースは、その後の話者を正として続くことがほとんど」との指摘を受けた
    - 対応: 語内補正に、長い1文字の語頭だけを後続の話者へ付け替える条件を足した。条件は [語内の長い語頭](speaker-boundaries.md#語内の長い語頭)
    - 限定: 不明の語頭を新しく補うことはしない。後続話者の声が語頭の末尾0.12秒以上を覆うことも必須にした。観測した箇所では条件の差は出なかったが、一般の入力の反例を防ぐため
    - 推測: 対象の2例では、語頭の前半は文字にならなかった別話者の声で、語頭の文字は末尾で発音されたと考える。区間データからの推測で、原音で確かめたのは話者の正解だけ

## 用語

| 用語 | 意味 |
|---|---|
| 話者区間 | Nemotron の出力を `SpeakerRuns` で畳んだ `SpeakerSegment` |
| 点判定 | トークン中央時刻 t を含む区間 (`start <= t < end`) の話者。複数あれば番号の小さい話者。無ければ不明 |
| 窓判定 | 既存の `Aligner.speaker(at:)`。中央±0.5秒の窓と区間の重なりを話者ごとに合計して最大を採る |
| 補正 | 窓判定・点判定の後に話者を書き換える処理。下表の6つ |

- 点判定の同時発話の扱いは、無補正の意味を単純にするための規則で、正しい話者を保証しない
- `KIKIGAKI_DEBUG_PHRASES` のログが「生の判定」と呼ぶのは窓判定。この試験では「raw」という語を使わない
- 窓判定もそれ自体が±0.5秒の平滑化なので、「全補正なし」は点判定 `point` と窓判定 `window` の2条件に分ける

## 補正の一覧と切替

`Aligner.Options` で各補正を個別に外せる。既定値 `.current` は従来と同一の結果を返す。

| 記号 | 補正 | 場所 |
|---|---|---|
| tail | 長い1文字の語頭を後続話者へ付け替える | `SpeechTail.speakers` |
| evidence | 長い1文字の多数決の重みを検出された声の時間へ絞る | `SpeechTail.evidenceWeights` |
| word | 語内で割れた話者を文字数の過半数へ揃える | `smoothSpeakers` の語内補正 |
| absorb | フレーズ多数派と違う1.5秒未満の島と、語を切る不明の島を多数派へ吸収する | `smoothSpeakers` の島の処理 |
| protect | absorb の例外。完結語・文末・相槌プリセット・応答末尾・修復した語頭の核を残す | 同上 |
| punct | 句読点だけのトークンを直前の話者へ付ける | `smoothSpeakers` の末尾 |

- 依存: absorb を外すと protect と evidence は効果を持たない。protect だけを外すと、短い島を例外なしに吸収する
- 句点は punct を外しても、多くは absorb が直前の話者へ戻す

| プリセット | 割当 | 補正 |
|---|---|---|
| `current` | 窓 | 全部 |
| `window` | 窓 | なし |
| `point` | 点 | なし |
| `current-tail` 等 | 窓 | 1つだけ外す。6種 |

- 補正を順に積み上げる比較は、1つずつ外した結果から必要になったときだけ行う

## 比較の入力を固定する

ASRを条件ごとに走らせ直すと、認識の試行差が補正の差に混ざる。1回のreplayで入力を保存し、全条件をその保存物へ適用する。

- `KIKIGAKI_TRIAL_DUMP=<dir>` で `<dir>/<会議名>/` へ書き出す。中身のある保存先は使わず、録音を始めない
    - `meta.json`: 流した速さ(`mic` / `replay-realtime` / `replay-accelerated`)と記録時の条件
    - `final.json`: 停止時の全トークンと区間。時刻は丸めない
    - `live.jsonl`: 録音中の描画ごとの snapshot
        - 中身: 消費音声秒・壁時計・トークン・`finalCount`・`accurateFinalCount`・区間・`judgedUntil`・その描画でアプリが新しく凍結した話者
        - トークンは直前の snapshot との共通接頭辞数とそれ以降だけ、区間は変わったときだけ書く
    - 会話本文を含むので、出力先はリポジトリ外の作業用ディレクトリに限る
- 比較は DEBUG の `Kikigaki --align-compare` で行う。UIもモデルも起動しない
    - 最終判定: 各プリセットを `final.json` へ適用する
    - 録音中: 各固定方式で、録音中の突き合わせループを `live.jsonl` の上で再生する
    - 疑似試験との違い: 最終トークンを時刻順に流し直すのではなく、実際の録音中の速報・未確定を含む列を使う
- 検証
    - 高精度側の確定済み接頭辞が後の snapshot や停止時と食い違う記録は、比較をエラーにする
    - 記録時と同じ条件の再生が、アプリの実際の凍結列と全描画で一致するかを照合する

## 固定方式

`KIKIGAKI_TRIAL_FREEZE=grace30|phrase`。未指定は `grace30` で従来と同じ。停止時はどちらも凍結を外して全体を再判定する。

### フレーズ固定の条件

`SpeakerFreeze.advanceByPhrase`。凍結済みの末尾から始まるフレーズ P を、次の全てを満たすときに丸ごと凍結する。満たさなければそこで止め、後ろのフレーズも凍結しない。

1. P の全トークンが高精度側で確定済み
2. P の終端が確定している
    - 文末記号で終わるなら、それだけで確定
    - 0.35秒の間・結果境界で閉じる場合は、次のトークンも高精度側で確定済み
        - 理由: 速報側のトークンは `phraseId` が負で必ず結果境界になり、後で差し替わる
3. tail 有効の条件だけ、P 内の長い1文字の後の最初の有意文字が P の外にあれば、その文字も高精度側で確定済み
    - 後続の有意文字がまだ無ければ保留する
    - tail を外した条件では待たない。待ちの差はこの依存の有無による
4. 判定済み末尾 `judgedUntil` が、読む区間の範囲以上
    - 範囲は、P のトークンと3の依存文字の `max(終端, 中央+窓の半幅)`。半幅は窓判定で0.5秒、点判定で0
    - 終端は、尾部・覆い・重みの判定がトークンの時間の区間を読むため。点判定でも保守的に含める
    - 根拠: `SpeakerRuns` は判定済み範囲の中身を後から変えない

- 長い無音の直前のフレーズは、文末記号が無いと次の発話が高精度で確定するまで凍結しない。30秒での逃げ道は置かず、未凍結のまま停止した件数として測る
- 取消は保存しないので対象外。モデル失敗後は `judgedUntil` が止まり、条件4で凍結も止まる。一時停止中は入力が無く、どちらの方式も進まない
- 既存の `grace30` は変えていない。その `judgedUntil` の確認は終端までで窓の先を含まないが、30秒の猶予が実質的に覆う

## 測るもの

正解の無い差を精度と呼ばない。

| 区分 | 指標 |
|---|---|
| 最終判定 | `current` との差: トークン数・文字数・差分フレーズの本文 |
| | 絶対値: 行数、話者切替数、断片行数、句読点だけの行数、不明の文字数、処理時間 |
| 正解あり | 9/26 の指摘区間でイチローの枠に付いた文字数 |
| | 旧fixture: 各プリセットで既存の実録由来テストの期待が保たれるかの表 |
| 録音中 | 固定待ち: トークン終端から凍結までの音声秒。中央値・p90・最大 |
| | 確定待ち: トークン終端から高精度確定までの音声秒。どの方式も凍結はこれより早くならない |
| | 未凍結のまま停止した件数と割合、そのうち確定済みで保留した件数 |
| | 停止時と不一致、凍結後の snapshot で判定し直すと変わった件数、固定前の話者の揺れ |

- 待ちは音声秒で、文字起こしの確定待ちを含む。話者判別モデルの推論速度そのものではない
- 等倍の記録では、最初と最後の描画の壁時計秒と音声秒の比も出す。消費がどれだけ遅れたかを示し、音声秒の待ちと壁時計の待ちの差を読むため
- 断片行: 有意文字1〜2字の行。相槌も含むので、多いこと自体を悪いとは断定しない
- 旧fixtureは Sortformer 時代の区間で作られている。その補正が当時の事例に効いたことを示すだけで、Nemotron での要否の根拠にはしない
- 差分の本文には時刻を付け、原音で聞き分けられる形にする

## 手順

### 記録

試験用 `.app` を組む。起動中の通常の `.build/KIKIGAKI.app` には触れない。

```sh
KIKIGAKI_TRIAL=1 ./scripts/make-app.sh
```

- 出力は固定の `.build/trial/KIKIGAKI-Trial.app`。識別子 `com.tadashi-aikawa.kikigaki.trial`
    - UserDefaults・マイク許可が本体と別になる。初回にマイク許可を求められる
    - AI会議の登録先は `~/Library/Application Support/KIKIGAKI-Trial`。本体の `KIKIGAKI` とは別で、起動時の復元で本体のAI会議を拾わない
        - 識別子を分けるだけではこの置き場は変わらないため、識別子を見て切り替える
        - replay の隔離条件 (`KIKIGAKI_DEBUG_TYPED_VERIFY=1` 等) を満たすときは、従来どおり保存先の `.typed-test-support` を優先する
        - 未対応: AIの既定の作業ディレクトリ `~/Library/Application Support/KIKIGAKI/ai-work/` は共有のまま。試験ではAIを設定しない
    - `kikigaki://` のリンクは受け付けない
- 既定の `make-app.sh` は従来どおり `.build/KIKIGAKI.app` を作り直す

replay で記録する。設定は作業用ディレクトリに置き、AIを設定しない。

```toml
outputDir = "/tmp/kikigaki-trial/0237/meeting"
saveRecording = false
dropRepeatedBackchannels = false
```

```sh
APP=.build/trial/KIKIGAKI-Trial.app/Contents/MacOS/KIKIGAKI
KIKIGAKI_DEBUG_DIARIZATION=on KIKIGAKI_DEBUG_TYPED_VERIFY=1 KIKIGAKI_DEBUG_REPLAY_REALTIME=1 \
KIKIGAKI_TRIAL_ALIGNER=current KIKIGAKI_TRIAL_FREEZE=phrase KIKIGAKI_TRIAL_DUMP=/tmp/kikigaki-trial/0237/dump \
  "$APP" --config /tmp/kikigaki-trial/0237/config.toml --replay ~/Documents/KIKIGAKI/2026-09-26_0237.wav
```

- `KIKIGAKI_DEBUG_TYPED_VERIFY=1` はAI登録先を保存先の中へ隔離するために付ける
- `KIKIGAKI_DEBUG_REPLAY_REALTIME=1` を外すと約10倍速。待ちの値は代表値にしない

### 比較

```sh
.build/debug/Kikigaki --align-compare /tmp/kikigaki-trial/0237/dump/<会議名> --out /tmp/kikigaki-trial/0237/compare \
  --expect 45.24-47.94=2 --expect 107.40-109.74=2 --names 0=司会,1=堀田,2=イチロー
```

- 出力: `comparison.md` (条件別の集計と時刻付きの差分本文)・`comparison.json`・`transcripts/<条件>.md` (条件ごとの全文)
- 録音中の再生は既定で `current` / `window` / `point` の3条件。`--live-presets` で変えられる。`--no-live` で省く
- 旧fixtureの行列: `KIKIGAKI_TRIAL_FIXTURE_REPORT=<出力.md> swift test --filter SpeakerTrialOptionsTests`

### マイクで試す

設定の例は `/private/tmp/kikigaki-correction-acceptance-01a0d933/mic.toml`。AIなし・録音WAVあり・相槌省略なしで、保存先は同じディレクトリの `mic/meeting`。

```sh
MIC=/private/tmp/kikigaki-correction-acceptance-01a0d933
TRIAL=.build/trial/KIKIGAKI-Trial.app

# 補正を全て外す: 点判定だけ。窓の平滑化も外す
open -n $TRIAL --env KIKIGAKI_TRIAL_ALIGNER=point --env KIKIGAKI_TRIAL_FREEZE=phrase \
  --env KIKIGAKI_TRIAL_DUMP=$MIC/mic/dump --args --config $MIC/mic.toml

# 窓判定だけ残す
open -n $TRIAL --env KIKIGAKI_TRIAL_ALIGNER=window --env KIKIGAKI_TRIAL_FREEZE=phrase \
  --env KIKIGAKI_TRIAL_DUMP=$MIC/mic/dump --args --config $MIC/mic.toml

# 補正は現行のまま、固定だけフレーズ条件
open -n $TRIAL --env KIKIGAKI_TRIAL_ALIGNER=current --env KIKIGAKI_TRIAL_FREEZE=phrase \
  --env KIKIGAKI_TRIAL_DUMP=$MIC/mic/dump --args --config $MIC/mic.toml
```

- 試験用 `.app` は本体と並べて起動できる。終了はメニューバーの試験版から行う
- `KIKIGAKI_TRIAL_DUMP` を付けると、その会議に全条件を当てて比べられる。会議ごとに別のディレクトリへ書く
    - 比較: `.build/debug/Kikigaki --align-compare $MIC/mic/dump/<会議名>`
- `saveRecording = true` なので、録音WAVを replay で流し直して別条件の画面も見られる
- 試験変数は録音開始時に読んで会議ごとに固定し、stderr へ1行出す
- 録音中の表示・停止時の判定・停止後の統合の再計算・AI送信の会話固定の全箇所で同じ条件を使う

## 既定の扱い

試験の時点の既定は `current` と `grace30` だった。原音を並べた比較の後、[採用](#採用) の組合せへ変えた。

## 結果

2026-09-26 に計測した。試験用 `.app` の replay で1素材1回ずつ記録し、全条件を同じ記録へ当てた。

- 手元だけに置いた成果物: `comparison.md` と `transcripts/`。会話本文を含むためリポジトリに入れない
- 9/26 の等倍の記録は、ASRが加速の記録と別の試行になる。トークン数も1266と1264で違う
