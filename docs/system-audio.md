# システム音声の取り込み

イヤホンでオンライン会議をするとき、Macで再生中の音を取り込み、マイクの音と混ぜて文字起こしへ渡す。

## 目的と位置づけ

マイクだけを聴く録音では、イヤホンへ流れる相手の声が入らない。スピーカーのときに相手の声が入るのは、スピーカーの音をマイクが拾っているためで、イヤホンではその経路が切れる。

KIKIGAKIが重視するのは対面の会議で、リモート会議への対応はサブの機能とする。そのため次の2つを受け入れる。

- マイクとシステム音声は混ぜて1本にし、既存の文字起こしと話者判別へ渡す。別々には文字起こししない。声が重なった部分は崩れる。オンライン会議で声が重なれば参加者自身も聞き取れず、1人ずつ話し直すため、重なった部分を拾うための別系統は持たない
- 取り込むのはMacで鳴っているすべての音で、会議アプリだけには絞らない。通知音や、会議と別に流している音も入る。絞るには会議アプリごとの対応が要り、ブラウザの会議では別のタブの音と分けられない

実現性の試作と実測は [システム音声取り込みの実現性試作の検証記録](records/system-audio-spike.md) にある。

## 開始シートでの指定

[録音開始シート](start-sheet.md) の「話者判別」の上に「システム音声」の行を置く。ラジオの3択で、説明文は置かない。

| 選択 | 取り込み |
|---|---|
| 自動 | 既定の出力がイヤホン・ヘッドホンと判定できたときだけ取り込む |
| 取り込む | 出力の種類によらず取り込む |
| 取り込まない | 取り込まない。従来どおりマイクだけを聴く |

- 既定は前回の選択で、初回は「自動」。選択は専用のUserDefaultsキーへ「開始」を押した時点で保存し、取消した選択は残さない。設定ファイルへは書き戻さない
- 「自動」は、いまの判定を括弧で見せる。`自動(いまは取り込む)` と `自動(いまは取り込まない)`。シートを開いている間に既定の出力が変われば、表示も追従する
- 取り込むかどうかは録音の開始時に決めて会議へ固定する。録音中のイヤホンの抜き差しや出力の切り替えには追従しない。話者判別と同じ扱い
- `kikigaki://start` のリンクから開いたシートでも同じ行を出す
- replayはシートを出さず、取り込まない。検証用の変数を指定したときだけ混合を通す

### 自動の判定

既定の出力デバイスを3つに見分ける。

| 判定 | 自動での扱い |
|---|---|
| イヤホン・ヘッドホン | 取り込む |
| 内蔵スピーカー | 取り込まない |
| 判定できない | 取り込まない |

- 内蔵スピーカーで取り込まない理由: マイクが拾う相手の声と、取り込んだ相手の声が二重に入る
- 判定できないのは、USBのオーディオ機器や外部モニターのように、その先がイヤホンかスピーカーか分からない出力。接続の種類や製品名だけでイヤホンとは決めない。対面の会議を重視するため、分からないときは取り込まない。取り込みたい日は「取り込む」を選ぶ
- 会議アプリが既定の出力とは別の出力を選んでいる場合は、判定が外れる。これも「取り込む」「取り込まない」の明示で補う

## 音源

- 取り込まない会議は、従来の `MicSource` をそのまま使う。経路を変えない
- 取り込む会議は、Core Audioのプロセスタップとマイクを同じaggregate deviceへ載せて同時に読む。マイクを時計の主にし、タップ側はドリフト補正を有効にする
  - タップは自プロセスを除くすべてのプロセスの出力を対象にし、再生は止めない。利用者に聞こえる音は変えない
  - aggregateとタップは非公開で作り、停止時に破棄する。システムの入出力の設定・音量・形式は書き換えない
  - マイクの形式は機器ごとに違う。内蔵と外付けUSBは48kHz、Bluetoothイヤホンのマイクは16kHzの通話用になる。aggregateの公称レートと実際に届くバッファで解釈し、streamごとの表示には頼らない
- 渡す音は従来と同じ16kHz mono Float32。文字起こし・話者判別・小音量除外・音量の計測・録音WAVは、混ぜた後の1本に対して従来どおり動く
- 一時停止は従来どおり、音源を止めずに取り込みだけを止める

## 混ぜ方と音量

マイクの音とシステム音声を、そのまま足して1本にする。音量は揃えない。

- マイクの音は、マイクだけの録音と同じ値で入る。自分の声の文字起こしと、小音量除外の効き方は、従来の録音と変わらない
- システム音声の側も下げない。相手の声は機器の中を通った音で、もともと十分な音量がある
- 足した結果が±1を超えたサンプルは、±1へ制限する。試作では入力音量を最大にした内蔵マイクの最大値が1.64に達した
- 混ぜるための遅延を足さない

マイクの音量は、システム音声より小さいことが多い。試作では、内蔵マイクの既定の入力音量で、自分の声が相手の声の約5分の1だった。この差は受け入れる。声が重なった場面では、小さい側の自分の声が負けて文字にならない。相手の発話に重ねた相づちも同じ。

## 許可と失敗時の扱い

- `Info.plist` に `NSAudioCaptureUsageDescription` を置く。取り込む会議の初回に、macOSが「システムオーディオ録音」の許可を求める。画面収録の許可は要らない
- 取り込みの準備に失敗したら、マイクだけで録音を始め、理由をヘッダーの1行へ出す。会議は止めない。失敗には、タップとaggregateの作成・開始の失敗、対応できない形式が含まれる
- 録音中に取り込みが続けられなくなったら、マイクだけへ切り替えて録音を続け、理由を同じ1行へ出す。Bluetoothイヤホンの切断のように、時計の主にしたマイクが消える場合を含む。黙って無音のまま録音を続けない
- 許可が無いことを確実に見分けられない場合がある。その場合はシステム音声の側が無音になるだけで、マイクの声は従来どおり入る

## 決めなかったこと

- **録音中の出力の切り替えへの追従。** 開始時に固定する。途中でスピーカーへ切り替えると相手の声が二重に入るが、会議の途中で出力を変える場面は少なく、追従は取り込みの作り直しを伴う
- **取り込み中であることの常時表示。** 失敗したときの理由だけを出す。画面に説明を足さない方針に合わせる
- **マイクの音量をシステム音声へ揃える処理。** 実装して測り、外した。声を重ねずに交互に話す音声では、揃えなくても双方の発話が文字になった。試作で自分の声が落ちたのは、声を重ねて話した録音だったためで、重なりは受け入れると決めている。揃える処理は、語頭から揃えるための先読みの遅延、声の無い区間の雑音の持ち上げ、小音量除外の効き方の変化を伴う。測った内容は [検証記録](records/system-audio-spike.md) にある
- **会議アプリだけを取り込む指定。** 上の「目的と位置づけ」のとおり
- **設定ファイルのキー。** 会議ごとに変える値なので、開始シートと前回値の記憶だけで持つ

## 検証

- 検証用の環境変数 `KIKIGAKI_DEBUG_REPLAY_SYSTEM=<wav>` は、replayのときだけ効く。`--replay` の音声をマイクの役、この変数の音声をシステム音声の役として、本番と同じ混合を通してから流す。試作で録った2本の音声を、マイクと出力デバイスなしで端から端まで確かめるための口。書式は [開発用のフラグと環境変数](dev-flags.md)
- 受け入れの観点
  - 相手と自分が声を重ねずに交互に話す音声で、双方の発話が文字になり、自分の声が1人の話者にまとまる。マイクの音量がシステム音声の2〜4割しかない実録から作った素材を含む
  - 入力音量を最大にしたマイクの実録でも、混ぜた音が±1を超えない
  - システム音声が無音のときの出力は、マイクの入力と同じ値になる
  - イヤホンでの実機の会議で、相手の声と自分の声の両方が文字になる。スピーカーでは「自動」が取り込まない
  - 「取り込まない」の会議は、従来と同じ結果になる
  - 録音中にイヤホンを切断しても録音が続き、理由が出る

## 実装の境界

- `KikigakiCore/SystemAudioMix.swift` は3択と出力の3値、16kHzの加算とピーク保護を持つ。
  - 理由: HALとファイルreplayで同じ処理を使い、機器なしで検証するため。
- `Kikigaki/SystemAudioHardware.swift` はHAL情報の読取と出力の分類を持つ。
  - 判定: terminal、data sourceとそのkindでイヤホンを確かめる。接続方式だけでUSBやBluetoothをイヤホンとは決めない。
- `Kikigaki/SystemAudioCapture.swift` はタップ、aggregate、IOProc、リングと変換器を持つ。
  - 時計: 既定マイクを主時計にし、タップのドリフト補正を有効にする。両系統を同じフレーム位置で読み、2channelのまま継続的に16kHzへ変換してから混ぜる。
  - スレッド: IOProcは事前確保したリングへコピーする。変換と混合、デバイス監視は別のworkerで行う。
  - 破棄: IOを停止し、IOとworkerの処理を排出してからaggregateとタップを破棄する。worker上で最後の参照が外れた場合は、そのqueueへsyncせずに後片付けする。
- `Kikigaki/MicAndSystemSource.swift` は準備・録音中の失敗を既存の `MicSource` へ切り替える。
  - 開始: 会議はMainActorからprepareをawaitし、HALの同期開始は専用queueで行う。許可待ち中も画面は「準備中」で応答し、開始完了後に録音へ移る。
  - 理由: 初回のタップ付きaggregateの録音はmacOSの許可要求を伴う。同期の開始が長く待っても、MainActorを占有しないため。
  - 入力: 許可待ち中は別のMicSourceを並走させない。aggregateが開始するまで、その間の自分の声の取得は保証しない。
  - 競合: 開始中の失敗通知はawaitの復帰まで保持し、captureを破棄してからマイクへ切り替える。停止後の遅れた開始完了は適用しない。
  - 復旧: 既定マイクが使えなければ1秒ごとに再試行する。利用可能なマイクが無い間は音声を取得できない。
  - 通知: 理由を `MeetingSession` の既存のヘッダー1行へ渡す。
- 混合は両系統の同じ位置のサンプルをゲイン1で足す。
  - 状態: 先読み・窓・音量基準・ゲインの状態は持たず、入力されたサンプル数をその呼び出しで返す。
  - 保護: 各系統の非有限値を0としてから加算し、和を±1へ制限する。
  - 無音: システム側が0なら、有限で±1以内のマイク入力は同じ値で出る。
  - 末尾: 混合用の排出は不要。サンプルレート変換器の末尾は通常停止時に排出する。
- 録音中はバッファ形式、時刻の欠落、リング溢れ、2秒の入力停止、マイクの生存とaggregateのレート変更を監視する。
  - 開始待ち: 入力停止の監視はAudioDeviceStartが成功して戻った時刻と、実際の最終入力の時刻の遅い方から数える。許可待ちの長さは数えず、コールバックのlastHostを開始用の仮の時刻で上書きしない。
  - 理由: 開始前の時刻を使うと、開始APIが2秒以上待った回に、最初の入力が来る前の監視で誤縮退し得る。
  - 無応答: 成功した開始から2秒たっても入力が一度も来なければ、入力停止としてマイクへ切り替え、理由を出す。開始後に途切れた場合も最後の実入力から2秒で検出する。
  - 拒否: 開始APIがエラーを返した場合は既存の準備失敗として切り替える。初回許可待ちだけを理由に期限を延長し続ける処理は置かない。
  - 限界: コールバックが正常に続きながらタップ側だけが無音になる場合は、許可拒否と実際の無音を見分けない。
  - 許可: 明示的な `kAudioDevicePermissionsError` は許可の失敗として案内する。他のOSStatusだけから許可状態を推定しない。
  - 根拠: [AppleのCore Audioタップの説明](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps) は用途説明キーと初回許可を示す。[タップ作成API](https://developer.apple.com/documentation/coreaudio/audiohardwarecreateprocesstap(_:_:)) はOSStatusを返すが、拒否時の無音を区別する契約を示していない。
