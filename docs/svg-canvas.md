# SVGの図

議事録タブでは、本文に書いたSVGの図を、切り離したiframeの中で描く。外部の画像・色の指定・文の折り返し・リンクが出て、拡大縮小と移動ができる。

設計時の決定と検証は [SVGキャンバスの要件と全体設計](records/svg-canvas-design.md)。まだ実装していない「指す」もそちらにある。

## 対象

- 拾う書き方
    - 情報文字列が `svg` だけのコードフェンス。大文字小文字は問わない
    - 閉じたSVGブロック: 行頭の `<svg` から最初の `</svg>` までで、閉じタグの後ろが行末のもの
        - 前後の空行は要らない。中の空行、箇条書き・calloutの中、3空白までの字下げも拾う
- 拾わない書き方: 直さずに受け入れた範囲
    - 見え方「図が無い」: 段落の途中の `<svg>`、`<div>` などで囲んだ `<svg>`、`</svg>` の後ろの同じ行に文字があるもの
        - 生HTMLのsanitizeは `svg` を許可しない。図の中の文字だけが本文に残ることがある
    - 見え方「コードのまま」: 4空白以上の字下げ、`xml` ・ `html` のフェンス、`svg title="…"` のように情報文字列が `svg` だけでないフェンス
- iframeで描かないもの
    - ボードタブで描く文書の図。従来どおり、無害化して画像にする。色の指定・外部の画像・リンクは出ない
    - `![](図.svg)` ・ `![[図.svg]]` で参照したSVGファイル。画像として読み、クリックで拡大モーダルを開く
        - `xmlns` の無いSVGファイルは「画像を表示できません」になる。ファイルは書き直さずそのまま読む

## 描き方

親ページが原文を無害化し、表示する大きさ・リンク・画像を原文から読んでから、iframeへ渡す。

- iframeは `sandbox="allow-scripts"` で、`srcdoc` に子のCSP・無害化したSVG・同梱の `canvas.js` の読み込みだけを入れる
- iframeはポインタのイベントを受けない。クリックもピンチも親の要素が受ける
    - 理由: Mermaidの図と同じ操作の実装をそのまま使える
    - 限界: マウスを重ねたときのCSSの反応は出ない。アニメーションは動く
- `xmlns` の無い図も、`&nbsp;` のようなHTMLだけの実体参照を含む図も描ける
    - 理由: iframeの中ではHTMLとして読む
- 書体: 指定の無い文字は本文と同じゴシックになる

### 表示する大きさ

表示する大きさと、SVGの中の座標は別に扱う。上から順に採る。

1. `width` と `height` の両方が、単位なしかpxの正の数
2. 片方だけが有効で、`viewBox` がある。もう片方を `viewBox` の比で補う
3. `viewBox` の幅と高さ
4. 300×150

- 割合・0以下・数でない値は、無いものとして扱う
- 表示する幅がペイン幅を超える図は幅へ収め、小さい図は引き伸ばさない
- 大きさは親が原文から決める。iframeの読み込みを待たずに置き場の大きさが決まり、読み込みで本文がずれない

### 図に残すものと外すもの

- 残すもの: `style` 要素と属性、`foreignObject` とその中の文書要素、`image`、`use`、`a`、アニメーションの要素、`id` と `data-*`
- 外すもの: script、イベント属性、埋め込みとフォームの要素、`meta` ・ `link` ・ `base`
- 外のファイルを指せる場所は `image` ・ `img` ・ `a` だけ
    - ほかの要素の `href` は、`#` で始まる同じ図の中の参照だけを残す。`use` ・フィルタの画像・`textPath` が当たる
    - CSSと表示の属性の `url()` も、`#` で始まるものだけを残す。`<style>` ・ `style` 属性・`fill` や `filter` の属性が当たる
        - グラデーション・模様・影・矢印の先は、同じ図の中の参照なので残る
        - CSSの `url()` で貼る画像は出ない。画像は `image` か `img` で貼る
    - CSSはCSSOMで読んでから確かめる。エスケープした書き方で抜けられない
    - `@import` と `@font-face` は外す。変数の宣言・`var()` ・ `image-set()` を使う宣言も外す
        - 理由: 変数に文字列でURLを入れて `image-set()` へ渡すと、`url()` を書かずに画像を読める
    - 参照やCSSを後から書き換えるアニメーションは外す
    - 限界: CSSの検査は、分かっている書き方を外す形。漏れたときに読めるのはHTTPとHTTPSの画像で、`image` で許している通信と同じ種類。ローカルのファイルは、アプリのhostの照合が止める

### 画像

- 出るもの: 図の中の `image` と、`foreignObject` の中の `img`
- HTTP・HTTPS・data URIは、書かれたとおりに読む
- ローカルのパスは、本文の画像と同じ `minutes-image:` のURLへ親が書き換える
    - 書ける形: 議事録からの相対パス、絶対パス、`~/` 始まり、`file:///`
    - 上限も本文の画像と同じ仕組みを通る。1枚24MiBまで、1回の描画の合計96MiBまで
- 書き換える属性は、`image` の `href` と `img` の `src`
    - `image` に `href` と `xlink:href` の両方があれば `href` を採り、`href` 1つへ揃える
    - `img` の `srcset` は外す
- 読めなかった画像があると、図の下に「図の中の画像を表示できません: N件」と出す。図の中は変えない
    - 成否は `canvas.js` が、読み込みのイベントと画像のデコードの完了の両方で拾う
        - 理由: iframeの中のSVGの `image` で、読み込みのイベントが届かないことがあった
    - 8秒待っても成否が出ない画像は、読めなかったものに数える
    - 次の描き直しで読み直す

### リンク

- 図の中の `<a>` のリンク先は親が持つ。iframeへは番号だけを渡し、iframeの中にリンク先を残さない
- 選んだ図の中のクリックで、親が場所をiframeへ尋ね、返ってきた番号からリンク先を引く
    - `#見出し` は本文の中の移動。広げた図は、たたんでから移動する
    - ほかはアプリへ渡し、HTTP・HTTPS・mailtoだけを開く
- 最初のクリックは図を選ぶだけで、リンクは開かない

## 操作

Mermaidの図と同じ作法。詳細は [議事録の描画と検索](minutes-rendering.md) の「Mermaid図の選択と拡大縮小」。違うところだけを書く。

- 最初の大きさ: 選ぶ前も選んだあとも、操作するまではペイン幅へ収める。ペイン幅が変わると収め直す
    - 「全体」を押すと、またペイン幅へ追従する
    - 収めるときは、倍率の下限25%を掛けない。幅の広い図は25%より小さくなる
        - 理由: 下限を掛けると、収まっていた図が「全体」ではみ出す
        - 下限より小さい倍率からピンチしても、下限へ跳ばない。25%を超えたあとは、Mermaidの図と同じ下限が効く
- 操作列: 「− 倍率 + 全体 戻す」に「広げる」を足す
- 「広げる」: ペイン全体をその図にする。広げた瞬間に全体を収める
    - 戻り方: 「たたむ」かEsc。広げる前の倍率と位置へ戻る
    - 名前: 既存の「戻す」は等倍・初期位置へ戻す操作なので、別の名前にしている
- Esc: 1回につき1つ戻る。広げた図はまずたたみ、次に図の選択を外す
- 図をクリックしたときの拡大モーダルは出ない。「広げる」が置き換える
- AIの描き直し: 倍率・位置・広げた状態を引き継ぐ
    - 対応付け: 見出しのIDと、その節の中のSVGの図の順番。Mermaidの図とは別に数える
- 文字の倍率は図にも掛かる

## 描き直し

本文は描き直すたびに全部のDOMを差し替え、図のiframeも毎回読み込み直す。

- 理由: iframeは別の親要素へ移すと読み込み直す。読み込み直さずに移す方法は、このWebKitに無い
- 実測: 900×850pt、24枚の付箋を持つ図が2枚の議事録で、描き直しを始めた次のフレームまでに、2枚とも準備が終わった。ローカル画像を含む図でも同じ。5回ずつ
    - 判断: 図が無いフレームが出ないので、図を本文のDOMの外に置いて使い回す形は採らなかった
- 置き場の大きさは親が先に決めるので、読み込みの前後で本文の位置は変わらない
- ローカル画像は描き直しのたびに読み直す。同じパスのファイルを上書きすると、本文の画像と同じく新しい画像になる

## 更新の強調

付箋のある図は、変わった付箋だけを光らせる。基準と寿命は本文と同じ。詳細は [議事録の描画と検索](minutes-rendering.md)。

- 付箋: `id` と `data-kind` の両方を持つSVGの要素
    - `id` はUTF-8で1〜64バイト、`data-kind` は1〜32バイト。空白と制御文字を含まない
    - `id` が図の中で重なる要素は付箋にしない。ルートの `<svg>` の `id` とも比べる
    - 入れ子なら内側を採る
    - 無害化した後のDOMから読む
- 光らせるもの: 新しく現れた付箋と、文が変わった付箋
    - 文: 付箋の中の、画面に出る文字。空白を1つに畳んで比べる
        - 外すもの: `style` ・ `script` ・ `title` ・ `desc` ・ `metadata` の中の文字。付箋の中のCSSや題だけを変えても光らない
- 光らせないもの: 位置・色・大きさだけが変わった付箋、消えた付箋
    - 理由: AIは付箋を並べ直してよい。位置で光らせると、更新のたびに全部が光る
- 図の突き合わせ: ルートの `<svg>` の `id` 。議事録の中で重なる名前の図と名前の無い図は、見出しのIDと節の中の順番に名前を添えて引く
    - 図の名前が変わると、付箋は全部新しいものとして光る。重なったままの名前を別の名前へ変えたときも同じ
- 図の枠を光らせるのは、比べる基準の側にも今の側にも付箋の無い図だけ。原文が変わったら、画像と同じ淡い紫の枠で示す
    - 例: 最後の1枚の付箋を消した図は光らせない
- 描き方: 親が光らせる付箋の `id` をiframeへ渡し、`canvas.js` が付箋の外形の上に、本文と同じ淡い紫の四角を重ねる
    - 四角は付箋の座標系へ合わせるので、回転した付箋にも沿う。形は付箋の外接の四角
    - 四角の層はshadow DOMの中に描く
        - 理由: 図の `<style>` はiframeの文書の全体に効く。図の中に置くと、`rect` の塗りのような規則で強調が塗り替わる
        - 層の置き場の要素だけは図の規則に当たりうるので、直に `all:initial` を `!important` で掛けてから、置き方の値を固める
            - 理由: `transform` とは別に効く `scale` ・ `translate` ・ `rotate` もまとめて戻す
    - iframeの準備ができる前に決まった強調は、親が覚えておき、準備の知らせで渡す
    - 強調を消すときは、親からiframeへも伝える
    - 限界: アニメーションで動く付箋には、四角が付いていかない
- 目次の印: 付箋が光った図の節にも、本文と同じ規則で付ける

## 実行境界

SVGを画像ではなく文書として描く。プレビューが議事録を書き換えないことは変わらない。

止めるものごとに、受け持つ守りを分ける。

| 止めるもの | 受け持つ守り |
| --- | --- |
| inlineの `<script>` とイベント属性 | 無害化。継いだCSP |
| SVGが書いた、同梱の資産を指す `<script src>` | 無害化。子のCSP |
| 外への通信 | 継いだCSPの `connect-src` |
| 親のDOMと保存領域 | sandbox |
| 親の遷移、ポップアップ、フォーム送信 | sandbox。アプリの遷移の判定 |
| iframe自身の遷移 | 無害化。継いだCSPの `frame-src` 。アプリの遷移の判定 |
| 入れ子のiframe | 無害化 |

- `srcdoc` のiframeは本体のCSPを継ぐ。子の側で緩めることはできない
- 子のCSP: 動かせるスクリプトを、親が付けたnonceを持つ要素だけに狭める。nonceは図を描くたびに作る
    - 理由: 継いだCSPの `script-src minutes-app:` は、SVGが書いたscriptと同梱のコードを区別しない
- sandboxは `allow-scripts` だけ。付けるのは同梱の `canvas.js` を動かすため
    - sandboxはiframe自身の遷移を止めない。遷移は表の3つが受け持つ
- アプリの遷移の判定: サブフレームは `about:srcdoc` だけを通す。本体の `index.html` もサブフレームへは通さない
- 親が受けるメッセージは、受け取る1か所で確かめる
    - 送り主が、親が作った図のウィンドウであること。描き直す前の図からの知らせは、ここで引けずに捨てられる
    - 種類と形が決めたとおりであること
    - リンクの番号は、親が出したクリックへの返答だけを受ける。リンク先は親の一覧から引く
    - 描画の取消と読み込み失敗で本文を隠すときは、図への対応を捨てる。遅れて届いた返答でリンクを開かない
- ローカルのファイル: 図の中から読めるのは、本文の画像と同じ仕組みを通る画像だけ
    - 議事録の外にあるローカル画像も、絶対パスで指せば表示する。本文の画像と同じ、受け入れたリスク
    - 図が自分で書いた `minutes-image:` のURLは通らない。無害化が属性から外し、アプリは描画ごとに変わるhostの合わない要求を拒む
    - スクリプトが動かないので、読んだ画像の中身を取り出す手段が無い
- 外への通信: 図の中の `image` と `img` の画像。HTTPとHTTPSへ出る。iframeの文書には、リファラを送らない指定を付けている
    - 議事録に書かれた外部画像と同じ、受け入れたリスク
- DOMPurifyは既定で `foreignObject` の中のHTMLを外す。文の折り返しに要るので通している
    - 出力はsandboxとCSPの中でだけ描く

## 実装

- `web/minutes/figures.js`: 無害化、リンクの番号、画像の書き換え、iframeへ入れる文書
- `web/minutes/figure-rules.js`: 表示する大きさと、CSSの値の検査。DOMに触れない
- `web/minutes/canvas.js`: iframeの中で動く。画像の成否を知らせ、親が渡した場所のリンクの番号を返し、親が渡した付箋を光らせる。本体とは別のファイルに組む
- `web/minutes/updates.js`: 図の比べる項目を `figureEntries` で作り、本文と同じ `UpdateHighlighter` に乗せる
- `web/minutes/diagrams.js`: 図の中身がSVG要素でもiframeでも、同じ操作を掛ける
- テスト
    - `SVGCanvasTests`: 実WebKitで、描画と参照の絞り込み、無害化を通さない原文での守り、操作とリンク、更新の強調。文字100%と200%
        - 更新の強調は、iframeの中を親から読めないので、画面の画素で確かめる
        - 守りの確認は、子のCSPだけを外した対照と比べる。対照では、SVGが書いた同梱のスクリプトへの参照が読まれる
    - `web/minutes` の `npm test`: 表示する大きさ、CSSの値の検査、付箋の名前の長さ、更新の強調の比べ方
