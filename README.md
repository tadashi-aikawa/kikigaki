# KIKIGAKI

会議の発話を聴いて、話者付きでリアルタイムに文字起こしし、Markdownで残すmacOSアプリです。

フクロウの顔を2つの吹き出しで表したロゴが目印。朱色と生成りに、金のくちばしを添えています。

## できること

- マイクの音声を端末内で文字起こし。速報を先に出し、高精度の結果で静かに差し替え
- イヤホン利用時はMacのシステム音声も取り込み、相手の声とマイクの声を合わせて文字起こし
- 最大8話者の判別と、話者名の編集・手動統合
- 会議ごとの話者判別切替。無効時は文字起こしの確定後すぐに発言として表示
- 発話の確定前後を、半透明と通常の濃さで表示
- 別会議の声など小音量の発話を、しきい値で薄く除外
- 録音の一時停止・再開
- URLや補足を固定名「手入力」で会話へ投稿
- 会議ごとのMarkdown保存と、任意のWAV保存
- 「会話をコピー」から、会話全体と議事録の参照を任意のAIへ受け渡し
- herdr上のCodex・Claude Codeを会議へ参加させ、依頼・返事・定期の自動送信を同じ画面で扱う
- AIが書いた議事録を右ペインでプレビュー。目次・検索・変更箇所の強調・Mermaid・数式・Wikiリンクに対応。議論のボードは「議事録」「ボード」の別タブで表示
- 書き起こしウィンドウの最前面への固定

話者判別は推定です。必要に応じて書き起こしと話者を確認してください。

## 動作環境

- macOS 26以降
- マイクへのアクセス許可
- 初回セットアップ時のネットワーク接続

文字起こしにはApple Speech、話者判別にはFluidAudioのNemotron 3 Diarizationを使います。必要なモデル・言語アセットは自動でダウンロードします。

- 話者判別モデル: 有効な設定での起動時か有効へ切り替えたときに、Hugging Faceから約193 MBを取得します。以後は保存済みモデルを再利用し、無効設定での起動時は取得・読み込みを行いません。
    - 旧版が使っていたSortformerのモデルは不要になりました。アプリからは消さないため、容量を空けたいときは `~/Library/Application Support/FluidAudio/Models/sortformer` を削除してください。
- Apple Speechの日本語アセット: 未導入の場合、初めて録音を開始するときに別途取得します。容量は上記に含みません。

取得が完了するまで、録音開始は準備待ちになります。

## インストール

Homebrewで導入します。

```bash
brew install --cask tadashi-aikawa/tap/kikigaki
```

更新は次のコマンドです。

```bash
brew upgrade --cask kikigaki
```

自己署名(未公証)のアプリです。初回起動がブロックされた場合は、システム設定 → プライバシーとセキュリティ → 「このまま開く」で許可してください。

配布物は [Releases](https://github.com/tadashi-aikawa/kikigaki/releases) の `KIKIGAKI-<バージョン>.zip` からも取得できます。

### ソースからビルドする場合

macOS 26のSDKとSwift 6.2以上に対応するXcodeまたはCommand Line Toolsを用意し、以下を実行します。

```bash
git clone https://github.com/tadashi-aikawa/kikigaki.git
cd kikigaki
./scripts/make-app.sh
open .build/KIKIGAKI.app
```

作成された `.build/KIKIGAKI.app` をFinderで「アプリケーション」へコピーすれば、以後は通常のアプリとして起動できます。

この方法ではSkillのリンクを張らないので、会議へAIを参加させる場合は同梱CLIで導入してください。

```bash
.build/KIKIGAKI.app/Contents/Helpers/kikigaki-cli skill install
```

「アプリケーション」へコピーして使う場合は、コピー先の `/Applications/KIKIGAKI.app/Contents/Helpers/kikigaki-cli` で実行します。仕組みは後述の「会議へAIを参加させる」を参照してください。

## 起動と基本操作

メニューバーのフクロウから「開く」で書き起こしウィンドウを出し、録音を開始すると発話が順に表示されます。停止すると、既定では `~/Documents/KIKIGAKI` にMarkdownを保存します。

### 発話の確定表示

録音中の発話は、アバター・名前・時刻・本文の濃さで確定前後を示します。

| 見た目 | 意味 |
|---|---|
| 行全体が半透明 | 文字や話者が後から変わる可能性があります |
| 通常の濃さ | 行全体の文字と話者が固定済みです |

話者判別が無効な会議は、高精度の文字が確定した時点で通常表示になります。停止後の最終結果も通常表示です。

半透明の発話もコピー・AI送信に含まれます。小音量による除外には「小音量のため除外」の注記が付きます。

確定は認識の正しさを保証しません。最後の発言は後続発言や録音停止まで半透明のままになる場合があります。詳しくは [発話の確定表示](docs/utterance-progress.md) を参照してください。

### システム音声

録音開始シートの「システム音声」は「自動」「取り込む」「取り込まない」から選びます。初回は「自動」で、前回の選択を記憶します。

- 自動: イヤホン・ヘッドホンと判定できたときだけ取り込みます。
- 操作: 判定できない機器で取り込みたいときは「取り込む」を選びます。
- 許可: 初回はmacOSの「システムオーディオ録音」を許可してください。画面収録の許可は不要です。
- 対象: Macで鳴る通知音や会議以外の音も入ります。声が重なる部分は聞き取りにくくなります。
- 切替: 開始後の出力変更には追従しません。スピーカーで「取り込む」を選ぶと、マイクが拾う声と二重に入ります。

詳しくは [システム音声の取り込み](docs/system-audio.md) を参照してください。

### 話者判別と小音量の除外

「録音を開始」を押すと、その会議だけの指定を決めるシートが出ます。システム音声・話者判別・小音量の除外・議事録・AIへの自動送信を決めてから始められます。話者判別と小音量の除外は前回の値、議事録は空欄、自動送信は設定の `autoStart` の宛先が初期値なので、何も触らずReturnでも始められます。取消を押すと何も始まりません。詳しくは [録音開始シート](docs/start-sheet.md) を参照してください。

話者判別はこのシートで切り替えます。初期値は有効で、選択はアプリ再起動後も記憶します。録音を始めると変更できません。無効時は全員を「発言」として扱い、文字起こしの確定後に話者の判定を待たず表示します。聞き取り中の文字は引き続き暫定表示し、文末や無音でフキダシを分けます。詳しくは [話者判別の切替](docs/diarization-toggle.md) を参照してください。

話者名かアバターをクリックすると、その枡の名前を台帳の候補や自由入力で変えられます。同じ人が2つの枡に割れたときは、上部の人型ボタンから開く「話者」ポップアップで統合先を選べます。詳しくは [話者の手動統合](docs/speaker-mapping.md) を参照してください。

隣の会議の声など小さな声が混ざるときは、同じ「話者」ポップアップのスイッチとスライダーで小音量の発話を除外できます。録音開始シートでもON/OFFを切り替えられます。除外した行は薄く残り、コピーとAI送信から外れます。初回はOFFで、しきい値は−45 dBFSです。詳しくは [小音量発話の除外](docs/audio-exclusion.md) を参照してください。

録音中・一時停止中は、本文下の「会話に書き込む… · ⌘Enterで投稿」から⌘Enterで手入力を投稿できます。Enter・Shift+Enterで改行し、複数行の貼り付けにも対応します。長文は折り返して欄内で縦にスクロールできます。IME変換中のEnterは確定だけを行い、Escは下書きを残してフォーカスを外します。手入力のURLはクリックで開けます。投稿は声の行の間に入り、画面とMarkdownには改行を保持します。コピー・AI送信では1発話1行にまとめます。一時停止中の投稿時刻も再開後に変わりません。

録音の開始・停止・一時停止はウィンドウのボタンかメニューバーから操作します。AIへの手動実行はフッター左端のロボットのメニューの「手動実行…」からです。グローバルショートカットはありません。

フッターのピンボタンで、書き起こしウィンドウを最前面に固定できます。詳しくは [書き起こしウィンドウ](docs/transcript-window.md) を参照してください。

手入力欄では⌘Vで画像も添付できます。スクリーンショットやコピーした画像ファイルを貼り付けると、番号付きサムネイルが並び、×で取り外せます。画像だけでも⌘Enterで投稿できます。1枚10MiB・4,000万画素までで、PNG・JPEG以外は先頭フレームをPNGへ変換します。投稿時に会議Markdownの隣の `<会議名>.attachments/` へコピーするため、元画像を移動しても残ります。投稿したサムネイルはクリックで開け、Markdownには画像、コピー・AI送信には番号付きの画像パスを含めます。

## 設定

`~/.config/kikigaki/config.toml` で設定します。すべて省略可能です。

```toml
outputDir = "~/Documents/KIKIGAKI"
saveRecording = false
```

WAVも残す場合は `saveRecording = true` にします。

話者候補やAIなどを含む全キーは [設定リファレンス](docs/config.md)、AIへ会話を渡す手順は [AIへの受け渡し](docs/ai-handoff.md)、開発手順は [CLAUDE.md](CLAUDE.md) を参照してください。

### 会議へAIを参加させる

herdrとCodexまたはClaude Codeを導入します。AIが会話を受け取るための [kikigaki Skill](skills/kikigaki/SKILL.md) はアプリに同梱してあります。次のコマンドで `~/.claude/skills/kikigaki` と `~/.codex/skills/kikigaki` へリンクしてください。一度実行すれば、`brew upgrade` 後も新しいSkillが届きます。

```bash
/Applications/KIKIGAKI.app/Contents/Helpers/kikigaki-cli skill install
```

- 同名のファイルが既にある場合は上書きしません。自分で置いたSkillをそのまま使い続けられます
- 同梱版へ切り替えるときは、そのファイルを消してから再実行してください
- 外すときは `skill uninstall` を実行します。KIKIGAKI.appを指すリンクだけを外し、`brew uninstall --cask kikigaki` では外れません

設定へ次を追加すると、次の会議からロボットのメニューの「手動実行…」が使えます。`[[ai]]` を省略した場合は無効です。

```toml
[[ai]]
cli = "codex" # Claude Codeなら "claude"
address = "迅雷へ"
notifySound = false
# 手動・自動実行シートと録音開始シートのプロンプト初期値
autoPrompt = "会議の決定事項と担当・期限をMarkdown議事録へ更新してください" # 省略時は空欄
autoIntervalMinutes = 3 # 1〜60分、省略時は3分
# 録音開始シートの自動送信の宛先の既定にします。配列で1つまで
# autoStart = true
# CLIとherdrはPATHのほか ~/.local/bin・miseのshims・Homebrewを探します。見つからないときだけ絶対パスを指定します
# command = "/opt/homebrew/bin/codex"
# herdrCommand = "/opt/homebrew/bin/herdr"
```

初回の送信で専用herdrペインが作られます。固定の作業場所でも最初は利用者が一度ペインで信頼確認を承認してください。送信欄は空欄なら直近の声を送り、入力した場合は入力文を優先します。返事と確認は書き起こしの中のAIの行へ届き、会議Markdownにも残ります。確認質問の「返答する」から続けられます。

録音停止後も返事を回収します。次の会議への返事と混ぜず、旧会議の返事は元のMarkdownへ保存します。保存に失敗したときは「保存を再試行」を使えます。アプリ再起動後は未完了会議の返送を回収しますが、AIセッションの再接続や送信の再試行はしません。

録音を停止すると、返事待ちの依頼が片付いた時点で専用のherdrペインを閉じます。停止後は新しい依頼を送れません。

モデル・推論の強さ・作業場所・追加引数の設定は [設定リファレンス](docs/config.md) と [AI設定の複数プロファイル](docs/ai-profiles.md) を参照してください。声の作業依頼も扱う会議参加モードと、従来の手動コピーでは操作の許可範囲が異なります。

議事録の保存先は依頼文に従い、envelopeの `participant.minutes_path` に書き先があればそちらを使います。作成・更新後は同梱CLIの `minutes` でアプリへパスを通知します。ボードを使う会議では人の指定が無い場合に限り、通知したパスを以後の手動・自動送信へ渡します。ボードのない会議では伝播しません。ボードのプロファイルに `boardLocation` を設定すると、パス未指定でもAIがその指示文に従ってファイルを作成します。詳細は [議論のボード](docs/board.md) を参照してください。ヘッダーの「議事録」か「表示」メニューで右ペインを開けます。パス欄はReturnで確定し、Escapeで取り消します。パス欄にフォーカスすると最近表示したファイルの履歴が出ます。指定ファイルの更新は自動で表示し、AIの依頼中に変わった箇所は淡い紫で残します。右上の「目次」で見出しへ移動でき、⌘Fで本文を検索できます。ObsidianのVault内にある議事録では `[[ノート]]` がリンクになり、クリックでObsidianの該当ノートを開きます。×ボタンは表示中の議事録を閉じ、ペインは開いたままです。受け渡しの詳細は [議事録プレビューの設計](docs/minutes-preview.md)、描画できる記法は [議事録の描画と検索](docs/minutes-rendering.md) を参照してください。

ボードを設定した会議では、パス欄の下に「議事録」「ボード」のタブが並びます。議事録の本文と目次からボードの見出しは外れます。パス欄の右のボタンで、表示中の議事録をNeovim・Obsidianで開けます。詳しくは [議事録ペイン](docs/minutes-pane.md) を参照してください。

議事録を用意する側は、`kikigaki://start?minutes=<パーセントエンコードした絶対パス>` のリンクを出せます。クリックすると議事録を入れた録音開始シートが開きます。録音はシートで開始を押すまで始まりません。詳しくは [録音開始シート](docs/start-sheet.md) を参照してください。

`[[ai]]` を複数書くと、送信ごとに宛先のAIを選べます。詳しくは [AI設定の複数プロファイル](docs/ai-profiles.md) を参照してください。

Codexの起動では `outputDir` を書き込み許可へ追加します。任意のパス指定で無条件の許可は増えませんが、保存先外への書き込みはCLIの承認の仕組みに委ねられ、herdrのペインで承認すれば保存できます。拒否されたときだけ `work_failed` になります。追加許可によって保存先内の全会議の管理ファイルも書き換え可能になる点は、[議事録プレビューの設計](docs/minutes-preview.md) の「Skillの規則と書き込み許可」を参照してください。Claudeの承認待ちはherdrのペインで確認します。

### 会話を定期的にAIへ送る

録音開始シートで自動送信の宛先を選ぶと、録音の開始と同時に自動送信が始まります。設定で `autoStart = true` を書いた宛先が、シートの既定の宛先です。シートで「送らない」を選ぶと、その会議では始まりません。

録音中・一時停止中に始めるときは、フッター左端のロボットのメニューの「自動実行…」を開き、毎回送る依頼、間隔、作業許可を設定して「開始」を押します。既定は3分です。

開始の直後に、変更の有無を1回確かめます。前回の受領から変更があればすぐ送り、変更がなければ送らず、開始から指定間隔後の判定を待ちます。手動の「手動実行…」と同じAIセッションを使い、前回の受領から変更がない回や返事待ちの回はスキップします。

実行中はロボットの下に次の送信までの残り時間が出ます。メニューの「今すぐ送る」は同じ判定を直後に行い、「自動実行解除」は録音を続けたまま自動送信を止めます。

「録音停止時に最後の1回を送る」は既定ONで、録音の最終処理と保存が成功し、変更があれば最後に1回送ります。返事待ちなら到着後まで保留し、保留中も「自動実行解除」で取りやめられます。

自動の返事は「自動」の印付きで表示し、通知音は鳴りません。確認質問・失敗は通常どおり表示し、未回答の確認質問は「要返答」の赤バッジで強調します。自動送信の稼働状態は新しい会議やアプリ再起動では引き継がず、シートで変えた値も設定ファイルへは書き戻しません。詳しくは [定期自動送信](docs/ai-scheduled.md) を参照してください。

## ロゴ

共通の元画像は [Resources/kikigaki.png](Resources/kikigaki.png) です。READMEとアプリアイコンはこの画像を使います。

元画像を更新したら、次のコマンドで配布用アイコンを再生成します。

```bash
bash scripts/make-icon.sh
```

生成した `Resources/kikigaki.icns` はアプリの組み立て時に同梱されます。

owlery・parliamentへの反映手順と制作記録は [ロゴの管理](docs/logo.md) を参照してください。
